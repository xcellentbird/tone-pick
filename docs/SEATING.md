# 자리 배정

N명(남 M · 여 W)을 T개 테이블에 나눠 앉히고, 라운드마다 반복한다.
가중치 상수는 `src/shared/constants.ts` 의 `SEAT_W`.

---

## 무엇을 최대화하나

**사람마다 만족을 재고 그 합을 최대화한다** (ADR-57). 쌍마다 벌점을 더하면
어디에 앉혀도 남들의 값이 안 변하는 사람 — 콕도 표도 없는 사람 — 이 제일 먼저 희생된다.

```
u_i = (1/(k−1)) · Σ_j [ 끌림(i→j) − 1.0·(Δ나이/10)³ − 0.6·min(1, 만난 횟수/2) ]
    +             Σ_j  w_new · 1[처음 · 나이차≤6 · 이성] · (1 + 결핍_i)

끌림(i→j) = w_poke·pull(콕 i→j) + 0.4·pull(투표 i→j) + 2.5·1[상호 콕]
pull(보낸 수, 상한) = 보낸 수>0 ? min(1, (보낸 수 + 2·1[상대도 보냄]) / (상한+2)) : 0

목적 = Σ_i λ_i · u_i     λ_i = clamp((평균 채운 비율 + 0.3) / (내 비율 + 0.3), 0.5, 2)
```

| 항 | 값 | 성질 |
|---|---|---|
| 나이차 | `(Δ/10)³` × 1.0 | **문턱이 없다.** Δ=5 → 0.125 · Δ=10 → 1 · Δ=20 → 8 |
| 재회 | `min(1, 만난 횟수/2)` × 0.6 | |
| 매력 투표 | `pull` × 0.4 | 호기심이라 가볍다. 진행도와 무관 |
| 콕 | `pull` × (0.4 ~ 1.8) | **진행도에 따라 커진다** |
| 상호 콕 | +2.5 | **갚은 뒤에도 사라지지 않는다** |
| 처음 만나는 나이대 이성 | 0.4 ~ 1.0 | **인원으로 나누지 않는다** |

### 세 가지가 이 설계의 급소다

**① 끌림에 방향이 있다.** 내가 보낸 것만 나에게 만족을 준다 — 콕은 익명이라 받은 쪽은
누가 찔렀는지 모른다. 목적함수는 여전히 쌍으로 분해되므로(`Σ_{i<j} [λ_i·f(i→j) + λ_j·f(j→i)]`)
맞교환 증분 평가가 그대로 돈다.

**② 새 만남을 인원으로 나누지 않는다.** 나누면 이성이 3명인 테이블과 2명인 테이블이
같은 값이 되어 성비가 치우친 테이블에 계속 앉는 사람이 생긴다. 남28·여12 회차에서
이 한 줄이 나이대 이성 커버리지를 **88% → 99%** 로 올렸다.

**③ 진행도를 라운드가 아니라 쌓인 상호 콕으로 잰다.**
```
p = min(1, 상호 콕 쌍 수 / (인원/3))
w_new = 0.4 + 0.6·(1−p)      w_poke = 0.4 + 1.4·p
```
**운영자는 시계를 보고 끝낸다** — 몇 번째가 마지막인지 알 수 없어서 `r/R` 을 못 쓴다.
콕은 만나본 사람에게만 갈 수 있어 파티가 진행될수록 저절로 쌓인다.

> ⚠️ **`SEAT_W.MUTUAL` 을 8 이상으로 올리지 마라.** 마지막 라운드 동석은 조금 오르지만
> 나이대 이성 전원 만남이 무너진다 (실측 60/60 → 57/60, 20 에서는 46/60).

## 어느 라운드가 마지막이 되어도

상호 콕을 **갚은 뒤에도 계속 끌게** 두면 후반으로 갈수록 저절로 모인다 —
새로 만날 사람이 고갈되면서 다양성이 끌림을 밀어낼 힘을 잃기 때문이다.
40명(남28·여12) · 4테이블 · 5라운드 실측:

| | R2 | R3 | R4 | R5 |
|---|---|---|---|---|
| 갚으면 끌림 소멸 | 6% | 19% | 45% | 89% |
| **갚은 뒤에도 유지** | 6% | 21% | 51% | **97%** |

**마무리 버튼을 만들지 마라** — 시계를 보고 끝내는 사람은 *"이번이 마지막인가"* 에 답할 수 없다.

## 얼마나 만날 수 있나 — 테이블 수가 정한다

병목은 **이성이 적은 쪽**이다. 남28·여12 면 남자가 라운드마다 보는 여자 수가 전부다.

```
가용 = 라운드 수 × (그 사람 테이블의 이성 수)
필요 = 나이차 6살 안의 이성 수      ← 나이 분포 한가운데 사람이 최댓값이다
```

| 테이블 | 구성 | 남자가 라운드당 보는 여자 | R=5 | 28세 남자가 만날 여자 | 여유 |
|---|---|---|---|---|---|
| **4** | 10명 = 남7·여3 | **3명** | 15 | 12 | **3** |
| 5 | 8명 = (6,2)·(5,3) | 2~3명 | 12~18 | 12 | 0~6 |

**여유가 0 이면 어떤 알고리즘도 못 한다** — 같은 사람을 한 번이라도 두 번 만나면 실패다.
남28·여12 는 **4테이블**이어야 한다.

## 제약

**하드 (절대 안 깨짐)** — 각 테이블의 남/여 정원은 전체 성비를 따라 미리 정해지고 그대로 유지된다.
테이블별 인원 편차 ≤1, 미배정 0.

## 성비 불변식 — 구조로 지킨다

성비를 소프트 제약으로 두면 다른 벌점이 커질 때 밀린다. 그래서 깨질 수 없게 만든다.

1. `tableCaps()` 로 테이블별 남/여 정원을 **먼저 고정**한다
2. 초기 배치가 정원을 만족한다
3. 개선 단계는 **같은 성별 두 명만 맞바꾼다**

→ 성비는 "지키려고 노력"하는 게 아니라 **바뀔 방법이 없다.**

> ⚠️ **좌석 변경 API 는 `swap(a, b)` 하나뿐이다.** 한 명만 옮기는 API 를 만들면
> 운영자 조작 한 번에 이 불변식이 깨진다. 프로토타입이 그랬다.

**앉히기(`seatPlayer`)는 변경이 아니라 더하기다.** 자리 없는 사람을 넣는 것이라
아무도 자리를 잃지 않고, 붙어 앉은 쌍도 그대로다. 대신 **테이블을 받지 않는다** —
자기 성별이 가장 적은 테이블, 같으면 사람이 적은 쪽, 그것도 같으면 낮은 번호를
서버가 고른다. 난수를 쓰지 않아 같은 상태면 같은 자리가 나온다.

> ⚠️ **운영자가 테이블을 고르게 하는 순간 그게 곧 위의 금지된 API 다.**
> "3번에 앉혀" 를 받지 마라. 받는 건 "앉혀" 뿐이다.

## 라운드는 한 가지뿐이다

**한동안 `마지막 라운드`(`final = true`)가 따로 있었다.** 재회 벌점 해제 · 상호 쌍 끌림 ×2.5 ·
나이차 면제 · 붙은 쌍은 맞교환 제외 — 쌍을 **구조로** 붙이는 라운드였다.
**ADR-51 에서 걷어냈다.** 콕이 매 라운드 자리에 들어가므로(ADR-40) 그 일을 모든 라운드가
조금씩 하고 있고, 그것만 하는 라운드를 따로 두면 운영자가 매번 "이번이 그 라운드인가" 를
정해야 한다. 배정 버튼은 하나뿐이다.

**대신 못 붙인 쌍은 운영자가 붙인다.** 자리 검토 화면이 짚어준다 —
`💘` 는 짝과 같은 테이블, `💔` 은 다른 테이블(=옮길 수 있다), 표시 없음은 이 라운드에 짝이 없다.

### 그래서 못 붙는 쌍이 있다

상호 콕 끌림(2.5)은 나이차가 약 13.6살일 때의 벌점과 같다 (`(13.6/10)³ ≈ 2.5`).
**그보다 벌어진 상호 쌍은 이 식이 못 붙인다** (ADR-11 · ADR-57).
가중치를 올려 자동으로 붙이면 그 테이블의 나이 구성이 통째로 무너진다 —
`SEAT_W.MUTUAL` 을 8 로 올리면 나이대 이성 전원 만남이 60/60 → 57/60 이 되고, 20 이면 46/60 이다.

**무작위가 아니라 설명되는 실패다.** 나머지는 사람이 맞교환으로 붙인다.

## 테스트 기준

`buildSeating` 은 순수 함수다. 구현 전에 아래를 테스트로 박아두면 알고리즘을 어떻게 짜든 상관없다.

| 지표 | 기준 |
|---|---|
| 성비 편차 | **0** (하드 제약) |
| 미배정 인원 | **0** |
| 테이블별 인원 편차 | ≤ 1 |
| 나이차 10살+ 쌍 | 무작위 배치의 **절반 이하** + 표본별 상한 |
| **나이대 이성 전원 만남** | 남28·여12 · 4테이블 · 5라운드 → **못 만난 쌍 0** (씨앗 8개 전부) |
| **마지막 라운드 상호 콕 동석률** | **≥ 90%** (씨앗 8개 평균, 실측 0.97) |

> **확률적 규칙은 씨앗 하나로 재면 안 된다.** 실측이 흔들리는 폭이 판정보다 크다 —
> 뒤의 둘은 씨앗 8개를 돌려 평균과 최댓값으로 본다.

> 나이차만 절대값이 아니라 **무작위 대비**로 재는 이유: `test/05-seating.test.ts` 의 표본은
> 24~44세 균등 난수라 조합이 가혹하다. 같은 알고리즘도 표본에 따라 절대값이 달라진다.
> "무작위보다 훨씬 낫다 + 지난번보다 나빠지지 않았다"가 실제로 지키려는 것이다.
>
> ⚠️ **세제곱으로 바꾸면서 10살+ 기준선이 올라갔다** (ADR-57). 절벽은 10살을 절대 못 넘게 했는데
> 세제곱은 10살이 1.0 이라 12살짜리 하나가 6살짜리 넷보다 싸다. 그 대신 20살짜리를 훨씬 무겁게 벌한다.

### 잠기지 않는 것 — 알고 두는 것

**결핍 가중 · 공정성(`λ`) · 재시작 · 진행도 스케줄은 각각 테스트로 잠기지 않는다.**
넷을 **함께** 떼면 나이대 이성 전원 충족이 8/8 → **4/8** 로 무너지지만, 하나씩 떼면 여유에 묻힌다.

**규칙이 아니라 여유를 넓히는 값**이라 그렇다. 잠긴 것은 그 값들이 아니라 **결과**다 —
전원 충족과 마지막 라운드 동석률. 이 값들을 만질 때는 그 둘을 다시 재라.

## 조합의 한계

남12/여12 를 **3테이블(테이블당 8명)로 3라운드** 돌리면 새 이성 비율이 35%까지 떨어진다.
알고리즘 문제가 아니라 조합의 문제다 — 라운드가 늘수록 "안 만난 이성"이 고갈된다.

**테이블을 늘리거나 라운드를 줄여야 한다.** 인원을 넣으면 적정 조합을 제안하는 기능이 필요하다.

## 운영 흐름

```
테이블 수 선택 → 초안 생성 → 검토·수동 맞교환 → 📣 알림 발송
```

- **테이블 수는 배정할 때마다** 고른다. 결과에 그때 쓴 값을 함께 저장해 과거 라운드가 덮어써지지 않게 한다 (ADR-5)
- 테이블당 2명 미만 / 8명 초과면 경고
- **초안은 참가자에게 렌더링하지 않는다.** 발송해야 자리와 알림이 뜬다
- 라운드 횟수 제한 없음. **확정해도 배정은 닫히지 않는다** (ADR-28) — 지각자가 오면 필요하다
- 발표가 끝났으면 자리를 더 바꾸지 않는다

## 무료 플랜 CPU 10ms

로컬 서치가 요청당 10ms 를 넘으면 잘린다. 실측하며 얻은 것:

1. **안쪽 루프에서 문자열을 만들지 마라.** `\`${a}|${b}\`` 키로 Map 을 두드리던 판이
   100명에 23ms 였다. 사람을 번호로 바꾸고 관계를 n×n 바이트 판(100명이면 10KB)에 펼치니 3ms 가 됐다
2. 맞교환 비용은 전체를 다시 계산하지 않고 **두 사람 몫만** 계산한다 (O(테이블 인원))
3. 평가 횟수에 예산을 둔다. 다만 예산을 10배로 올려도 결과가 같았다 —
   품질을 막는 건 예산이 아니라 지역 최소값이다

측정: 100명 · 12테이블 기준 **3ms 안쪽** (`test/05-seating.test.ts` 가 상시 감시한다).
그래도 부족해지면 배정을 여러 요청으로 쪼개거나 Workers 유료 $5/월.

## 손으로 고치는 두 가지

배정은 계산이지만, 현장에서 운영자가 아는 사정은 계산에 없다.

| 손잡이 | 하는 일 | 지키는 것 |
|---|---|---|
| **맞교환** `swap(a, b)` | 두 사람의 자리를 바꾼다. 남녀도 된다 (ADR-16) | 테이블 인원 |
| **자리 섞기** `shuffle()` | 남녀 비율은 그대로 두고 **사람만** 다시 섞는다 | 테이블별 남 몇·여 몇 |

`shuffle()` 은 나이차·재회·콕 보너스를 **보지 않는다.** "그냥 다시 섞어줘" 라고 할 때 쓰는 손잡이다.
다만 **붙어 앉은 쌍은 움직이지 않는다** (ADR-23 → 모든 라운드로 넓혔다, ADR-51) —
운영자가 손으로 붙여둔 쌍을 섞기가 흩어놓으면 버튼 하나로 그 손이 헛일이 된다.
다시 계산하고 싶으면 `자리 재배정` 을 누른다 — 그쪽이 가중식을 처음부터 다시 돌린다.

**한 명만 옮기는 API 는 여전히 없다.** 그건 테이블 인원이 어긋나는 일이라 성격이 다르다.

## 한 사람이 여러 명과 이어질 때

A–B 와 A–C 가 동시에 성립한다 (ADR-24). `partners` 는 사람마다 **리스트**이고
`withPartner()` 는 "짝 중 아무나 이 테이블에 있는가" 를 본다.

**불가능한 상황이 아니다** — A 의 테이블에 B 와 C 가 함께 앉으면 두 쌍 다 성공한다.

정원이 모자라 하나만 붙일 수 있을 때는 **주고받은 표가 많은 쪽**이 자리를 가져간다 (ADR-25).
쌍 목록을 표 수 순으로 정렬해 강한 쌍부터 앉히고, 벌점 보너스도 표 수에 비례한다 (`pullScore`) —
다만 상한(24)을 넘지 않는다. 한 쌍이 나이차 벌점을 밀어내면 그 테이블만 이상해진다.
