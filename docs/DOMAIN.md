# 도메인 규칙 요약

## 단계

```
prep(준비 중) → reg(등록 중) → prevote(사전 투표) → party(파티 진행) → done(발표 완료)
```

예약 시각은 **한 번만 울리는 알람**이다. 실제 전환 시각을 `fired` 에 기록하고,
알람은 `fired` 가 비어 있을 때만 울린다. 그래서 되돌리기를 해도 즉시 다시 밀리지 않는다.
예약 값 자체는 지우지 않는다 — "예약은 21:00 이었는데 20:45 에 진행했다"를 보여줘야 하기 때문.

잠금은 **지나온 항목만**. 등록이 시작됐으면 등록 시각만 잠기고 발표 시각은 여전히 수정 가능하다.

## 콕

| 라운드 | 시점 | 기본 |
|---|---|---|
| `pre` 사전 투표 | 등록 후 ~ 마감 | 3회 (1~5) |
| `party` 파티 중 | 마감 후 ~ 발표 | 3회 (1~10) |

예산은 라운드별로 분리. **같은 사람에게 중복 가능**, **0회도 가능**.
`+` 는 확인 다이얼로그를 거치고, `−` 는 즉시(되돌릴 수 있으므로 확인은 마찰만 늘린다).

1인당 k회일 때 기대 상호 매칭 쌍 수는 파티 규모와 무관하게 **k²** 에 수렴한다.

## 공개 범위

| 정보 | 참가자(발표 전) | 참가자(발표 후) | 운영자 |
|---|---|---|---|
| 받은 콕 횟수 | O | O | O |
| 찌른 사람이 누구인지 | 비공개 | **상호 매칭만**(닉네임) | 전원 |
| 일방적으로 받은 콕 | 익명 | **끝까지 익명** | 발신자까지 |
| 실명·전화·인스타 | 비공개 | **매칭돼도 비공개** | 전체 |

이건 옵션이 아니라 고정 규칙이다. 이 앱이 없애려는 건 "거절당하는 경험"이다.

## 자리 배정

1. **남녀 비율** — 하드 제약. 테이블별 정원 고정 + 같은 성별끼리만 교환하므로 깨질 수 없다
2. **10살 이상 차이 회피** (벌점 30)
3. **이전 라운드 재회 회피** (라운드마다 증가, 22.5 상한 — 나이 제약을 못 넘는다)
4. I·E 혼합(4) · 콕 반영(상호 −12 / 단방향 −4). 상호 매칭 쌍은 재회 벌점 면제

테이블 수는 **배정할 때마다** 고르고, 각 라운드 결과에 함께 저장한다.
마지막 라운드는 재회 회피를 끄고 상호 매칭 보너스를 ×2.5 한다.
