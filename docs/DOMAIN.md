# 도메인 규칙 요약

## 단계

```
prep(준비 중) → reg(등록 중) → prevote(매력 투표) → party(파티 진행) → done(발표 완료)
```

예약 시각은 **한 번만 울리는 알람**이다. 실제 전환 시각을 `fired` 에 기록하고,
알람은 `fired` 가 비어 있을 때만 울린다. 그래서 되돌리기를 해도 즉시 다시 밀리지 않는다.
예약 값 자체는 지우지 않는다 — "예약은 21:00 이었는데 20:45 에 진행했다"를 보여줘야 하기 때문.

잠금은 `schedLocked` 한 곳이 판정한다. **지나온 항목이 잠기고, 파티가 시작되면 나머지도 함께 잠긴다** —
현장에서 일정을 흔들 자리가 아니다. **예외는 발표 시각 하나뿐이다** (ADR-43): 파티가 길어지면 미뤄야 하는데
파티 시작에 잠그면 손쓸 방법이 없다. 등록 시작은 회차를 만드는 순간 지나가므로 **늘 잠겨 있다** (ADR-38).

### 무엇이 예약되나

| 전환 | 무엇이 정하나 |
|---|---|
| 등록 시작 | **회차를 만드는 순간** (ADR-38) |
| 매력 투표 시작 | `prevoteAt` — 예약 |
| 매력 투표 마감 | **파티 시작** — 따로 시각이 없다 (ADR-100) |
| 파티 시작 | `partyAt` — 예약 (ADR-93). 매력 투표 중에만 울린다 |
| 커플 발표 | `revealAt` — 예약. **파티가 시작된 뒤에만 울린다** (ADR-43) |

발표 예약이 파티를 조건으로 다는 이유는 ADR-43 이다 — 아무도 안 온 자리에서 발표가 뜨면
콕이 열린 적도 없어 매칭 0으로 끝난 것이 된다. **그 조건은 파티가 예약이 된 뒤에도
그대로다** (ADR-93) — 두 예약이 이어질 뿐, 발표가 파티를 건너뛰는 길은 없다.

운영자는 언제든 먼저 누를 수 있다. 버튼은 **예약을 앞당기는 자리**로 남는다 —
미룰 일이면 시각을 고친다. 파티가 길어지면 **발표 시각만** 파티 시작 뒤에도 미룰 수 있다.

## 콕

| 라운드 | 시점 | 기본 |
|---|---|---|
| `pre` 매력 투표 | 매력 투표 시작 ~ **파티 시작** (ADR-100) | 1회 (1~5) |
| `party` 파티 중 | **파티 시작** ~ 발표 | 2회 (1~10). 매력 투표 1위는 +1 (회차 설정, ADR-100) |

예산은 라운드별로 분리. **같은 사람에게 중복 가능**, **0회도 가능**.
**알림(`preNotify`·`pokeNotify`)은 라운드마다 따로** 정한다 (ADR-43).
알림을 끄면 그 라운드의 수는 `received` 에서도 0으로 나간다 — **발표 뒤에도 그대로다** (ADR-85).
받은 수는 **라운드마다 따로** 내려간다 (ADR-46 후기) — 소식 줄이 표와 콕을 갈라 부르기 위해서다.
**되돌리기는 두 라운드 다 언제나 된다** (ADR-95). 회차 설정으로 막던 때가 있었는데 걷어냈다 —
막는 회차를 만들 이유가 없었고, 그 설정 하나 때문에 확인창 문구와 도움말이 둘로 갈렸다.

**되돌리기는 확인창 안에만 있다** — 목록에 `−` 버튼을 따로 두지 않는다. 찌른 적 있는 사람을
다시 누르면 같은 창이 열리고 거기서 되돌린다. **다 쓴 뒤에도 그 창은 열린다** (ADR-34 후기) —
막으면 마지막 한 번을 잘못 쓴 사람이 손쓸 데가 없다. 그때는 되돌리기 하나만 있고 화살표가 반대다.

1인당 k회일 때 기대 상호 매칭 쌍 수는 파티 규모와 무관하게 **k²** 에 수렴한다.

## 공개 범위

| 정보 | 참가자(발표 전) | 참가자(발표 후) | 운영자 |
|---|---|---|---|
| 받은 콕 횟수 | O (알림을 끈 라운드는 0 — ADR-43) | O (끈 라운드는 여전히 0 — ADR-85) | 라운드별 수. **현황 탭 순위에서만** (ADR-30·46) |
| 찌른 사람이 누구인지 | 비공개 | **상호 매칭만**(닉네임·실명) | **상호 매칭 쌍만** |
| 일방적으로 받은 콕 | 익명 | **끝까지 익명** | **앱에는 없다** — 발신자는 R2 콕 로그 파일에만 (ADR-84) |
| 실명 | 비공개 | **서로 콕 찌른 쌍에게만** (ADR-19) | 전체 |
| 전화번호·인스타 | 비공개 | **매칭돼도 비공개** (ADR-42) | 전체 |
| 나이·MBTI | 매력 투표 중에는 비공개 — **파티가 시작돼야** 열린다 (ADR-21) | O | 전체 |
| 매력 투표 1위 (보너스를 켠 회차) | **1위 본인만** — `매력 투표에서 가장 많은 표를 받았어요` 와 늘어난 콕 한도. **표 수는 본인에게도 없다** (ADR-100) | 같다 | 누가 받았는지(`meta.topVoters`) · 받은 표 수 |
| 익명 쪽지 | 본문은 **받은 사람과 보낸 사람만.** 보낸 사람은 **끝까지 익명** (ADR-98) | 같다 — 서로 찌른 쌍에게도 | **보낸 장 수뿐** — 본문·상대·받은 장 수 없음 (ADR-98 후기 2) |

운영자 응답(`hostState`)에는 한쪽만 찌른 콕(`oneWay`)이 **없다.** 화면에서 감춘 게 아니라 응답에 없다 —
누가 누구를 찔렀는지 전부는 운영자가 Cloudflare 에서 받는 로그 파일에만 있다 (ADR-84).

이건 옵션이 아니라 고정 규칙이다. 이 앱이 없애려는 건 "거절당하는 경험"이다.
**회차 설정으로 만들지 마라** — 회차마다 다르면 참가자가 이번 파티의 규칙을 매번 새로 배워야 한다.

### 실명이 열리는 세 조건 (ADR-19 · ADR-42)

참가자에게 실명이 나가는 통로는 `MatchInfo.realName` **하나뿐**이고, 셋이 다 맞아야 한다.

1. 발표 단계일 것
2. 서로 **콕** 찔렀을 것 — 매력 투표는 세지 않는다 (ADR-34)
3. 그 상대의 것일 것

**전화번호와 인스타에는 이런 조건이 없다 — 아예 안 나간다** (ADR-42).
`MatchInfo` 에 담을 자리가 없는 것이 곧 방어다. 인스타를 받는 이유는
**운영자가 참가자를 확인하기 위해서**이고, 등록 화면이 그렇게 말한다.

실명을 남긴 이유는 **연락 수단이 아니라 신원**이라서다 — 닉네임만으로는 파티장에서
서로를 못 찾고, 그러면 `💘 서로 찔렀어요` 가 아무 일도 안 한 것이 된다.

## 자리 배정

**가중식·불변식·테스트 기준은 `docs/SEATING.md` 에 있다.** 가중치 값은 `src/shared/constants.ts` 의
`SEAT_W` 하나가 쥔다 — 여기에 숫자를 옮겨 적지 마라. 옮겨 적은 표는 값이 바뀔 때 조용히 낡는다.

남녀 비율만 **하드 제약**이다 — 배정이 테이블별 정원을 먼저 정하고 구조로 지킨다
(운영자의 손은 깰 수 있다 — ADR-16·79). 나머지는 전부 가중치다.

테이블 수는 **배정할 때마다** 고르고, 각 라운드 결과에 함께 저장한다.
**라운드마다 규칙이 다르지 않다** (ADR-51) — 마지막 라운드에만 걸던 면제와 보너스를 걷어냈다.
못 붙은 쌍은 운영자가 초안의 `💔` 를 보고 맞교환으로 옮긴다.
