# 화면 요구사항

화면을 만들 때 지켜야 할 것. 문구는 전부 `src/shared/copy.ts` 에서 가져온다.
URL·히스토리 규칙은 `ROUTES.md`, 도메인 규칙은 `DOMAIN.md`.

---

## 전역 원칙

| 원칙 | 내용 |
|---|---|
| **되돌릴 수 없는 것만 확인을 받는다** | 콕 `+` · 단계 전환 · 참가자 삭제 · 자리 발송은 확인. 콕 `−`(되돌리기)와 자리 초안 생성은 즉시 |
| **확인창은 무엇이 어떻게 바뀌는지 숫자로** | "정말 하시겠습니까?"만 있는 다이얼로그는 만들지 않는다 |
| **문구가 버튼 이름과 겹치지 않게** | 본문에 "취소"를 쓰면 옆의 취소 버튼과 헷갈린다 → "되돌리기" |
| **에러는 그 값을 입력한 자리에** | 닉네임 중복이면 3스텝이 아니라 1스텝으로 되돌려 표시. 입력값은 보존 |
| **참가자에게 "0"을 들이대지 않는다** | 받은 콕 0회는 숫자 대신 별도 문구 (`REVEAL.noMutual`) |
| **일정은 30분 단위** | 파티 일정은 21:00 / 21:30 으로 잡힌다. 21:07 을 고를 수 있게 두면 고를 것만 많아지고 안내 문구에도 어중간한 시각이 나간다. `step` 은 피커만 붙잡으므로 **받은 값을 코드에서 맞춘다** (`snapSchedule`) |
| **하나만 켜지는 선택은 세그먼트 토글** | 한 컨테이너 안에서 채워진 칸이 움직여야 "여러 개 중 하나"가 형태로 보인다. 켜진 칸은 색이 아니라 채움과 굵기로 말한다 |

## 화면별 요구사항

### 뿌리 `/`

**여기서 할 수 있는 일이 없다.** 문은 참가 링크 하나뿐이다 (ADR-13·15 후기).

- 이미 어느 회차에 들어가 있으면 **그리로 보낸다.** 들어와 있는 사람에게 "링크로 오세요" 는 거짓말이다
- 아니면 링크로 들어오라고 말하고 끝. **입력 칸도 버튼도 두지 마라**
- **`운영자로 들어가기` 를 되살리지 마라.** 참가자에게 관리 경로를 광고할 이유가 없다 —
  운영자는 `/host` 를 직접 연다
- 예전엔 여기서 입장 코드 6자리를 물었다. 운영자는 보통 **링크만** 주므로,
  링크를 열었다 뒤로 간 참가자가 알지도 못하는 코드를 요구받는 **막다른 길**이었다

### 회차 확인 `/j/:id` — 참가 링크가 여는 곳

- 보이는 것: 단계 · 회차 이름 · 파티 일시. **입장 코드는 응답에도 화면에도 없다**
- **전화번호**를 넣어야 등록으로 넘어간다 (ADR-15). 명단에 있는 번호만 통과한다
- 칸은 **`010` 이 채워진 채로** 시작하고, 치는 대로 `010-1234-5678` 로 끊어 보여준다.
  **고정 접두사(칸 밖 라벨)로 두지 마라** — 칸이 여덟 자리가 되면 자동완성이 채운 열한 자리가
  안 들어가고(세 번 아끼려다 열한 번을 잃는다), 011 같은 옛 번호를 지우고 칠 수도 없어진다.
  그 사람은 문 앞에서 막히는데 **실패 문구는 하나뿐이라 이유를 알 길이 없다**
- 끊는 자리는 **언제나 3-4-4**. 자리 수를 세어 바꾸면 마지막 글자에서 하이픈이 밀려 칸이 흔들린다
- 상태와 전송은 **숫자 그대로**, 하이픈은 그릴 때만 (생년월일 칸과 같은 방식)
- 실패 문구는 하나뿐이다 (`ENTRY.notInvited`) — 왜 안 되는지 말하지 않는다
- 번호가 틀려도 **입력값을 지우지 않는다**
- 이미 등록한 사람은 번호만 넣으면 곧바로 자기 화면으로 간다 — 링크를 다시 여는 게 기본 동작이다
- 준비 중 회차면 언제 열리는지 알린다 (`ENTRY.notOpenYet`)

### 참가자 등록 `/j/:id/register/1..3`

| 스텝 | 항목 |
|---|---|
| 1 기본 정보 | 닉네임 · 실명 · 나이 · 성별(토글 2개) |
| 2 연락처 | 인스타(**필수** — **운영자 확인용**, ADR-42) · **전화번호는 묻지 않는다.** 입장할 때 확인했다 |
| 3 나를 소개 | MBTI 4문항 토글 · 매력 3가지 |

- **MBTI 는 16지선다 드롭다운이 아니라 4문항 토글** (`MBTI_AXES`). 모르는 사람도 답할 수 있어야 한다
- 선택 토글은 **입력값을 날리지 않는다.** 폼 전체를 다시 그리면 아직 저장 안 된 입력이 사라진다
- 닉네임 중복은 `REGISTER.err.nickTaken` + 1스텝으로 되돌림
- 이탈 시 `useDraftGuard` (`REGISTER.draftGuard`)
- **인스타를 왜 받는지 그 칸 아래에서 말한다** (ADR-42, `REGISTER.instaWhy`).
  이 줄이 없으면 참가자가 `연락 수단으로 쓰이겠구나` 로 읽는데 그건 사실이 아니다 —
  매칭 상대에게는 전화번호도 인스타도 나가지 않는다. **등록 폼과 수정 폼이 같은 말을 쓴다.**
  ⚠️ 연락처 공개 범위를 **고르는 자리를 다시 만들지 마라** (ADR-42 가 ADR-37 을 걷었다).
  고를 것이 없다 — 애초에 안 나간다
- **마치면 도움말이 한 번 저절로 열린다** (슬라이스 21). 물음표는 *이미 질문이 생긴 사람*의 장치라
  늦다 — 질문이 생기기 전에 한 번 읽혀야 하고, 그 순간은 주의가 가장 높고 화면이 가장 비어 있는 등록 직후다.
  본 적 있다는 기록은 남기지 않는다 (ADR-4) — **`등록 완료` 라는 사건에 붙는다.**
  다시 등록한 게 아니라 돌아온 것(`resumed`)이면 밀지 않는다

### 참가자 메인 `/e/:code`

3탭: **🏠 홈 / 👥 참가자 / 🙋 내 정보** (`TABS_PARTICIPANT`)

**탭마다 답하는 질문이 하나씩이고, 겹치지 않는다.** 같은 정보가 두 탭에 있으면
어느 쪽이 맞는지 눈이 한 번 더 확인하게 된다.

| 탭 | 질문 | 여기에만 있는 것 |
|---|---|---|
| 홈 | 지금 무슨 일이고 내가 뭘 하면 되나 | 단계별 **할 일 문장**, **남은 시간**, **내 자리**, 결과 요약(몇 명인지), **지금까지의 소식** |
| 참가자 | 누가 왔나 · 누굴 찌를까 | 목록·필터·프로필 시트·콕, 남은 콕 |
| 내 정보 | **내가 낸 것** | 내 프로필과 그걸 고치는 길 (ADR-31). 회차 이름은 상단 바로 옮겼다 |

**알림을 탭으로 두지 않는 이유** — `fired` 에서 파생되는 것뿐이라 파티 한 번에 많아야 네 개다.
읽음 상태도 없어서(ADR-4) 받은편지함이 아니라 타임라인이고, 그건 "지금 무슨 일인가"의 과거형이다.
탭바의 자리는 그보다 비싸다.

- **단계 이름은 운영자 용어다.** 참가자에게는 할 일을 문장으로 준다 (`HOME.todo`)
- **남은 시간은 제 카드다** (`.countdownCard`, 할 일 카드 **위**). 할 일 카드 **안**에 두지 마라 —
  매력 투표부터는 같은 카드에 `콕 N회 남음` 이 서는데 둘 다 `.kicker` 라 **같은 무게로 연달아**
  붙는다. 하나는 시계고 하나는 예산인데 눈이 둘을 같은 종류로 읽는다.
  양끝 정렬이라 **시간은 늘 오른쪽 끝**이다 — 상단 바에 있던 시절부터 그 자리다.
  **세는 것이 없으면 카드째 사라진다**(파티·발표). 빈 상자를 남기지 마라.
  **다음에 일어날 일**만 센다: 등록 중이면 `매력 투표까지`, 매력 투표 중이면 `파티까지`.
  예약 시각이 지났는데 운영자가 아직 안 넘겼으면 **그 다음 것을 센다** — 지나간 시각을 세면
  음수가 뜨고 사람은 그 숫자를 자기 시계가 틀린 걸로 읽는다.
  **사전 투표 마감·발표는 세지 마라** (ADR-14). **라벨을 떼지 마라** — 숫자만 있는 타이머는
  무엇을 세는지 알 수 없다. **숫자를 키우지 마라** — 1초마다 바뀌는 큰 숫자는 화면의 주인이 된다
- **등록 중에만** 카드에 `진행 방식 보기` 가 붙는다 (`HOME.guide`, 슬라이스 21). 등록 직후 저절로 뜬
  도움말을 반사적으로 닫은 사람이 다시 여는 길이다 — 자리 확인창에서 겪은 것과 같다.
  **사전 콕 찌르기부터는 두지 마라**: 그 자리에 `참가자 보러 가기` 가 서고, 한 카드에 버튼이 둘이면
  어느 것이 지금 할 일인지 갈린다. 그 뒤로는 상단 물음표가 맡는다
- 결과는 홈에 **숫자만**, 상대가 누구인지는 내 정보에서 — 홈이 결과 화면이 되면 알림·내 정보가 빈다

**상단 두 줄** — 왼쪽에 `회차 이름`(위) `단계`(아래), 오른쪽에 도움말.

답하는 질문은 하나다 — **"내가 지금 어느 파티의 어느 단계에 있나."** 그것만 둔다.

**카운트다운은 여기 없다. 홈의 할 일 카드가 맡는다** (아래 「홈 탭」).
카운트다운이 세는 건 늘 *다음에 일어날 일*이다 — 매력 투표 시작 · **마감**(ADR-39) · 파티 시작.
**발표는 세지 않는다** — 운영자가 눌러서 셀 수 있는 시각이 없다 (ADR-14).
그건 "지금 무슨 일이고 내가 뭘 하면 되나" 에 답하는 홈의 질문이다.

여기 있던 시절의 대가는 **회차 이름**이 치렀다 — 오른쪽 열이 제 폭(약 85px)을 붙들고 있어서
390px 폰에서 이름 칸이 219px 뿐이었다. 조금만 긴 이름이면 늘 말줄임됐다. 지금은 304px 다.

**도움말은 옅게 채운 원이다.** 한동안 22×30px 테두리 네모였는데, 다른 것들(카드·버튼·칩)이
전부 **가로가 긴** 모서리 둥근 네모라 세로로 긴 저것만 좁은 슬롯처럼 보였다.
게다가 헤더에서 유일하게 테두리를 가진 것이라 *"회차 이름보다 먼저 읽히면 안 된다"* 를 스스로 깼다.
보이는 크기(28px)와 탭 영역(`--tap` 44px)은 같을 필요가 없다 — 바깥 버튼이 44px 를 지킨다.

스크롤해도 남는다.

- **줄어드는 건 회차 이름 하나뿐이다.** 나머지는 `flex: none` 으로 제 폭을 지킨다 —
  한 줄이던 시절 `108th TONE PARTY🔥 …` 같은 이름이 들어오자 옆의 것들이 같이 쪼그라들어
  두 줄로 접혔다. 이름만 말줄임한다
- **단계는 색으로도 구분한다** — 등록=회색 / 사전 투표=핑크 / 파티=골드 / 발표=완료색.
  부제 자리로 내려왔어도 색은 그대로다
- **회차 이름은 여기 하나뿐이다.** 어느 탭에 있든 "내가 어느 파티에 있나" 를 확인할 수 있어야 한다
- **인원 수도, 남은 콕도 여기 없다.** 남은 콕은 참가자 탭이 맡고,
  **인원 수는 참가자 화면 어디에도 없다** — 등록 중에 나가면 안 되고(ADR-21),
  사전 투표부터는 명단이 대신 말한다

**배너** — 최근 3분 이내의 단계 변화만 배너로 띄운다. 그보다 오래된 건 알림 탭에만.

- 단계 배너 → 누르면 홈. **홈에서는 띄우지 않는다** — 소식 목록이 이미 있다. 발표 되돌림은 `warn` 변형
- 자리 배너 → 누르면 내 정보 탭
- **자리 이동 확인**은 전체 화면을 덮는다. 단, **발표가 끝났으면 띄우지 않는다**

**참가자 탭**

- 카드 높이 **74px 고정**. 매력은 한 줄 말줄임 — 문장형 입력이 들어와도 카드 높이가 흔들리면 안 된다
- 이름 줄과 매력 줄 사이를 붙이지 마라. MBTI 배지와 매력 칩의 **테두리가 맞닿아 겹쳐 보인다**.
  두 줄이 22+22px 이라 74px 안에 여유가 있다
- 프로필 시트에서는 매력 **전문**을 보여준다
- 필터는 **`전체` 가 왼쪽**이다. 기본값이 전체라(ADR-17) 켜져 있는 쪽이 먼저 읽혀야 한다.
  **인원 수를 붙이지 마라** — 이 버튼이 답하는 건 "누구를 볼까" 하나이고,
  애초에 참가자 응답에 인원 수가 없다 (ADR-21)
- 필터와 목록 **사이에 다른 것을 끼우지 마라.** 거르는 버튼은 걸러지는 것 바로 위에 있어야 한다 —
  걸러지지 않는 것이 사이에 있으면 눌러도 그게 남아 있어 **필터가 안 먹은 것으로** 읽힌다
- 거를 명단이 없으면 필터도 그리지 않는다. 다만 판단은 **거르기 전 명단**으로 한다 —
  `이성만` 이 0명이라고 감추면 `전체` 로 돌아갈 버튼째 사라져 화면이 잠긴다
- `이성만 보기` 토글은 **전체 폭**이다. 옆에 글자를 붙이면 알약 컨테이너와 맨 글자가
  한 줄에서 서로 다른 층위로 읽히고, 늘어난 토글과 오른쪽 글자 사이에 빈 공간이 남는다
- **남은 콕은 내 카드 오른쪽 칸에 있다** (`.mineCell`). `.pokeCell` 과 **같은 폭(62px)** 이라야
  카드 오른쪽 끝이 맞는다 — 사이에 필터 줄이 있어도 끝이 같으면 같은 식구로 보인다.
  **라벨(`남은 콕`)을 떼지 마라.** 남들 줄에서 그 칸은 버튼이라, 숫자만 두면
  눌리지 않는 내 콕 버튼으로 읽힌다.
  상단 바에도 두지 마라 — 두 곳에 같은 숫자가 있으면 어느 쪽이 맞는지 눈이 한 번 더 확인한다
- 목록 머리에는 아래 사람들에 대한 안내만 남는다. 볼 사람이 없으면 그 줄도 없다
- 👉 버튼 = 콕 확인 다이얼로그 (`POKE.confirm`). **카드와 같은 키·같은 모서리**다 —
  44px 알약이던 시절엔 74px 카드 옆에서 혼자 작고 동그래서 짝이 안 맞았다.
  찌른 횟수는 **버튼 안**에 있다 (밖에 두면 폭이 흔들리지 않게 자리를 늘 비워둬야 했다).
  찌른 뒤에는 `--heart → --accent-solid` 로 흐른다 — 보낸 마음이 매칭으로 향하는 방향이다
  (순위 바 `--meter` 와 같다). **`.btn` 이 아니므로 `:disabled` 를 따로 준다**

**내 카드 — 필터 위** (ADR-31 후기)

답하는 질문은 하나다: **내가 남들에게 어떻게 보이나.** 내가 낸 것 전부는 내 정보 탭에 있다.

- **`toPublic()` 을 그대로 쓴다.** 화면에서 규칙을 다시 짜면 갈라지고, 하필 "이렇게 보여요" 라고
  말하는 자리라 갈라지는 순간 거짓말이 된다. **서버 응답은 바뀌지 않는다**
- **단계를 그대로 넘기지 마라.** `toPublic` 은 `prevote` 에서만 나이·MBTI 를 뺀다 —
  등록 중에 그대로 부르면 나이가 나오는데 정작 사전 투표에서는 안 보인다.
  **남들이 나를 처음 보게 되는 상태**로 바꿔서 부른다
- **필터 위에 둔다.** 한동안 목록 맨 줄에 뒀었는데(같은 모양이라야 "이렇게 보여요" 가 성립한다고 봤다),
  필터가 다스리지 않는 것이 필터와 목록 **사이**에 끼는 모양이었다. 옮겨도 같은 카드·같은
  `toPublic()` 결과라 "이렇게 보여요" 는 그대로다 — 잃은 건 목록과 붙어 있음 하나뿐이고
  그게 오해를 만들고 있었다
- **`이성만 보기` 에서 빠지지 않는다.** 이제 필터 밖이라 자동으로 그렇다.
  감추고 남은 콕만 따로 어딘가에 남기는 길로 가지 마라 — 숫자가 두 집 살림을 하게 된다
- **콕 버튼이 없다.** 비활성이 아니라 아예 없다
- **누르면 내 정보 탭으로 간다.** 남들 카드처럼 프로필 시트를 열 수는 없다 —
  시트는 `roster` 에서 상대를 찾는데 거기 나는 없다. 그렇다고 혼자 못 누르는 카드로 두면
  여기서 더 보고 싶은 것(매력 전문·내가 낸 것 전부)이 어디 있는지 알 길이 없다.
  이동은 **`onTab` 을 통한다** — push/replace 규칙이 거기 한 곳에 있다 (`docs/ROUTES.md`).
  **화살표를 붙이지 마라**: 이 줄에만 붙으면 남들 카드보다 더 눌러도 되는 것처럼 보인다.
  대신 목적지를 `.srOnly` 한 줄로 남긴다 (`PEOPLE.mineOpen`) — **`aria-label` 로 덮지 마라.**
  덮으면 "내가 남들에게 어떻게 보이나" 가 스크린리더에게만 사라진다
- "나" 는 **글자로** 말하고 **아바타 위에** 얹는다 (`.avatarMine`). 이름 줄은 닉네임·나이·MBTI 로
  이미 꽉 차 있다. **동물을 "나" 로 바꾸지 마라** — 이 카드는 남들이 보는 모습이고 남들은 내 동물을 본다.
  지우면 내가 어느 동물인지 끝내 모르는데, 파티장에서 사람을 찾는 게 그 동물이다 (ADR-30).
  **매칭 색(`--accent`)도 쓰지 마라** — 목록에서 가장 눈에 띄어야 하는 건 서로 찌른 사람이다
- 카드 아래에는 아무 말도 붙이지 않는다. "나" 태그와 맨 위라는 자리가 이미 말한다 —
  아직 안 열린 항목에 대한 안내는 **목록 머리 줄**이 맡는다 (`PEOPLE.agesAtParty`).
  **문구의 주어는 자리가 정한다**: 목록 위에 있으면 아래 사람들 이야기라 "볼 수 있어요" 이고,
  내 카드 밑이면 반대 방향이라 "남들에게" 를 박아야 한다. 자리를 옮기면 문장도 함께 본다
- **등록 중에도 보인다.** 남의 명단은 사전 투표부터지만(ADR-21) 내 카드는 내 정보라 그 규칙과 무관하고,
  고칠 수 있는 유일한 시간이 그때다. `PEOPLE.notOpenYet` 은 **남들에 대한 말**이라 그대로 둔다

**소식 (홈 안)**

- `ev.fired` 에서 파생한다. 읽음 상태를 저장하지 않는다 (ADR-4)
- 익명 콕이 쌓이면 정보량 0인 카드가 반복된다 — 카운터로 합칠 것

**내 정보 탭**

- 실명·전화번호는 기본 가림. 파티장에서 어깨너머로 보인다
- **등록할 때 낸 것은 등록 중에만 고칠 수 있다** (ADR-31). 명단이 열리는 시점과 같다
- **고치기는 하나뿐이다.** 누르면 기본 정보와 매력이 **함께** 폼이 되고 저장도 한 번이다 —
  매력만 따로 고치는 버튼을 두지 마라. 참가자가 하는 일은 하나고 잠기는 순간도 하나다
- **전화번호는 편집 모드에서도 칸이 아니다** (ADR-15). 값은 보이되 왜 못 바꾸는지 한 줄이 붙는다
- 잠긴 뒤에는 버튼을 없애고 그 자리에 `ME.locked` 를 둔다 — 버튼만 사라지면
  "내 화면만 이상한가" 가 된다. **늦게 등록한 사람은 처음부터 이 문구만 본다**
- 닉네임이 겹치면 그 칸에 알리고 **입력값은 지우지 않는다.** 저장은 전부 되거나 전부 안 된다
- 발표 후에도 결과는 여기 없다. 매칭·연락처는 전부 참가자 탭에 있다 (ADR-18·19)

**도움말 `/e/:code/help`** — 파티장에서 읽는 글이다. 어둡고, 시끄럽고, 한 손에 잔이 있다.

- **네 칸이다** — `등록 · 사전 콕 찌르기 · 파티 · 발표`. `등록` 칸을 빼지 마라:
  등록 직후에 저절로 열리는데 그때 어디에도 `지금` 이 안 붙으면 **처음 읽는 사람이 자기 위치를 못 찾는다**
- 지금 단계는 **글자로도** 말한다 (`HELP.nowHere`). 색만으로 말하지 않는다
- **회차 설정에서 오는 것은 값뿐이다.** 문장 구조는 고정하고 숫자와 켬/끔만 갈아끼운다 —
  콕 횟수(`maxPre`·`maxParty`)와 동성 콕 여부(`allowSameGender`)뿐이다.
  **자유 입력 칸을 만들지 마라** — 그러면 회차마다 낡는 글이 하나 생긴다
- **동성 콕 줄은 막힌 회차에만.** 기본값에서는 줄 자체가 없다 —
  "누구에게나 찌를 수 있어요" 는 아무도 안 묻는 답이고, 그만큼 묻는 답이 뒤로 밀린다
- **일정 시각·장소를 넣지 마라.** 시각은 상단 카운트다운이 이미 세고(같은 숫자가 두 곳에 있으면 안 된다),
  장소는 참가자 응답에 없다 (ADR-32)
- **`링크를 잃어버렸어요` 를 넣지 마라.** 답이 "운영자에게 말하세요" 뿐이라 질문을 줄이는 게 아니라 유도한다
- 한 줄을 더할 때 묻는 것은 하나다 — **이 줄이 없으면 운영자에게 묻게 되는가**

**회차 목록** — `새 회차 만들기` 와 `회차 기본 설정` 은 스크롤에서 빠진다 (`.pinned`).
회차가 쌓이면 목록과 함께 밀려 올라가는데, 그때 운영자가 하려던 일이 바로 그것이다.
`.screen` 이 세로 flex 라 `.body` 만 흐른다 — 그 앞에 두면 제자리에 남는다.

**회차 코드는 만들 때 묻지 않는다.** 서버가 겹치지 않는 것으로 붙인다 —
참가자가 코드를 입력하는 화면이 없어진 뒤로(ADR-15) 그 칸이 답하는 질문이 없어졌다.
만들어진 코드는 회차 목록과 콘솔 머리에서 본다.

**`나가기` 는 없다.** 운영자 세션은 12시간이면 스스로 끊긴다 — 파티가 도는 화면에
전체 권한을 지우는 버튼을 상시로 둘 이유가 없다. PIN 화면으로는 세션이 끊길 때 알아서 간다.

## 실패했을 때 — 하얀 화면을 남기지 않는다

실패에도 **다음 할 일**이 있어야 한다. 그리고 이 앱에는 다른 앱이 못 하는 말이 하나 있다 —
**운영자가 눈앞에 있다.** `새로고침해도 안 되면 운영자에게 이 화면을 보여주세요` 는
빈말이 아니라 실제로 회복되는 길이다. 운영자는 콘솔에서 그 사람을 찾을 수 있다.

| 실패 | 무엇이 받나 |
|---|---|
| API 오류 (401·404·409·429) | `Failed` — 서버가 고른 문구 + 돌아가기 |
| **요청이 매달림** | `AbortSignal.timeout` — 보통 10초, **운세만 25초.** `fetch` 에는 기본 시간 제한이 없어서, 없으면 브라우저가 포기할 때까지 몇 분간 빈 화면이다 |
| **망이 끊김** (`fetch` 거부) | `ApiError(0, "offline")` → `Failed` 에 **새로고침**. `처음으로` 를 주면 안 된다 — 회차를 잘못 찾은 게 아니다 |
| **렌더 중 예외** | `Boom` 경계. 라우터 **바깥**이라 라우팅이 터져도 덮는다 |
| **번들이 아예 안 붙음** | `index.html` 안의 인라인 화면. 경계도 소용없다 — 경계가 그 번들 안에 있다 |
| 없는 주소 | `NotFound` |
| **운영자 콘솔·기본 설정을 못 불러옴** | `LoadFailed` — 401·403 은 PIN 화면으로 가지만 **그 밖의 실패는 아무 데도 안 갔다.** 파티 중에 콘솔이 통째로 비면 단계도 못 넘긴다 |

- **운세 시간 제한만 길다.** 미리 만들지 않고 **뒤집는 순간 LLM 을 부르기 때문**이다 (ADR-20).
  서버가 12초에 규칙 문구로 떨어뜨리므로 짧게 잡으면 **정상인 걸 우리가 먼저 끊는다**
- **`signal` 은 `...init` 뒤에 둔다.** 앞에 두면 호출자가 `init` 을 넘기는 순간 조용히 덮이고,
  시간 제한이 사라진 걸 아무도 모른다
- **오류 내용을 화면에 찍지 마라.** 참가자에게는 읽을 수 없는 글자이고,
  스택에 무엇이 섞여 나올지 우리가 통제하지 못한다. 콘솔에만 남긴다
- **밖으로 보내지 마라.** 외부 오류 추적 도구는 예외 컨텍스트에 요청 본문을 담는 일이 흔하고,
  이 앱에서 그건 등록 폼이다 — 파기가 DO 하나 지우는 일로 끝나야 한다
- **`return <div className="screen" />` 앞에 반드시 실패 갈래를 둔다.** 그 빈 화면은
  *불러오는 중* 이라는 뜻이지 *실패했다* 는 뜻이 아니다. 실패가 그리로 흘러가면
  화면이 영영 비어 있고, 사용자는 무엇이 잘못됐는지도 뭘 해야 하는지도 모른다
- **그 화면은 6초 뒤에야 나타난다** (`.bootFail` · CSS 애니메이션). HTML 안에 있으니
  브라우저가 먼저 그리고 React 가 덮는데, 늦추지 않으면 **정상 경로에서 매번 번쩍인다.**
  멀쩡히 도는 앱이 매번 실패했다고 말하면 진짜 실패했을 때 아무도 안 믿는다.
  **JS 로 늦추지 마라** — 번들이 안 붙은 상황을 위한 자리라 스크립트에 기댈 수 없다.
  그 전까지 어두운 바탕만 보이는데, 앱이 자료를 기다릴 때와 같은 모습이라 이질감이 없다
- `index.html` 의 문구와 모양은 **전부 인라인**이다. CSS 파일도 같이 못 붙었을 수 있다.
  `copy.ts` 밖에 문구가 있는 유일한 자리이고, `FAIL` 을 고치면 그쪽도 같이 봐야 한다

## iOS 사파리에서 다른 것

실기기 점검은 아직이다. 코드에서 맞춰둔 것만 적는다.

- **전화번호는 `+82 10-…` 로 들어온다.** iPhone 연락처가 그 모양으로 저장하고,
  자동완성·붙여넣기가 그대로 준다. 숫자만 남기면 `821012345678` 이라 앞에서 자르면
  **틀린 번호가 조용히 통과한다.** `typedPhone()` 이 편다 — 안드로이드는 `010…` 을 줘서
  이 문제가 오래 안 보였다
- **소프트 키보드는 `--kb` 가 맡는다.** 뷰포트 메타의 `interactive-widget=resizes-content` 를
  iOS 는 모른다. 거기서는 시각 뷰포트만 줄고 레이아웃은 그대로다 (`lib/keyboard.ts`)
- **`100dvh` 앞에 `100vh` 를 둔다.** iOS 15.3 이하는 `dvh` 를 모르고, 그러면 선언이 통째로
  버려져 화면 뼈대가 무너진다
- **`viewport-fit=cover` + `env(safe-area-inset-*)`.** 노치와 홈 인디케이터를 피한다 —
  헤더·탭바·토스트·전체 화면 알림 넷 다
- **`pageshow`(bfcache)를 듣는다.** iOS 는 페이지를 얼렸다 되살리는데, 그때 소켓은 죽었고
  `visibilitychange` 가 안 올 수 있다. 놓친 건 서버가 다시 밀어주지 않는다 (ADR-26)
- **입력칸 글자는 16px 이상.** 그 미만이면 iOS 가 입력할 때 화면을 확대한다
- **복사 실패를 성공이라고 말하지 않는다.** 막히는 브라우저가 있어서 주소창을 쓰라고 알려준다
- **버튼에 `-webkit-touch-callout: none` + `user-select: none`.** iOS 는 버튼 안 글자를 길게 누르면
  선택 메뉴와 돋보기를 띄운다. 콕처럼 연달아 누르는 버튼에서 두 번째 탭이 그 메뉴를 여는 일이 생긴다
- **닫기가 `navigate(-1)` 인 라우트에는 갈아끼우기 길을 함께 둔다.** 주소를 직접 열었거나
  새로고침한 사람에게는 뒤로 갈 자리가 없어서 **앱을 벗어난다.** iOS 는 가장자리 스와이프가
  뒤로 가기라 더 쉽게 걸린다 — `/me/edit` 과 `/seat` 둘 다 그렇게 돼 있다

🔥 받은 콕 TOP 5(동점이면 그만큼 확장 · 공동 순위 같은 번호 · 0회 제외 ·
하트→주 색 그라데이션 바 · 3위까지 금색 번호).
자리 이동 확인율은 여기 없다 — 자리를 보낸 직후에 보는 숫자라 자리 탭 라운드 카드에 있다.

**받은 콕 순위는 여기에만 있다.** 참가자 탭의 개인 행에는 넣지 않는다 —
명단은 한 사람씩 훑는 자리고, 현황은 전체 분위기를 읽는 자리다.
**공동 1위는 함께 보여준다** — 한 명만 집으면 나머지가 조용히 가려진다.

일부러 두지 않은 것 —
- **성비** · **등록 명단** — 참가자 탭에 있다. 같은 숫자를 두 곳에 두면 어느 쪽이 맞는지 눈이 한 번 더 확인한다
- **아직 콕을 못 받은 사람** — 알면 그 사람을 다르게 대하게 된다. 이 앱이 없애려던 경험이다
- **콕 총 횟수** · **참여율** — 운영 판단에 쓰이지 않는다.
  화면에 있는 숫자는 전부 누를 이유가 있어야 한다

**참가자** — **위아래 두 목록이 역할을 나눈다.**

| | 맡는 것 | 하는 일 |
|---|---|---|
| **입장 명단 카드** (맨 위) → 시트 | 등록 **전/후** | 명단에 더하기 · 안내문 복사 · 아직 등록 안 한 사람의 링크 · 명단에서 빼기 |
| **참가자 카드** (아래) | 등록 **후** | 참가 상태(도착·미도착·나감) · 상세 → 삭제 |

**한 사람은 한 번만 나온다** — 등록하면 명단 행에서 빠지고 카드로 올라온다.
그래서 명단은 파티가 다가올수록 줄고 카드가 그만큼 는다. 같은 사람이 두 곳에 있으면
"누구에게 보냈나" 와 "누가 왔나" 를 같은 사람으로 두 번 세게 된다.

맨 위가 **입장 명단 카드**다 (ADR-15). 카드는 **열지 않고도 아는 것**만 말한다 —
비었나(가장 크게. 비어 있으면 아무도 못 들어온다) · `초대 N명 · 등록 M명`.
누르면 `/host/:id/players/invites` 시트가 열리고 명단 일이 전부 그 안에 있다 —
더하기 · 안내문 카드(복사·문구 고치기) · 아직 등록 안 한 사람의 행(링크·빼기).
**시트로 접은 이유**는 시간이다: 명단 일은 파티 **며칠 전에 한 번에** 하고,
카드 일(참석 찍기)은 **문 앞에서** 한다. 늘 펼쳐 두면 당일에 쓰는 목록이 지난 일 아래로 밀린다.

**안내문을 보낼 일이 남은 사람은 아직 등록 안 한 사람뿐이다** — 등록하면 행에서 빠지고
카드로 올라간다. **남아 있는 줄이 곧 아직 안 온 사람이다.**

**문구와 링크는 따로 복사해 두 번에 나눠 보낸다** (ADR-32 후기). 한 덩어리로 보내면 참가자가
그 글에서 링크만 집어내야 하고, 장소에 지도 링크를 넣은 회차에서는 한 메시지에 링크가 둘이 된다.
링크만 온 메시지는 그대로 눌러 열거나 주소창에 붙여넣을 수 있다.

- **안내문 복사는 명단 머리에 하나뿐이다.** 링크가 빠져서 안내문이 회차당 하나가 됐다 —
  사람마다 다를 것이 없으니 행마다 두지 않는다. **행에는 사람마다 다른 것만** 남긴다
- 안내문에 `{링크}` 는 없다. 저장해 둔 옛 문구에 남아 있으면 **렌더링에서 지운다** —
  채워 넣으면 한 사람의 링크가 모두에게 나간다
- **보냄 표시를 만들지 마라.** 복사가 곧 발송이 아니고(붙여넣기 전에 마음이 바뀐다),
  되돌릴 수 있는 표시는 틀렸을 때 아무도 모른다. 명단에 남아 있는 줄이 이미 그 답이다
- **안내문 카드는 버튼 둘이 전부다** — 복사와 고치기. **미리보기를 두지 마라**:
  고치는 화면이 글을 그대로 띄우고 있어 같은 일을 두 번 한다. 명단은 계속 보면서 일하는
  목록이라, 한 번 확인하면 되는 글이 그 위를 차지하면 안 된다

명단 편집은 **더하기와 빼기만** 한다. 칸은 한 명씩 넣는 것 하나뿐이고,
통째로 갈아치우는 길은 두지 않는다 (ADR-15).
**명단에 더하는 길은 이 시트 하나다** — 참가자 카드 쪽에는 없다.

**번호 칸은 참가자가 문 앞에서 치는 칸과 같은 모양이다** — `010` 이 미리 들어가 있고
하이픈으로 3-4-4 로 끊겨 보인다 (`formatPhone`). 목록에 쌓인 번호도 같은 모양으로 끊는다.
운영자가 넣는 번호와 참가자가 치는 번호가 같아야 문이 열리는데, 두 칸이 달리 보이면
같은 번호를 다르게 옮겨 적게 된다.
- **`maxLength` 를 걸지 마라.** 미리 들어간 `010` 뒤에 커서를 두고 `010-1234-5678` 을
  붙여넣으면 `010010…` 이 되는데, 브라우저가 먼저 잘라버리면 겹친 것을 알아볼 길이 없어진다.
  자르는 곳은 `typedPhone()` 한 곳이다 — 거기서 겹친 앞머리를 버린다.
  이 사고는 **운영자 쪽이 더 비싸다**: 참가자는 문 앞에서 다시 치면 그만이지만
  명단에 조용히 틀린 번호가 들어가면 파티 당일에야 드러난다
- 문턱은 **아홉 자리**다. 서버(`addInvites`)와 같은 값이라 011 같은 옛 번호도 들어간다

그 아래 전체 / 남성 / 여성 필터와 등록한 사람 카드. 셋 중 하나가 항상 켜져 있고,
**각 버튼에 인원 수가 함께 붙는다** — 고른 쪽만 세면 성비를 보려고 버튼을 두 번 눌러야 한다.
**칩 셋이 곧 성비라** 성비를 따로 적지 않는다. 현황 탭에서 뺀 성비가 실제로 필요한 자리가 여기다.
카드 → 상세 시트. **삭제는 상세에서만**, `DELETE_PLAYER` 로 사라지는 데이터를 숫자로.

**참가 상태는 카드 안 맨 오른쪽의 배지**다 (ADR-33). 그냥 글자가 아니라 **상태값**으로 읽혀야 해서
알약 모양에 톤을 준다 — 도착 `--ok` · 나감 `--warn` · 미도착/등록함 무채색.
**톤은 거들 뿐 글자가 정보를 다 나른다.** 파티 전에는 작은 배지(`등록함`),
시작 뒤에는 눌러서 찍는 44px 칩(`미도착` ↔ `도착`) — 문 앞에서 한 명씩 하는 일이라
한 번에 끝나야 한다. **크기는 단계가 정한다**: 파티 중에는 누를 수 없는 `나감` 도 같은 크기로 선다.
한 줄만 작으면 덜 중요한 사람으로 읽힌다. `나감` 을 되돌릴 자리는 상세의 3단 선택이다.
카드가 버튼 하나가 아니라 상자인 이유가 이 칩이다 — 버튼 안에 버튼을 넣을 수 없어서
왼쪽(아바타·실명·번호)이 상세를 여는 손잡이고 오른쪽이 참석이다.
파티가 시작되면 카드 위에 **`도착 N · 미도착 N` 한 줄**이 붙는다. 카드마다 상태가 있어도
"몇 명 남았나" 는 세어서 알 일이 아니다.

**받은 콕은 어디에도 보여주지 않는다** (ADR-22) — 목록에도, 상세에도, 삭제 확인창의 숫자에도.
보낸 콕만 남긴다. "누가 아직 아무도 안 찔렀나" 는 말을 걸어볼 신호다.

**자리** — **자리 재배정**(→ 시트에서 테이블 수) → 검토(맞교환·**자리 섞기**) → **자리 확정하고 알리기**.

**참가자에게는 발행해야 보인다** (ADR-39) — 파티가 시작되기 전에도. 초안은 조용하다.
매력 투표 마감(`voteEndAt`)과 파티 일시 사이가 **첫 자리를 짜는 시간**이고,
그 사이에 보내면 일찍 온 사람이 자기 테이블에 앉아 기다린다.

**배정 시트에는 뺄 사람을 고르는 자리가 없다** (ADR-41). 빠지는 건 참석 상태가 `나감` 인
사람뿐이고, 그건 **서버가 읽는다** — 화면은 결과를 미리 말해줄 뿐이다.

- 인원 줄은 **테이블 수보다 위**에 선다. 아래 `테이블당 N명` 이 이 인원으로 계산되므로,
  빠진 사람이 있는 줄 모르면 방금 읽은 숫자가 왜 그런지 알 수 없다
- 나간 사람이 있으면 `1명 배정 · 나감 1명 제외` · 없으면 `2명 배정` 한 줄이다.
  **`나감 0명` 이라고 쓰지 마라** — 없는 일을 알리는 줄이다
- **`미도착` 은 앉힌다.** 안 찍은 사람과 안 온 사람이 같은 값이라(ADR-33) 여기서 빼면
  온 사람이 조용히 자리를 잃는다. 빈 자리는 보이지만 없는 자리는 안 보인다
- 되돌릴 곳은 **참가자 탭의 상태 칩 하나뿐**이다. 되돌리면 다음 배정에 다시 들어온다

파티 시작 확인창은 여전히 `배정된 자리` 를 숫자로 말한다: 자리 없이 시작하면 참가자 전원이
`자리가 정해지면 알려드려요` 만 보게 되는데, 예전에는 누른 뒤에야 알았다. **막지는 않는다.**

**발행한 라운드도 고칠 수 있다.** 초안과 같은 조작 셋이 붙는다 (슬라이스 11).

| | 어떻게 | 확인창 |
|---|---|---|
| 맞교환 | 같은 카드 안에서 두 명을 차례로 누른다 | 커플 자리에서 쌍이 깨질 때만 |
| 앉히기 | `자리 없는 사람` 의 이름을 누른다 | 없음 (되돌릴 수 있다) |
| 자리 비우기 | 한 명을 고른 뒤 나타나는 버튼 | 없음 (되돌릴 수 있다) |

- **고른 사람은 라운드까지 함께 기억한다.** 카드가 여럿이라, 초안에서 고른 사람이
  발행된 라운드의 다음 클릭과 짝지어지면 엉뚱한 맞교환이 된다
- **`자리 비우기` 는 고른 뒤에만 보인다.** 상시로 두면 사람마다 버튼이 하나씩 붙는다
- **앉히기는 테이블을 고르게 하지 마라** — 그게 `SEATING.md` 가 금지한 단일 이동 API 다.
  어디 앉았는지는 앉힌 **뒤에** 토스트가 말한다
- **발표 후에도 화면은 그대로 있다.** 지난 자리를 읽는 건 끝난 뒤에도 하는 일이다
  (다음 회차 자리를 짤 때, 사진을 정리할 때). 잠기는 건 **고치는 버튼뿐**이고,
  서버도 같은 문을 닫는다. **좌석 칩을 흐리게 하지 마라** — 저건 버튼이 아니라 정보다
- **발행된 라운드를 고쳐도 자리 이동 확인이 뜨지 않는다.** 그래서 카드에
  `고친 자리는 조용히 바뀌어요 — 본인에게 말해주세요` 를 **고치기 전에** 띄운다.
  앱이 말해주는 줄 알고 두면 그 사람은 옛 테이블에 앉아 있다.
  화면 자체는 방송으로 다시 읽는다 — **알림을 안 보내는 것과 화면을 안 고치는 것은 다른 일이다**
확정해도 배정은 닫히지 않는다 (ADR-28). 발표만이 자리를 끝낸다.
상세는 `SEATING.md`. 확정 전 자리는 참가자에게 렌더링하지 않는다.

문구는 운영자가 하는 일 그대로 쓴다 — '초안'은 우리 말이지 운영자 말이 아니다.
`자리 확정하고 알리기` 는 그 버튼이 하는 **두 가지 일**을 순서대로 적은 것이다.

좌석 칩에는 닉네임 아래 **실명 · 나이 · MBTI** 가 붙는다. 자리에서 사람을 찾으려면 실명이 필요하다
(운영자만 전체를 본다).

**커플 자리(`💘 커플 자리 배정`)는 화면이 다르다** (ADR-23) —
성적표 한 줄(`8쌍 중 7쌍`), 떨어진 쌍의 이름, 같은 테이블에서 이어진 사람에게 붙는 💘,
쌍을 깨는 맞교환에 붙는 확인. 확정 확인창은 배정이 닫힌다는 사실과 되돌리는 방법을 함께 말한다.
참가자에게는 이 라운드가 특별하다고 **말하지 않는다** — 누가 나를 찔렀는지 짐작하게 된다.

테이블마다 `남 3 / 여 3` 을 적고, 좌석 칩을 성별로 칠한다(`--male` / `--female`) —
어두운 파티장에서 성비가 깨진 테이블을 색으로 먼저 찾는다.
**색만으로 구분하지 않는다**: ♂/♀ 기호와 숫자가 같은 정보를 함께 준다.
고른 칩의 보라 테두리가 성별 색보다 세다 — 지금 하는 일이 맞교환이라서.
**남녀도 맞바꿀 수 있다** (ADR-16). 바뀐 성비는 그 숫자에 바로 보인다.

**설정** — 저장은 **확인을 거친다** (ADR-22). 바뀐 항목만 `이전 → 이후` 로 보여준다.
입장 코드는 글자로만 보이고 바꿀 수 없다. 콕 상한은 이미 쓴 횟수 아래로 내려가지 않는다.

#### 설정은 네 묶음으로 접힌다

위쪽 알약 줄에서 고르면 그것만 그려진다. 칸이 스무 개 가까이 되면서 한 두루마리로는
무엇이 어디 있는지 못 찾았다.

| 묶음 | 무엇이 |
|---|---|
| **기본 정보** | 회차 이름 · 장소 · 입장 코드 |
| **예약** | 등록 시작 → 매력 투표 시작 → 마감 → 파티 시작 → 커플 발표 (**시간 순**) |
| **콕 설정** | 횟수 둘 · 대상 · 되돌리기 둘 · 알림 둘 |
| **삭제** | `이 회차 삭제하기` 하나 |

앞의 셋은 **회차 만들기의 스텝과 같은 이름·같은 순서**다 (`HOST_UI.steps`, 테스트가 지킨다) —
만들 때 고른 것을 고치러 오는 자리라, 이름이 다르면 어디를 눌러야 할지 다시 찾는다.
예약이 시간 순인 것도 위저드 2스텝과 맞춘 것이다 (`등록 시작` 만 위저드에 없어 맨 앞에 더 있다).

⚠️ **묶음은 라우트가 아니라 화면 상태다.** 여는 게 아니라 **거르는 것**이라 뒤로 가기로
닫을 것이 없다 (모달·시트와 다르다 — `CLAUDE.md` 5번). 폼 하나를 나눠 보는 것뿐이라
**어느 묶음에 있든 입력값은 살아 있고 `적용` 은 셋을 한꺼번에 저장한다.**

**그래서 접힌 자리의 변경이 안 보이는 게 유일한 위험이다.** 두 곳에서 말한다 —
안 저장된 것이 있는 묶음에 **점**, 그리고 `적용` 아래 한 줄. 확인창은 **묶음과 상관없이**
바뀐 것을 전부 보여준다. 여기가 새면 접힌 자리에서 고친 것이 조용히 저장되거나 사라진다.

**삭제만 `적용` 버튼이 없다.** 저장할 값이 없고, 되돌릴 수 없는 버튼은 다른 걸 고치다
손이 닿는 자리에 두지 않는다. 그래서 다른 묶음에 끼워 넣지 않고 제 자리를 준다.

**설정** — 이름·PIN·코드·콕 횟수·일정. **지나온 일정 항목은 잠근다** (`schedLocked`).
순서가 역전되는 값은 저장을 거부한다.
**개인정보 파기 칸은 없다** (ADR-36) — 자동 파기가 없으므로 고를 숫자도 없다.
회차는 **운영자가 `이 회차 삭제하기` 를 누를 때까지** 남는다. 그 자리를 다시 만들지 마라 —
아무것도 지우지 않는 "며칠 뒤 삭제" 칸은 없는 것보다 나쁘다.
등록 화면의 연락처 안내(`REGISTER.contactNote`)는 **어디까지 가는지**만 말하고,
그 두 문장은 지우지 마라 — 받을 때 한 약속이 먼저다 (ADR-19).

### 회차 위저드 `/host/new/1..3`

**세 스텝은 성격으로 나뉜다.** 머리글이 `2/3 · 예약` 처럼 그 성격을 말한다 —
숫자만 있으면 몇 장 남았는지는 알아도 지금 무엇을 정하는 중인지는 모른다.

| 스텝 | 성격 | 입력 | 검증 |
|---|---|---|---|
| 1 | **기본 정보** | 회차 이름 · 장소 | 이름이 비면 `다음` 이 막힌다. **입장 코드는 묻지 않는다** — 서버가 붙인다 |
| 2 | **예약** | 매력 투표 시작 → 마감 → **파티 시작** → 커플 발표 | 30분 단위. 등록 시작은 묻지 않는다 (ADR-38). 발표가 파티보다 앞이면 거부 (ADR-43) |
| 3 | **콕 설정** | 횟수 둘 · 콕 대상 · 되돌리기 둘 · 알림 둘 | 예상 매칭 안내를 함께 표시 |

**2스텝의 네 시각은 시간 순으로 선다.** 그래야 읽는 사람이 어느 것이 먼저인지 다시 계산하지 않는다.
장소가 1스텝으로 간 것도 그래서다 — 시각이 아닌 유일한 칸이 시각 넷 사이에 끼면 그 목록이
시간 순으로 안 읽힌다.

⚠️ **넷 중 파티 시작만 예약이 아니다** (ADR-14). 운영자가 현황 탭에서 누른다.
그 사실은 목록 아래가 아니라 **그 칸에** 붙는다(`partyHint`) — 아래에 떠 있으면 어느 칸
이야기인지 알 수 없고, 넷 다 저절로 넘어가는 줄로 읽으면 **파티가 영영 안 열린다.**

**`partyAt` 은 셋째 자리에 있어도 여전히 기준점이다.** 이걸 옮기면 손대지 않은 칸이 따라 움직인다
(`changeParty`). **화면 순서와 계산 순서는 다른 이야기다** — 기본값은 여전히 파티에서 거꾸로 잰다.

**시각 칸은 위에서 아래로 시간 순이다.** 커플 발표만 파티 **뒤**를 재므로 맨 아래에 둔다 —
순서가 섞이면 어느 것이 먼저인지 읽는 사람이 다시 계산해야 한다.
발표 칸 힌트는 **`파티를 시작해야 울려요`** 를 말한다 (ADR-43). 그걸 모르면 운영자가
이 시각만 믿고 `파티 시작` 을 안 눌러서, 발표도 콕도 안 열린 채 시각만 지나간다.

**3스텝의 규칙 다섯은 설정 탭과 같은 순서로 둔다** — 대상 → 되돌리기(매력 투표·콕) → 알림(매력 투표·콕).
두 화면의 순서가 다르면 운영자가 매번 다시 찾는다.
되돌리기와 알림은 짝이라 라운드마다 따로고, 한쪽만 갈라놓으면 나머지도 갈라져 있는지 매번 확인하게 된다.

**다섯은 콕이 오가기 시작하면 함께 굳는다** (ADR-35) — 즉 **만들 때가 사실상 유일한 기회**다.
그래서 다섯이 다 여기 있어야 하고, 서버의 `validConfig` 도 다섯을 다 본다.
하나가 빠지면 이상한 값이 조용히 기본값으로 접히고, 운영자는 고른 대로 저장된 줄 안다.

### 회차 기본 설정 `/host/defaults`

콕 횟수 둘 · 매력 투표 오프셋 둘(시작·마감) · **발표 오프셋** · **장소** · 안내문.
**운영자 PIN 칸은 없다** —
배포 시크릿 `MASTER_PIN` 하나가 유일한 출처다.
저장된 옛 모양은 읽을 때 지금 모양으로 맞춘다. 없는 항목이 그대로 올라오면 숫자 칸이 NaN 이 된다.

**장소가 여기 있는 이유**는 늘 같은 곳에서 여는 모임이기 때문이다 (ADR-38).
위저드는 **비어 있을 때만** 채운다 — 운영자가 이미 적었으면 덮지 않는다.

**파티 시작이 기준이다.** 매력 투표 시작과 마감이 거기서 거꾸로 계산된다 —
(위저드에서는 **셋째 칸**에 서지만 계산의 기준인 건 그대로다)
`prevoteBeforeH`(기본 20)시간 전에 열리고 `voteEndBeforeH`(기본 1)시간 전에 닫힌다 (ADR-39).
**커플 발표만 앞으로 잰다** — `revealAfterH`(기본 3)시간 **뒤**다 (ADR-43). 부호가 반대인 유일한 값이라
위저드에서도 `+` 다. **등록 시작 오프셋은 없다** — 만드는 순간 열린다.

⚠️ 위저드는 서버 기본값에 **빠진 칸이 있으면 코드 기본값으로 메운다.** 새 칸이 붙은 직후에는
그 칸이 없는 응답이 실제로 온다 — 안 메우면 `undefined * HOUR` 가 `NaN` 이 되어 시각 칸이
**빈 채로** 뜨고, 그 빈 칸은 만들기 버튼을 누를 때에야 막힌다.

```
파티 일시를 옮기면  → 아직 손대지 않은 값만 따라 움직인다
직접 고친 값은      → 그대로 둔다. 고쳐놓은 걸 되돌리는 건 사고다
```

**예약하는 건 이 둘뿐이다.** 사전 투표 마감·파티 시작·발표는 현황 탭에서 운영자가 누른다 (ADR-14).
설정 화면에서 그 칸을 찾지 않도록, 일정 섹션 아래에 없는 이유를 적어둔다.

**콕 횟수 선택에는 예상 매칭을 함께 보여준다.** 기대 상호 매칭 쌍 수는 파티 규모와 무관하게
`k²` 에 수렴한다 (`pokeEstimate`, `pokeEstimateLabel`).

### 참가자 `/e/:code/people`

명단은 **단계마다 열리는 만큼만** 보인다 (ADR-21).

| 단계 | 보이는 것 |
|---|---|
| 등록 중 | 명단 없음 — 왜 비었는지 그 자리에서 말한다 |
| 사전 투표 | 닉네임 · 매력 |
| 파티 시작 후 | + 나이 · MBTI |

카드는 없는 항목을 빼고 그린다. `닉네임 · 28세 · ENFP` 가 사전 투표에서는 `닉네임` 하나다.

**발표 후 프로필 시트에 나가는 건 실명 한 줄이다** (ADR-19·42).

```
💘 서로 찔렀어요
파티장에서 직접 인사해보세요
이름                              이별빛
더 친해지고 싶다면 인스타를 나눠보세요.
```

⚠️ 라벨을 **`연락처` 라고 쓰지 마라.** 그렇게 쓰면 뒤에 뭔가 더 있어야 하는 칸이 되고,
빈 채로 남으면 고장 난 화면으로 읽힌다. **전화·인스타 줄을 다시 만들지 마라** —
`MatchInfo` 에 그 값이 아예 없다 (ADR-42).

마지막 줄은 **다음에 뭘 하면 되는지**만 말한다. 한동안 `연락처는 서로에게 보이지 않아요` 라고
없는 것을 설명했는데 뺐다 — 앱이 안 하는 일을 굳이 알릴 이유가 없고,
그 문장이 있으면 **못 받은 것**이 먼저 읽힌다.

⚠️ **앱이 인스타를 나눠준다고 읽히게 쓰지 마라.** 나누는 건 두 사람이지 앱이 아니다 —
`인스타가 열려요`·`인스타를 확인하세요` 는 화면 어디에도 없는 것을 찾아 헤매게 만든다.

### 재미 `/e/:code/fun` — 매력 투표부터, 탭 **맨 오른쪽**

**이 탭이 답하는 질문은 "심심한데 뭐 열어볼 거 없나" 다.** 파티의 기능(찌르기·명단·자리)이
아니라 **곁들이는 재미**가 여기 모인다. 지금은 운세 카드 하나뿐이고, 이상형 찾기가
두 번째로 붙는다 (슬라이스 19).

여기 들어오는 카드는 다섯을 지킨다. **하나라도 어긋나면 이 탭이 아니다.**

| | |
|---|---|
| 본인만 본다 | 운영자 화면에도 남에게도 나가지 않는다 |
| 한 번 열면 그대로 | 열 때마다 달라지면 그 순간 전부 거짓말이 된다 |
| 점수·등급·순위 없음 | 이 앱이 없애려던 경험을 앱이 직접 만드는 일이다 (ADR-20) |
| 실패해도 티가 나지 않는다 | 미션 규칙과 같다. 못 해도 아무 일이 없어야 한다 |
| 이야깃거리가 된다 | 답은 앱이 찾고, 말할지는 본인이 고른다 |

- **이름도 이모지도 카드 하나를 가리키지 않는다** (ADR-20 후기 2).
  `오늘`·`✨` 이었는데 `오늘` 은 날짜에 묶여 운세 말고는 들어올 자리가 없었고,
  `✨` 은 매력 투표 버튼(`ACT.emoji("pre")`)과 같은 것이었다.
  `재미`·`🎲` 는 탭 안에서 쓰는 🔮(운세)·🎯(미션)·🎨(색) 중 어느 것도 아니다 —
  카드 하나가 탭 전체를 대표하면 카드가 늘 때마다 아이콘이 거짓말이 된다
- **'내 정보' 와 헷갈리지 않게 가른다.** 내 정보는 *내가 적어 남에게 보이는 것*,
  여기는 *앱이 나에게만 주는 것*이다. 둘 다 나에 대한 자리지만 방향이 반대다
- **탭의 문은 가장 먼저 열리는 카드의 문이다.** 지금은 그게 운세라 `canOpenFortune` 이
  그대로 탭의 문이고, 꺼진 탭을 누르면 `FORTUNE.closed` 가 나간다.
  더 일찍 열리는 카드가 들어오면 탭의 문을 따로 적는다 — 카드의 문을 빌려 쓰지 마라
- **탭은 처음부터 자리를 지킨다. 없다가 생기지 않는다** (ADR-20 후기).
  매력 투표 전에는 흐리게 꺼져 있고(`aria-disabled`), 매력 투표가 시작되면 **같은 자리에서 켜진다** —
  탭이 도중에 생기면 넷이 나눠 쓰던 폭이 통째로 다시 나뉘어 손가락이 기억한 자리가 어긋난다
- 끝에 붙인다 — 도중에 끼어들면 있던 탭들이 밀려서 손가락이 기억한 자리가 어긋난다
- **꺼진 탭은 죽은 버튼이 아니다.** 누르면 `매력 투표가 시작되면 열려요` 를 말한다.
  눌러도 아무 일이 없으면 고장으로 읽힌다. 주소를 직접 열면 홈으로 갈아끼운다
- **미션의 문은 하나 늦다 — 파티부터.** 미션 문장에는 언제 할지가 들어가는데
  ("자리를 옮기고 막 앉았을 때") 매력 투표는 파티 스무 시간 전에 열린다.
  그때 뒤집으면 **할 수 없는 미션이 그대로 굳는다**(한 번 열면 그대로다).
  그 전까지 미션 카드는 `파티가 시작되면 열려요` 라고 적힌 채 물러나 있는다
- 운세의 `오늘` 은 **연 날이 아니라 파티 날**이다. 전날 밤에 연 사람이 어제 것을 읽지 않는다
- 오늘의 기운은 **세 문단**(오늘의 결 · 잘 통할 흐름 · 조심할 것), 그 아래 **오늘의 미션**
- 미션은 **두 줄이다**: 위가 왜 오늘 이것인지(`.missionLead`), 아래가 언제 무엇을(`.missionLine`).
  무게는 크기가 아니라 **차이**로 준다 — 이유를 흐리게 깔고 그 위에 미션을 얹어야 눈이 미션에 앉는다.
  **둘 다 굵게 하지 마라.** 둘 다 안 읽힌다
- `lead` 가 없는 저장본이 있다 (이 칸이 생기기 전에 연 운세, LLM 이 빼먹은 경우).
  그때는 **미션 한 줄만** 그린다 — 빈 자리를 남기거나 대신할 문장을 지어내지 마라
- 미션은 **두 번째 LLM 호출**이 만들지만 **카드는 하나다.** 호출이 둘이라고 카드가 둘일 이유는 없다 —
  '오늘의 어필' 을 따로 세웠다가 미션과 같은 말을 두 번 하게 돼 걷어냈다 (ADR-20)
- **기다리는 문구의 결이 둘로 갈린다.** 운세는 `오늘을 읽는 중`(차분), 미션은 `뒤적이는 중...`(가볍게).
  하는 일이 다르고 — 하나는 오늘을 읽고 하나는 읽은 것에서 고른다 —
  **운세는 진지해야 몰입되지만 미션은 가벼워야 실행된다.** 무게가 같으면 미션이 숙제처럼 내려앉는다.
  오브가 도는 동안이라 "작동 중" 은 그림이 이미 말한다. 그 줄은 맛만 내면 된다
- **미션도 뒤집어서 연다.** 뒷면(`오늘의 미션 열기`)은 **미션이 들어설 그 자리**에 있어서
  열려도 화면이 튀지 않는다. 누르는 그 순간에 만든다 —
  **미리 만들어 두고 감췄다 보여주지 마라.** 여는 동작이 있어야 그 한 줄이 오늘 것처럼 읽힌다.
  안 열어 본 사람 몫은 아예 만들지 않는 것도 덤이다
- 문구는 운세와 **같은 말**을 쓴다 (`열기`). 같은 동작에 같은 말이라야 두 번째도 같은 무게로 읽힌다
- 열기 전에는 카드 뒷면. 탭하면 뒤집히며 열린다 — 여는 동작이 있어야 그 한 줄이 오늘 것처럼 읽힌다.
  그 0.6초가 LLM 을 기다리는 시간을 자연스럽게 덮는다
- **한 번 열면 그대로 남는다.** 다시 열어도 같다는 걸 화면에서 미리 말한다
- **점수를 보여주지 않는다** (ADR-20)
- 카드 색은 `--tone` 하나로 갈린다. 테마 토큰에서만 골라서 어떤 결과에도 화면이 깨지지 않는다
- 미션 칸도 그 색으로 한 겹 띄운다 — 읽고 끝나는 게 아니라 **하는 것**이라서
- `prefers-reduced-motion` 이면 돌지 않고 그대로 나온다

## 시트와 확인창

동작은 Radix Dialog 에서 빌려 쓰고 **모양은 우리 CSS 변수 그대로**다 (`src/client/ui/Sheet.tsx`).
손으로 만들었을 때 없던 것: 포커스 트랩·포커스 복원·**스크롤 잠금**·Escape·배경 비활성화.

- 재본 값: gzip **12KB**. 같은 자리를 antd 로 채우면 215KB 였다
- **히스토리는 여전히 우리가 쥔다.** 뒤로 가기로 닫히고 실행 **전에** 히스토리를 정리하는 규칙은
  라이브러리가 모른다 — 열림 상태를 밖에서 주고 닫힘 요청만 받는다
- Escape 는 **취소와 같다.** 닫히기만 하고 행동은 실행되지 않는다

## 모바일 체크리스트

- `<meta name="viewport" ... viewport-fit=cover, interactive-widget=resizes-content>`
- 높이는 `100dvh` — iOS 주소창 때문에 `100vh` 는 어긋난다
- **아래에 붙는 것은 `--kb` 만큼 띄운다** — 시트·확인창·화면 높이·토스트.
  `position: fixed; bottom: 0` 은 **레이아웃 뷰포트** 기준이라 키보드가 떠도 안 움직인다.
  안드로이드는 위 메타가 레이아웃을 줄여 알아서 따라오지만 **iOS 사파리는 그 속성을 모른다** —
  거기서는 `lib/keyboard.ts` 가 시각 뷰포트로 잰 `--kb` 가 유일한 단서다.
  입력칸만 보이게 사파리가 스크롤해줘도 **눌러야 할 버튼은 여전히 안 보인다**
- 하단 탭바에 `padding-bottom: env(safe-area-inset-bottom)`
- 터치 타겟 최소 **44×44px**
- 입력 폰트 **16px 이상** — 미만이면 iOS 가 자동 확대한다
- 색·간격·모서리는 **CSS 변수로만**. 하드코딩 금지 (테마 교체의 토대)

## 테마

지금 테마는 **Airbnb 의 형태 언어를 밤으로 옮기고, 주 색만 우리 것으로** 바꾼 것이다.

| | |
|---|---|
| 주 색 | **자정 보라** — 글씨·테두리 `#9B7CFF` / 채운 버튼 `#6D48E5` |
| 의미색 | Babu `#00A699` 좋은 상태 · Arches `#FC642D` 주의 (Airbnb 그대로) |
| 형태 | 카드 16px · 버튼 8px · 필터는 알약 · 테두리보다 **그림자로 띄운다** |
| 바탕 | 순수 검정을 피한다. 파티장 조명 아래서 검정은 화면이 꺼진 것처럼 보인다 |

**주 색을 Airbnb 의 Rausch(자홍)로 두지 않은 이유**

- Rausch 는 예약 버튼의 색이다. 여기 버튼은 조심스럽게 누르는 콕이라 결이 다르다
- 소개팅 앱의 분홍·빨강은 가장 예상 가능한 선택이라 기억에 남지 않는다
- 앰버(파티)·청록(발표)과 색상환에서 가장 멀어 **단계 구분이 제일 또렷하다**

이 색은 버튼만이 아니라 **사전 투표 단계의 색**이다. 콕을 찌르는 시간의 색이라
경고처럼 튀지 않으면서 온기는 있어야 한다.

**밝은 쪽과 짙은 쪽을 나눠 쓴다.** 어두운 바탕 위의 글씨·테두리는 밝은 쪽(대비 5.9:1),
흰 글씨를 얹는 버튼은 짙은 쪽(5.7:1). 어두운 파티장에서 읽어야 하는 화면이라
대비에서 타협하지 않는다.

테마를 통째로 바꾸면서 **컴포넌트는 한 줄도 건드리지 않았다.** 색을 변수로만 쓰기로 한 규칙이
값을 한 자리에 모아둔 덕이다. 다음 테마도 같은 방식으로 갈아끼운다.
