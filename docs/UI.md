# 화면 요구사항

화면을 만들 때 지켜야 할 것. 문구는 전부 `src/shared/copy.ts` 에서 가져온다.
URL·히스토리 규칙은 `ROUTES.md`, 도메인 규칙은 `DOMAIN.md`.

---

## 전역 원칙

| 원칙 | 내용 |
|---|---|
| **되돌릴 수 없는 것만 확인을 받는다** | 콕 `+` · 단계 전환 · 참가자 삭제 · 자리 발송은 확인. 콕 `−`(되돌리기)와 자리 초안 생성은 즉시 |
| **확인창은 무엇이 어떻게 바뀌는지 숫자로** | "정말 하시겠습니까?"만 있는 다이얼로그는 만들지 않는다 |
| **문구가 버튼 이름과 겹치지 않게** | 본문에 "취소"를 쓰면 옆의 취소 버튼과 헷갈린다 → "되돌리기" |
| **에러는 그 값을 입력한 자리에** | 닉네임 중복이면 3스텝이 아니라 1스텝으로 되돌려 표시. 입력값은 보존 |
| **참가자에게 "0"을 들이대지 않는다** | 받은 콕 0회는 숫자 대신 별도 문구 (`REVEAL.noMutual`) |
| **일정은 30분 단위** | 파티 일정은 21:00 / 21:30 으로 잡힌다. 21:07 을 고를 수 있게 두면 고를 것만 많아지고 안내 문구에도 어중간한 시각이 나간다. `step` 은 피커만 붙잡으므로 **받은 값을 코드에서 맞춘다** (`snapSchedule`) |
| **"지금 바로"는 시각이 아니라 토글** | `datetime-local` 이 초를 버려서, "지금"을 시각으로 넣으면 매번 몇 초씩 어긋난다 |
| **하나만 켜지는 선택은 세그먼트 토글** | 한 컨테이너 안에서 채워진 칸이 움직여야 "여러 개 중 하나"가 형태로 보인다. 켜진 칸은 색이 아니라 채움과 굵기로 말한다 |

## 화면별 요구사항

### 뿌리 `/`

**여기서 할 수 있는 일이 없다.** 문은 참가 링크 하나뿐이다 (ADR-13·15 후기).

- 이미 어느 회차에 들어가 있으면 **그리로 보낸다.** 들어와 있는 사람에게 "링크로 오세요" 는 거짓말이다
- 아니면 링크로 들어오라고 말하고 끝. **입력 칸도 버튼도 두지 마라**
- **`운영자로 들어가기` 를 되살리지 마라.** 참가자에게 관리 경로를 광고할 이유가 없다 —
  운영자는 `/host` 를 직접 연다
- 예전엔 여기서 입장 코드 6자리를 물었다. 운영자는 보통 **링크만** 주므로,
  링크를 열었다 뒤로 간 참가자가 알지도 못하는 코드를 요구받는 **막다른 길**이었다

### 회차 확인 `/j/:id` — 참가 링크가 여는 곳

- 보이는 것: 단계 · 회차 이름 · 파티 일시. **입장 코드는 응답에도 화면에도 없다**
- **전화번호**를 넣어야 등록으로 넘어간다 (ADR-15). 명단에 있는 번호만 통과한다
- 실패 문구는 하나뿐이다 (`ENTRY.notInvited`) — 왜 안 되는지 말하지 않는다
- 번호가 틀려도 **입력값을 지우지 않는다**
- 이미 등록한 사람은 번호만 넣으면 곧바로 자기 화면으로 간다 — 링크를 다시 여는 게 기본 동작이다
- 준비 중 회차면 언제 열리는지 알린다 (`ENTRY.notOpenYet`)

### 참가자 등록 `/j/:id/register/1..3`

| 스텝 | 항목 |
|---|---|
| 1 기본 정보 | 닉네임 · 실명 · 나이 · 성별(토글 2개) |
| 2 연락처 | 인스타(**필수** — 매칭되면 서로에게 공개되는 연락 수단) · **전화번호는 묻지 않는다.** 입장할 때 확인했다 |
| 3 나를 소개 | MBTI 4문항 토글 · 매력 3가지 |

- **MBTI 는 16지선다 드롭다운이 아니라 4문항 토글** (`MBTI_AXES`). 모르는 사람도 답할 수 있어야 한다
- 선택 토글은 **입력값을 날리지 않는다.** 폼 전체를 다시 그리면 아직 저장 안 된 입력이 사라진다
- 닉네임 중복은 `REGISTER.err.nickTaken` + 1스텝으로 되돌림
- 이탈 시 `useDraftGuard` (`REGISTER.draftGuard`)

### 참가자 메인 `/e/:code`

3탭: **🏠 홈 / 👥 참가자 / 🙋 내 정보** (`TABS_PARTICIPANT`)

**탭마다 답하는 질문이 하나씩이고, 겹치지 않는다.** 같은 정보가 두 탭에 있으면
어느 쪽이 맞는지 눈이 한 번 더 확인하게 된다.

| 탭 | 질문 | 여기에만 있는 것 |
|---|---|---|
| 홈 | 지금 무슨 일이고 내가 뭘 하면 되나 | 단계별 **할 일 문장**, **내 자리**, 결과 요약(몇 명인지), **지금까지의 소식** |
| 참가자 | 누가 왔나 · 누굴 찌를까 | 목록·필터·프로필 시트·콕, 남은 콕 |
| 내 정보 | **내가 낸 것** | 내 프로필과 그걸 고치는 길 (ADR-31). 회차 이름은 상단 바로 옮겼다 |

**알림을 탭으로 두지 않는 이유** — `fired` 에서 파생되는 것뿐이라 파티 한 번에 많아야 네 개다.
읽음 상태도 없어서(ADR-4) 받은편지함이 아니라 타임라인이고, 그건 "지금 무슨 일인가"의 과거형이다.
탭바의 자리는 그보다 비싸다.

- **단계 이름은 운영자 용어다.** 참가자에게는 할 일을 문장으로 준다 (`HOME.todo`)
- 결과는 홈에 **숫자만**, 상대가 누구인지는 내 정보에서 — 홈이 결과 화면이 되면 알림·내 정보가 빈다

**상단 두 줄** — 왼쪽에 `회차 이름`(위) `단계`(아래), 오른쪽에 `파티까지` 카운트다운.
스크롤해도 남는다.

- **줄어드는 건 회차 이름 하나뿐이다.** 나머지는 `flex: none` 으로 제 폭을 지킨다 —
  한 줄이던 시절 `108th TONE PARTY🔥 …` 같은 이름이 들어오자 `1명` 도 `파티까지` 도
  같이 쪼그라들어 두 줄로 접혔다. 이름만 말줄임한다
- **카운트다운은 초까지 움직인다.** 분 단위면 멈춘 화면처럼 보인다. 폭이 흔들리지 않게 고정폭 숫자로
- **단계는 색으로도 구분한다** — 등록=회색 / 사전 투표=핑크 / 파티=골드 / 발표=완료색.
  부제 자리로 내려왔어도 색은 그대로다
- **회차 이름은 여기 하나뿐이다.** 어느 탭에 있든 "내가 어느 파티에 있나" 를 확인할 수 있어야 한다
- **인원 수도, 남은 콕도 여기 없다.** 인원 수는 홈 탭이, 남은 콕은 참가자 탭이 맡는다

**배너** — 최근 3분 이내의 단계 변화만 배너로 띄운다. 그보다 오래된 건 알림 탭에만.

- 단계 배너 → 누르면 홈. **홈에서는 띄우지 않는다** — 소식 목록이 이미 있다. 발표 되돌림은 `warn` 변형
- 자리 배너 → 누르면 내 정보 탭
- **자리 이동 확인**은 전체 화면을 덮는다. 단, **발표가 끝났으면 띄우지 않는다**

**참가자 탭**

- 카드 높이 **74px 고정**. 매력은 한 줄 말줄임 — 문장형 입력이 들어와도 카드 높이가 흔들리면 안 된다
- 이름 줄과 매력 줄 사이를 붙이지 마라. MBTI 배지와 매력 칩의 **테두리가 맞닿아 겹쳐 보인다**.
  두 줄이 22+22px 이라 74px 안에 여유가 있다
- 프로필 시트에서는 매력 **전문**을 보여준다
- 필터는 **`전체` 가 왼쪽**이다. 기본값이 전체라(ADR-17) 켜져 있는 쪽이 먼저 읽혀야 한다.
  **인원 수를 붙이지 마라** — 이 버튼이 답하는 건 "누구를 볼까" 하나다
- `이성만 보기` 토글은 **전체 폭**이다. 옆에 글자를 붙이면 알약 컨테이너와 맨 글자가
  한 줄에서 서로 다른 층위로 읽히고, 늘어난 토글과 오른쪽 글자 사이에 빈 공간이 남는다
- **남은 콕은 내 카드 오른쪽 칸에 있다** (`.mineCell`). 남들 줄에서 그 칸은 👉 로 콕을 **쓰는** 자리고,
  내 줄에서는 **얼마나 남았는지**를 말한다 — 같은 세로줄이 같은 것(내 콕)을 이야기한다.
  `.pokeCell` 과 **같은 폭(62px)** 이라야 카드 오른쪽 끝이 맞는다. 폭이 다르면 목록이 들쭉날쭉해 보인다
- 목록 머리에는 아래 사람들에 대한 안내만 남는다. 볼 사람이 없으면 그 줄도 없다
- 👉 버튼 = 콕 확인 다이얼로그 (`POKE.confirm`). **카드와 같은 키·같은 모서리**다 —
  44px 알약이던 시절엔 74px 카드 옆에서 혼자 작고 동그래서 짝이 안 맞았다.
  찌른 횟수는 **버튼 안**에 있다 (밖에 두면 폭이 흔들리지 않게 자리를 늘 비워둬야 했다).
  찌른 뒤에는 `--heart → --accent-solid` 로 흐른다 — 보낸 마음이 매칭으로 향하는 방향이다
  (순위 바 `--meter` 와 같다). **`.btn` 이 아니므로 `:disabled` 를 따로 준다**

**내 카드 — 목록 맨 위** (ADR-31 후기)

답하는 질문은 하나다: **내가 남들에게 어떻게 보이나.** 내가 낸 것 전부는 내 정보 탭에 있다.

- **`toPublic()` 을 그대로 쓴다.** 화면에서 규칙을 다시 짜면 갈라지고, 하필 "이렇게 보여요" 라고
  말하는 자리라 갈라지는 순간 거짓말이 된다. **서버 응답은 바뀌지 않는다**
- **단계를 그대로 넘기지 마라.** `toPublic` 은 `prevote` 에서만 나이·MBTI 를 뺀다 —
  등록 중에 그대로 부르면 나이가 나오는데 정작 사전 투표에서는 안 보인다.
  **남들이 나를 처음 보게 되는 상태**로 바꿔서 부른다
- **`이성만 보기` 에서 빠지지 않는다.** 필터를 바꿨는데 내가 사라지면 버그로 읽힌다
- **콕 버튼이 없다.** 비활성이 아니라 아예 없다
- "나" 는 **글자로** 말하고 **아바타 위에** 얹는다 (`.avatarMine`). 이름 줄은 닉네임·나이·MBTI 로
  이미 꽉 차 있다. **동물을 "나" 로 바꾸지 마라** — 이 카드는 남들이 보는 모습이고 남들은 내 동물을 본다.
  지우면 내가 어느 동물인지 끝내 모르는데, 파티장에서 사람을 찾는 게 그 동물이다 (ADR-30).
  **매칭 색(`--accent`)도 쓰지 마라** — 목록에서 가장 눈에 띄어야 하는 건 서로 찌른 사람이다
- 카드 아래에는 아무 말도 붙이지 않는다. "나" 태그와 맨 위라는 자리가 이미 말한다 —
  아직 안 열린 항목에 대한 안내는 **목록 머리 줄**이 맡는다 (`PEOPLE.agesAtParty`).
  **문구의 주어는 자리가 정한다**: 목록 위에 있으면 아래 사람들 이야기라 "볼 수 있어요" 이고,
  내 카드 밑이면 반대 방향이라 "남들에게" 를 박아야 한다. 자리를 옮기면 문장도 함께 본다
- **등록 중에도 보인다.** 남의 명단은 사전 투표부터지만(ADR-21) 내 카드는 내 정보라 그 규칙과 무관하고,
  고칠 수 있는 유일한 시간이 그때다. `PEOPLE.notOpenYet` 은 **남들에 대한 말**이라 그대로 둔다

**소식 (홈 안)**

- `ev.fired` 에서 파생한다. 읽음 상태를 저장하지 않는다 (ADR-4)
- 익명 콕이 쌓이면 정보량 0인 카드가 반복된다 — 카운터로 합칠 것

**내 정보 탭**

- 실명·전화번호는 기본 가림. 파티장에서 어깨너머로 보인다
- **등록할 때 낸 것은 등록 중에만 고칠 수 있다** (ADR-31). 명단이 열리는 시점과 같다
- **고치기는 하나뿐이다.** 누르면 기본 정보와 매력이 **함께** 폼이 되고 저장도 한 번이다 —
  매력만 따로 고치는 버튼을 두지 마라. 참가자가 하는 일은 하나고 잠기는 순간도 하나다
- **전화번호는 편집 모드에서도 칸이 아니다** (ADR-15). 값은 보이되 왜 못 바꾸는지 한 줄이 붙는다
- 잠긴 뒤에는 버튼을 없애고 그 자리에 `ME.locked` 를 둔다 — 버튼만 사라지면
  "내 화면만 이상한가" 가 된다. **늦게 등록한 사람은 처음부터 이 문구만 본다**
- 닉네임이 겹치면 그 칸에 알리고 **입력값은 지우지 않는다.** 저장은 전부 되거나 전부 안 된다
- 발표 후에도 결과는 여기 없다. 매칭·연락처는 전부 참가자 탭에 있다 (ADR-18·19)

### 운영자 콘솔 `/host/:id`

4탭: **현황 / 참가자 / 자리 / 설정** (`TABS_HOST`)

헤더에 `회차 목록` 버튼이 있다. 회차 하나에 갇히지 않는다 — 파티가 여러 개면 오가는 게 기본 동작이다.
회차 이름 아래에 코드 · 단계 · 등록 인원.

**현황** — 단계 컨트롤이 맨 위. 각 전환은 `phaseAction()` 의 항목을 보여주는 확인창을 거친다.
예약이 있는 전환(등록 시작·사전 투표 시작)은 `schedDiff()` 한 줄이 자동으로 붙는다.

그 아래는 셋이다 (ADR-30): 👑 사전 투표 1위(왕관 카드, 금색) · 💘 상호 매칭 쌍(하트 색 카드) ·
🔥 받은 콕 TOP 5(동점이면 그만큼 확장 · 공동 순위 같은 번호 · 0회 제외 ·
하트→주 색 그라데이션 바 · 3위까지 금색 번호).
자리 이동 확인율은 여기 없다 — 자리를 보낸 직후에 보는 숫자라 자리 탭 라운드 카드에 있다.

**받은 콕 순위는 여기에만 있다.** 참가자 탭의 개인 행에는 넣지 않는다 —
명단은 한 사람씩 훑는 자리고, 현황은 전체 분위기를 읽는 자리다.
**공동 1위는 함께 보여준다** — 한 명만 집으면 나머지가 조용히 가려진다.

일부러 두지 않은 것 —
- **성비** · **등록 명단** — 참가자 탭에 있다. 같은 숫자를 두 곳에 두면 어느 쪽이 맞는지 눈이 한 번 더 확인한다
- **아직 콕을 못 받은 사람** — 알면 그 사람을 다르게 대하게 된다. 이 앱이 없애려던 경험이다
- **콕 총 횟수** · **참여율** — 운영 판단에 쓰이지 않는다.
  화면에 있는 숫자는 전부 누를 이유가 있어야 한다

**참가자** — 맨 위가 **입장 명단**이다 (ADR-15). 비어 있으면 아무도 못 들어오므로 그때 가장 크게 말한다.
명단 편집은 시트에서 **더하기와 빼기만** 한다. 한 명씩 넣는 칸과 여러 명 붙여넣는 칸이 함께 있고,
붙여넣기도 있는 명단에 **더한다** — 통째로 갈아치우는 길은 두지 않는다 (ADR-15).

그 아래 전체 / 남성 / 여성 필터와 등록한 사람 목록. 셋 중 하나가 항상 켜져 있고,
**각 버튼에 인원 수가 함께 붙는다** — 고른 쪽만 세면 성비를 보려고 버튼을 두 번 눌러야 한다.
현황 탭에서 뺀 성비가 실제로 필요한 자리가 여기다.
목록 → 상세 시트. **삭제는 상세에서만**, `DELETE_PLAYER` 로 사라지는 데이터를 숫자로.

**받은 콕은 어디에도 보여주지 않는다** (ADR-22) — 목록에도, 상세에도, 삭제 확인창의 숫자에도.
보낸 콕만 남긴다. "누가 아직 아무도 안 찔렀나" 는 말을 걸어볼 신호다.

**자리** — **자리 재배정**(→ 시트에서 테이블 수) → 검토(맞교환·**자리 섞기**) → **자리 확정하고 알리기**.
확정해도 배정은 닫히지 않는다 (ADR-28). 발표만이 자리를 끝낸다.
상세는 `SEATING.md`. 확정 전 자리는 참가자에게 렌더링하지 않는다.

문구는 운영자가 하는 일 그대로 쓴다 — '초안'은 우리 말이지 운영자 말이 아니다.
`자리 확정하고 알리기` 는 그 버튼이 하는 **두 가지 일**을 순서대로 적은 것이다.

좌석 칩에는 닉네임 아래 **실명 · 나이 · MBTI** 가 붙는다. 자리에서 사람을 찾으려면 실명이 필요하다
(운영자만 전체를 본다).

**커플 자리(`💘 커플 자리 배정`)는 화면이 다르다** (ADR-23) —
성적표 한 줄(`8쌍 중 7쌍`), 떨어진 쌍의 이름, 같은 테이블에서 이어진 사람에게 붙는 💘,
쌍을 깨는 맞교환에 붙는 확인. 확정 확인창은 배정이 닫힌다는 사실과 되돌리는 방법을 함께 말한다.
참가자에게는 이 라운드가 특별하다고 **말하지 않는다** — 누가 나를 찔렀는지 짐작하게 된다.

테이블마다 `남 3 / 여 3` 을 적고, 좌석 칩을 성별로 칠한다(`--male` / `--female`) —
어두운 파티장에서 성비가 깨진 테이블을 색으로 먼저 찾는다.
**색만으로 구분하지 않는다**: ♂/♀ 기호와 숫자가 같은 정보를 함께 준다.
고른 칩의 보라 테두리가 성별 색보다 세다 — 지금 하는 일이 맞교환이라서.
**남녀도 맞바꿀 수 있다** (ADR-16). 바뀐 성비는 그 숫자에 바로 보인다.

**설정** — 저장은 **확인을 거친다** (ADR-22). 바뀐 항목만 `이전 → 이후` 로 보여준다.
입장 코드는 글자로만 보이고 바꿀 수 없다. 콕 상한은 이미 쓴 횟수 아래로 내려가지 않는다.

**설정** — 이름·PIN·코드·콕 횟수·일정·파기 대기 일수. **지나온 일정 항목은 잠근다** (`schedLocked`).
순서가 역전되는 값은 저장을 거부한다.
파기 대기 일수(1~14)는 회차마다 정한다 — 등록 화면의 "N일 뒤에 지워져요"가 이 값을 읽는다.
참가자가 이미 있으면 줄이는 변경은 등록 때 한 약속과 어긋난다고 그 자리에서 말해준다.

### 회차 위저드 `/host/new/1..3`

| 스텝 | 입력 | 검증 |
|---|---|---|
| 1 기본 정보 | 이름 · 입장 코드 | 코드 중복 불가 (비우면 자동) |
| 2 일정 | **파티 일시** · 등록 시작(`지금 바로` 토글) · 사전 투표 시작 | 사전 투표 시작 > 등록 시작 · 30분 단위 |
| 3 규칙 | 사전 콕 1~5 · 파티 콕 1~10 | 예상 매칭 안내를 함께 표시 |

### 회차 기본 설정 `/host/defaults`

콕 횟수 둘 · 일정 오프셋 둘. **운영자 PIN 칸은 없다** — 배포 시크릿 `MASTER_PIN` 하나가 유일한 출처다.
저장된 옛 모양은 읽을 때 지금 모양으로 맞춘다. 없는 항목이 그대로 올라오면 숫자 칸이 NaN 이 된다.

**파티 일시가 먼저다.** 나머지 두 시각은 거기서 거꾸로 계산된다 —
등록은 `regOpenBeforeD`(기본 6)일 전, 사전 투표는 `prevoteBeforeH`(기본 24)시간 전.

```
파티 일시를 옮기면  → 아직 손대지 않은 값만 따라 움직인다
직접 고친 값은      → 그대로 둔다. 고쳐놓은 걸 되돌리는 건 사고다
```

**예약하는 건 이 둘뿐이다.** 사전 투표 마감·파티 시작·발표는 현황 탭에서 운영자가 누른다 (ADR-14).
설정 화면에서 그 칸을 찾지 않도록, 일정 섹션 아래에 없는 이유를 적어둔다.

**콕 횟수 선택에는 예상 매칭을 함께 보여준다.** 기대 상호 매칭 쌍 수는 파티 규모와 무관하게
`k²` 에 수렴한다 (`pokeEstimate`, `pokeEstimateLabel`).

### 참가자 `/e/:code/people`

명단은 **단계마다 열리는 만큼만** 보인다 (ADR-21).

| 단계 | 보이는 것 |
|---|---|
| 등록 중 | 명단 없음 — 왜 비었는지 그 자리에서 말한다 |
| 사전 투표 | 닉네임 · 매력 |
| 파티 시작 후 | + 나이 · MBTI |

카드는 없는 항목을 빼고 그린다. `닉네임 · 28세 · ENFP` 가 사전 투표에서는 `닉네임` 하나다.

### 오늘 `/e/:code/fortune` — 파티 시작 후에만, 탭 **맨 오른쪽**

- 파티가 시작돼야 **탭 자체가 생긴다**. 그 전에 빈 탭을 보여줄 이유가 없다
- 끝에 붙인다 — 도중에 끼어들면 있던 탭들이 밀려서 손가락이 기억한 자리가 어긋난다
- 오늘의 기운은 **세 문단**(오늘의 결 · 잘 통할 흐름 · 조심할 것), 그 아래 **오늘의 미션** 한 줄
- 그 아래 **오늘의 어필**이 별도 카드로 선다. 운세가 "오늘 나는 어떤 결인가" 라면
  이건 **"그래서 뭘 어떻게 보여주나"** 다 — 매력 3가지에 팁 하나씩.
  한 카드에 이어 붙이지 마라. 읽을 것이 너무 길어지고 둘의 성격이 형태로 갈리지 않는다.
  **운세 카드의 `--tone` 을 쓰지 마라** — 그 색은 "오늘의 색" 이라는 뜻을 이미 지고 있다.
  팁에 번호를 붙이지 마라. 순서나 등급으로 읽히는데 셋은 우열이 없다
- 옛 저장본에는 어필이 없다. 그때는 그 카드가 통째로 없다 — 화면이 조건부로 그린다
- 열기 전에는 카드 뒷면. 탭하면 뒤집히며 열린다 — 여는 동작이 있어야 그 한 줄이 오늘 것처럼 읽힌다.
  그 0.6초가 LLM 을 기다리는 시간을 자연스럽게 덮는다
- **한 번 열면 그대로 남는다.** 다시 열어도 같다는 걸 화면에서 미리 말한다
- **점수를 보여주지 않는다** (ADR-20)
- 카드 색은 `--tone` 하나로 갈린다. 테마 토큰에서만 골라서 어떤 결과에도 화면이 깨지지 않는다
- 미션 칸도 그 색으로 한 겹 띄운다 — 읽고 끝나는 게 아니라 **하는 것**이라서
- `prefers-reduced-motion` 이면 돌지 않고 그대로 나온다

## 시트와 확인창

동작은 Radix Dialog 에서 빌려 쓰고 **모양은 우리 CSS 변수 그대로**다 (`src/client/ui/Sheet.tsx`).
손으로 만들었을 때 없던 것: 포커스 트랩·포커스 복원·**스크롤 잠금**·Escape·배경 비활성화.

- 재본 값: gzip **12KB**. 같은 자리를 antd 로 채우면 215KB 였다
- **히스토리는 여전히 우리가 쥔다.** 뒤로 가기로 닫히고 실행 **전에** 히스토리를 정리하는 규칙은
  라이브러리가 모른다 — 열림 상태를 밖에서 주고 닫힘 요청만 받는다
- Escape 는 **취소와 같다.** 닫히기만 하고 행동은 실행되지 않는다

## 모바일 체크리스트

- `<meta name="viewport" ... viewport-fit=cover, interactive-widget=resizes-content>`
- 높이는 `100dvh` — iOS 주소창 때문에 `100vh` 는 어긋난다
- **아래에 붙는 것은 `--kb` 만큼 띄운다** — 시트·확인창·화면 높이·토스트.
  `position: fixed; bottom: 0` 은 **레이아웃 뷰포트** 기준이라 키보드가 떠도 안 움직인다.
  안드로이드는 위 메타가 레이아웃을 줄여 알아서 따라오지만 **iOS 사파리는 그 속성을 모른다** —
  거기서는 `lib/keyboard.ts` 가 시각 뷰포트로 잰 `--kb` 가 유일한 단서다.
  입력칸만 보이게 사파리가 스크롤해줘도 **눌러야 할 버튼은 여전히 안 보인다**
- 하단 탭바에 `padding-bottom: env(safe-area-inset-bottom)`
- 터치 타겟 최소 **44×44px**
- 입력 폰트 **16px 이상** — 미만이면 iOS 가 자동 확대한다
- 색·간격·모서리는 **CSS 변수로만**. 하드코딩 금지 (테마 교체의 토대)

## 테마

지금 테마는 **Airbnb 의 형태 언어를 밤으로 옮기고, 주 색만 우리 것으로** 바꾼 것이다.

| | |
|---|---|
| 주 색 | **자정 보라** — 글씨·테두리 `#9B7CFF` / 채운 버튼 `#6D48E5` |
| 의미색 | Babu `#00A699` 좋은 상태 · Arches `#FC642D` 주의 (Airbnb 그대로) |
| 형태 | 카드 16px · 버튼 8px · 필터는 알약 · 테두리보다 **그림자로 띄운다** |
| 바탕 | 순수 검정을 피한다. 파티장 조명 아래서 검정은 화면이 꺼진 것처럼 보인다 |

**주 색을 Airbnb 의 Rausch(자홍)로 두지 않은 이유**

- Rausch 는 예약 버튼의 색이다. 여기 버튼은 조심스럽게 누르는 콕이라 결이 다르다
- 소개팅 앱의 분홍·빨강은 가장 예상 가능한 선택이라 기억에 남지 않는다
- 앰버(파티)·청록(발표)과 색상환에서 가장 멀어 **단계 구분이 제일 또렷하다**

이 색은 버튼만이 아니라 **사전 투표 단계의 색**이다. 콕을 찌르는 시간의 색이라
경고처럼 튀지 않으면서 온기는 있어야 한다.

**밝은 쪽과 짙은 쪽을 나눠 쓴다.** 어두운 바탕 위의 글씨·테두리는 밝은 쪽(대비 5.9:1),
흰 글씨를 얹는 버튼은 짙은 쪽(5.7:1). 어두운 파티장에서 읽어야 하는 화면이라
대비에서 타협하지 않는다.

테마를 통째로 바꾸면서 **컴포넌트는 한 줄도 건드리지 않았다.** 색을 변수로만 쓰기로 한 규칙이
값을 한 자리에 모아둔 덕이다. 다음 테마도 같은 방식으로 갈아끼운다.
