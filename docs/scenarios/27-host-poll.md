# 슬라이스 27 — 설문

운영자가 파티 중 언제든 **두 선택지 설문**을 보내고, **누가 무엇을 골랐는지** 본다.
첫 쓰임은 뒤풀이 수요조사다 — 몇 명이 아니라 **누가** 간다고 했는지 알아야 자리를 잡는다.

서버는 슬라이스 14 가 이미 만들었다 (`Announcement` · `/api/vote`). 이 슬라이스는 그 계약을 셋 고치고
화면을 붙인다. 고친 셋은 ADR-88 에 있다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 슬라이스 14 에서 바뀐 것

| | 14 | 27 |
|---|---|---|
| 운영자가 보는 것 | 숫자 둘 | **누가 무엇을 골랐는지** (`HostAnnouncement.choices`) |
| 참가자가 보는 것 | 숫자 둘 + 내 답 | **내 답만.** 숫자 없음 |
| 열린 설문 | 한 번에 하나 | **여러 개.** 닫는 건 운영자 |
| 화면 | 현황 탭 | **설문 탭** — 자리 탭 옆 |
| 이름 | 투표 | **설문** — `투표` 는 매력 투표가 쓰는 말이다 |

**첫 규칙은 그대로다 — 선택지에 사람을 넣지 않는다.** 이제 운영자가 누가 골랐는지까지 보므로
`축구 vs 디디` 는 전보다 더 나쁘다. 선택지를 참가자 목록에서 고르는 길은 여전히 없고,
보내기 시트가 한 줄로 말한다: *참가자 이름을 고르게 하는 설문은 만들지 마세요.*

## 범위

**만든다**

| | |
|---|---|
| 설문 탭 `/host/:id/polls` | 새 설문 버튼 + 설문 카드 목록(질문 · 진행 중/마감 · 답 둘과 미응답의 수) |
| 보내기 시트 `/polls/new` | 질문 한 칸 + 선택지 두 칸. 셋 다 차야 보낼 수 있다 |
| 상세 `/polls/:aid` | 칩 셋(선택지 1 · 선택지 2 · 미응답)으로 걸러진 **참가자 카드** — 실명 · 닉네임 · 나이, 그 아래 **전화·인스타**. 마감/다시 열기 · 지우기 |
| 참가자 홈 설문 카드 | 선택지 둘이 버튼. 고르면 눌린 채로 남고, 마감되면 내 답만 남는다 |
| 배너 | 새 설문이 3분 안이면 배너. **버튼은 없다** — 누르면 홈으로 |

**안 만든다**

- **참가자 화면의 숫자.** 몇 명이 골랐는지는 운영자가 정하려고 묻는 것이다
- **텍스트 알림 화면.** 서버는 있지만(슬라이스 14) 이번엔 설문만이다
- 선택지 3개 이상 · 개인에게 보내기 · 읽음 표시 · 예약 발송 (슬라이스 14 와 같다)
- 단계 제한. 등록 중이든 발표 뒤든 보낼 수 있다 — 뒤풀이는 발표 뒤에 묻는다

## A. 운영자

### S-A1 ★ 누가 무엇을 골랐는지 본다
```
Given  A 가 '갈래요', B 가 '못 가요' 를 골랐다
Then   운영자 응답의 choices 가 { A: a, B: b } 다
```
> 카드를 누르면 칩으로 걸러진 참가자 카드가 나온다 — 참가자 탭과 같은 카드, 실명이 앞이고 전화·인스타가 바로 보인다.
> 뒤풀이 자리를 잡고 나면 이 목록을 보며 연락한다. 운영자 화면이라 된다 (원칙 3).

### S-A2 ★ 설문 여러 개가 함께 열려 있다
```
Given  설문 하나가 열려 있다
When   새 설문을 보낸다
Then   둘 다 열려 있고, 앞엣것에도 답할 수 있다
```

### S-A3 ★ 지우기 확인창이 받은 답의 수를 말한다
> 되돌릴 수 없는 일이다. 마감·다시 열기는 되돌릴 수 있어 확인창이 없다.

### S-A4 나간 사람의 답은 세지 않는다
> 명단에 없는 아이디가 빈 카드로 서면 안 된다.

## B. 참가자

### S-B1 ★ 남의 답도 숫자도 없다
```
Then   참가자 응답의 설문에는 선택지 둘 · 내 답 · 마감 여부뿐이다. 남의 아이디도 count 도 없다
```

### S-B2 ★ 고르면 눌린 채로 남는다. 다시 고르면 옮겨간다
### S-B3 ★ 마감되면 버튼이 사라지고 내 답만 남는다
