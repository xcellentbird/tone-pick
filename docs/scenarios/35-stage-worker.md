# 슬라이스 35 — 스테이지 워커: 컴퓨터 없이 온라인에서 스테이지를 만든다

스테이지(`scripts/qa/stage.mjs`)는 컴퓨터에서 도는 도구다. 폰 리모컨(`--remote`)은 같은 Wi-Fi 안에서만 열리고,
창 벽(`--watch`)은 그 컴퓨터의 Chromium 이다. **폰만 들고**, 또는 다른 사람이 어디서든 스테이지를 만들려면
컴퓨터 없이 도는 자리가 필요하다 — 스테이지의 핵심을 **따로 선 워커**로도 돌린다 (ADR-97).

앱 안에는 넣지 않는다 (ADR-7 후기). QA 워커는 main 과 같은 바이너리 그대로다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 왜 바깥 워커인가 — 그리고 왜 브랜치는 그대로인가

세 길을 견줬다 (ADR-97 에 표가 있다).

- **터널** (`cloudflared tunnel --url http://localhost:7000`) — 코드 0줄이지만 노트북이 켜져 있어야 한다
- **QA 워커 안에 var 로 켜기** — 도구가 `SESSION_SECRET` 과 DO 를 직접 잡아 아무 참가자나 될 수 있고,
  그 길이 프로덕션 바이너리에 실린 채 설정값 하나가 막는 모양이 된다. 이 앱의 방어는 감추기가 아니라
  **자리를 없애기**다
- **바깥 워커** — 공개 API 와 PIN 이 한계라, 아무리 잘못돼도 사람 손으로 할 수 있는 것 이상을 못 한다.
  **이걸 고른다**

브랜치는 가르지 않는다. 같은 저장소, 같은 흐름(feature → `qa` → `main`)이고, **배포 대상 하나**
(`tone-pick-qa-tool`, `qa` 에서)만 는다. 도구 코드는 `main` 까지 가되 배포하는 곳이 없을 뿐이다.

## 범위

**만든다**

| | |
|---|---|
| 핵심 나누기 | `scripts/qa/core.mjs` — 가짜 참가자 만들기 · 명령(`run`) · 리모컨 페이지. `fetch` 만 쓴다. CLI 와 워커가 **같은 파일**을 쓴다 |
| 워커 | `scripts/qa/worker/` — 자기 `wrangler.jsonc`, 라우터, 스테이지 하나 = DO 하나 |
| 표적 | 서비스 바인딩 `APP → tone-pick-qa`. **주소를 받는 입력이 없다** |
| 문 | **로그인은 없다** (ADR-97 후기 4). 한국 밖에서는 안 열리고(QA 와 같은 국가 문), QA 를 부르는 횟수에 하루 상한이 있다 (슬라이스 37) |
| 리모컨 | ~~CLI 의 페이지 그대로 + 참가자마다 여는 링크 · 번호 · PIN~~ → **한 탭 스테이지 화면** (슬라이스 37) |
| 배포 | Workers Builds 프로젝트 `tone-pick-qa-tool`, 프로덕션 브랜치 `qa`. **Deploy command** `npx wrangler deploy -c scripts/qa/worker/wrangler.jsonc`, **Build command 는 비운다** (둘 다 적으면 배포가 두 번 돈다) |

**안 만든다**

- **창 벽(`--watch`)·`snap`.** (→ 창 벽은 **슬라이스 37 이 한 탭의 틀로** 했다. `snap` 은 여전히 없다) 워커엔 브라우저가 없다. 온라인에서는 **폰이 곧 창**이고, 세션이 탭마다
  갈리므로(ADR-44) 폰 하나에서 탭마다 다른 참가자가 된다
- **시간 이동(`now`).** QA 에 원래 없다 — `schedule` 로 대신한다. 여럿이 쓰는 환경의 시계를 한 사람이
  옮기게 두지 않는다
- **프로덕션 표적.** 어떤 입력으로도. 표적은 설정 파일의 바인딩 하나다
- **로그인·PIN.** 처음엔 Access 가 문이었는데 걷었다 (ADR-97 후기 4). 자체 로그인은 시도 제한을 다시 만드는 일이라 안 만든다
- **앱 코드 변경.** `src/` 는 한 줄도 안 건드린다
- **`main` 쪽 배포.** 코드는 가지만 배포하는 곳이 없다
- **실제 번호.** 가짜 참가자의 번호는 전부 가짜다 — CLI 와 같은 씨앗

## A. 표적 — QA 뿐이다

### S-A1 ★ 바인딩을 지나도 국가 문이 열린다 — **먼저 확인할 것**
```
Given  워커가 서비스 바인딩으로 QA 워커의 `/api/health` 를 부른다
When   한국 밖에서(또는 어디서든) 그 워커를 연다
Then   200 — QA 의 `ALLOWED_COUNTRIES=KR` 문이 바인딩 요청을 막지 않는다
```
> 국가는 `cf.country` 로만 본다 (ADR-92). 바인딩으로 **새로 만든** `Request` 에는 `cf` 가 없어
> "모르는 나라는 통과" 로 들어간다고 **예상**하지만, 이 슬라이스의 첫 걸음은 그것을 **배포해서 재는 것**이다.
> 열 줄짜리 워커로 잰다 — 바인딩 하나, `/` 를 열면 `APP.fetch(new Request("https://app/api/health"))` 의
> 상태와 본문을 그대로 돌려준다. 막히면 그때 답은 헤더가 아니다 (CLAUDE.md) — 다시 설계한다.
> **결과를 ADR-97 의 후기로 적는다.**
>
> **잰 결과 (2026-09-24)** — 한국에서 두 길 다 `200`, `label: "QA"`. **한국 밖은 VPN 이 없어 재지 못했다** —
> 틀렸을 때 도구가 막힐 뿐 QA 가 열리지는 않는 쪽이라 열어 둔다. 해외에서 쓸 일이 생기면 그때 잰다 (ADR-97 후기).

### S-A2 ★ 표적을 고르는 입력이 없다
```
Given  워커의 어떤 라우트도
When   주소나 워커 이름을 넘기려 해도
Then   받는 자리가 없다 — 표적은 `wrangler.jsonc` 의 바인딩 하나다
```
> CLI 의 "라벨 없으면 거부" 는 사람 손이 도는 도구의 문이다. 공개된 워커에는 `delete` 가 있어
> 프로덕션 PIN 하나면 진짜 회차를 지운다. 구조로 막는다.
>
> ⚠️ **경로나 본문을 받아 QA 로 그대로 넘기는 라우트도 두지 마라** — 워커가 프록시가 된다.
> 바인딩 요청에는 `cf` 가 없어 그 라우트는 **QA 국가 문의 우회로**가 되고(ADR-97 후기), 하루 상한(S-B2)은
> 명령 한 줄 단위로 세므로 그 라우트로 가는 호출은 세지도 못한다. 로그인도 없으니 그 순간 이 워커의 문 하나가
> QA 의 `/api` 전체의 문이 된다. 워커가 QA 를 부르는 말은 `core.mjs` 의 명령이 정한 것뿐이다.

### S-A3 ★ 설정이 프로덕션을 가리키면 `npm run check` 가 빨개진다
```
Given  `scripts/qa/worker/wrangler.jsonc` 의 `services[APP].service` 가 `tone-pick-qa` 가 아니다
Then   `check-config` 가 멈춘다
```
> 앱의 `wrangler.jsonc` 검사와 같은 파일에 한 줄이다.

## B. 문

### S-B1 로그인은 없다
> 처음엔 Cloudflare Access 뒤에 세우고 워커가 Access 의 JWT 를 스스로 확인했는데, 대시보드에서 Access 를 켜고도
> 들어가지 못했다. 운영자가 로그인 없이 쓰기로 했다 (ADR-97 후기 4). **대시보드의 Access 도 끈다** — 켜 두면
> 워커와 상관없이 엣지가 로그인을 먼저 묻는다 (**Workers & Pages** → `tone-pick-qa-tool` → **Access** 탭).
>
> 로그인이 없어도 할 수 있는 일은 그대로다 — 표적은 QA 하나(S-A2), 명령은 공개 API 뿐(S-C4), 번호는 가짜뿐(S-C2).
> 대신 주소를 아는 사람은 누구나 스테이지를 만들고 닫을 수 있다. 로비가 그렇게 말한다.

### S-B2 ★ 스테이지 만들기와 명령에 하루 상한이 있다
> **→ 슬라이스 37 이 QA 를 부른 횟수로 다시 센다** (S-D1 · ADR-99). 아래는 처음 모양의 기록이다.
```
Given  오늘(00:00 UTC 부터) 스테이지를 20번 만들었다 — 또는 명령을 500번 쳤다
When   한 번 더 만든다 — 또는 친다
Then   거절한다. 몇 번까지인지와 오전 9시에 다시 된다는 것을 말한다 — 스테이지는 로비에, 명령은 로그에
And    로비가 남은 횟수를 보여 준다. 거절한 시도는 세지 않는다
```
> 무료 플랜의 하루 한도는 **계정 전체라 프로덕션과 같이 쓴다.** 바인딩으로 부른 QA 는 워커 요청으로 따로 세지
> 않지만, QA 를 부를 때마다 QA 의 DO 가 깬다 — 12명 스테이지 하나를 만들면 DO 요청이 60번쯤이다. 상한을 다 써도
> 하루 DO 요청 한도의 9% 가 끝이다 (잰 값과 셈은 `budget.ts`, ADR-97 후기 4).
> 하루는 **UTC** 로 끊는다 — Cloudflare 의 한도가 그때(한국 오전 9시) 다시 찬다. 세는 곳은 로비 DO 하나다.
> 막힌 명령은 로그에 말하되 **저장하지 않는다** — 넘긴 뒤에도 두드릴 때마다 줄을 쓰면 쓰기 한도가 상한 밖에서 닳는다.

### S-B3 한국 밖에서는 열리지 않는다
```
Given  나라가 `ALLOWED_COUNTRIES` 밖이다 (`cf.country`)
Then   403 — QA 와 같은 문구
```
> QA 의 국가 문(ADR-92)과 **같은 값, 같은 규칙**이다 — 헤더가 아니라 `cf.country` 로 보고, 모르는 나라(로컬)는
> 통과한다. 도구가 여는 참가 링크가 어차피 QA 로 가서 한국에서만 열리므로 잃는 것이 없고, 로그인이 없는 지금은
> 아무 데나 훑는 봇이 하루 상한을 먼저 써 버리는 것을 줄인다. 두 값이 다르면 `check-config` 가 빨개진다 —
> 끄려면 둘을 함께 비운다.

## C. 스테이지

### S-C1 ★ 가짜 참가자는 실제 경로로 등록한다
```
Given  스테이지를 새로 만든다 (인원 N, 단계, 회차 설정)
Then   명단에 넣고 → `/enter` → `/register` — 사람마다 세션 쿠키를 따로 든다
```
> CLI 와 스테이지 워커는 `core.mjs` 하나를 쓴다. **리허설(`rehearsal.mjs`)은 아직 자기 복사본이다** — 백 명을
> 나란히 등록하는 동시성과 잰 값의 출력이 그쪽 일이라 이번에 옮기지 않았다. 옮길 때 `enroll` 을 가져다 쓴다.

### S-C2 ★ 번호는 가짜뿐이다
> `010-0000-` 씨앗(CLI 와 같은 것)이고, 실제 번호가 들어갈 입력이 없다. QA 에도 실제 번호를 넣지 않는다.

### S-C3 ★ 끝내면 회차를 지운다
```
When   스테이지를 닫는다
Then   `DELETE /api/host/events/:id` — `keep` 을 골랐으면 남긴다. 스테이지 DO 도 함께 비운다
```
> 온라인 스테이지는 **12시간 손대지 않으면 저절로 닫힌다** (DO 알람, `IDLE_MS`). 닫기를 누르지 않고 폰을 덮는 일이
> 흔하고, 그러면 QA 에 가짜 회차가 쌓인다. 명령을 칠 때마다 시계가 다시 간다.

### S-C4 ★ 명령은 공개 API 뿐이다
> `poke 3 5` · `unpoke 3 5` · `phase party` · `voteend` · `seating 2` · `publish` · `shuffle` · `late` ·
> `schedule reveal +30s` · `lock 4` — CLI 의 `run()` 그대로다. `open` · `close` · `snap` · `now` 는
> "이 스테이지에서는 쓸 수 없어요" 로 답한다 — 조용히 무시하지 않는다.

### S-C5 스테이지는 하나가 아니다
> 스테이지 = DO 하나. 목록에서 고른다. 두 사람이 나란히 QA 를 해도 서로의 회차를 안 건드린다.

## D. 리모컨

> **온라인 스테이지의 화면은 슬라이스 37 이 바꿨다** — 한 탭에 틀 여럿 (ADR-99). 아래 S-D2 · S-D3 의 온라인 쪽은
> 처음 모양의 기록이고, `remotePage()` 는 다시 CLI 의 것만 남았다.

### S-D1 CLI 의 페이지 그대로
> 명령 칸, 자주 쓰는 명령 칩, 참가자 표, 로그. `core.mjs` 의 `remotePage()` 다.

### S-D2 ★ 참가자마다 여는 링크 · 번호 · PIN 이 있다
```
Given  참가자 표의 한 줄
When   폰에서 링크를 누른다
Then   QA 의 `/j/<회차id>` 가 열리고, 옆에 적힌 번호 · PIN 으로 그 참가자가 된다
```
> 탭마다 세션이 갈려(ADR-44) 폰 하나가 참가자 여럿이 된다. 창 벽의 자리를 이것이 맡는다.

### S-D3 로그는 최근 60줄
> CLI 와 같다. 다시 읽는 때만 다르다 — **CLI 는 1.5초마다 읽고, 온라인 스테이지는 스스로 읽지 않는다.**
> 온라인에서는 명령을 친 뒤, 탭으로 돌아왔을 때, `로그 다시 읽기` 를 눌렀을 때만 읽는다 (그때는 `remotePage({ poll })`,
> 지금은 스테이지 화면이 명령의 답으로만 받는다 — 슬라이스 37 S-A6).
> 한 번 읽을 때마다 DO 가 둘 깨는데, 켜 둔 탭이 1.5초마다 읽으면 하루에 한도를 혼자 넘는다 (ADR-97 후기 4).
> 온라인 스테이지의 로그는 리모컨의 명령만 쓰므로 이걸로 충분하다. CLI 는 터미널로 친 명령도 로그에 쓴다.

## E. 저장소 · 배포

### S-E1 같은 저장소, `scripts/qa/worker/`
> 앱의 `wrangler.jsonc` 에 셋째 환경으로 넣을 수 없다 — 환경은 `vars`·바인딩만 갈리고 `main`(진입 파일)은
> 못 갈아서, 다른 스크립트는 다른 설정 파일이어야 한다.

### S-E2 `qa` 에서 배포한다
> 도구의 표적이 QA 뿐이라 QA 와 함께 움직인다. `qa → main` 이 도구 커밋을 실어 가도 `main` 에서 그 폴더를
> 배포하는 곳이 없다.

### S-E3 `npm run check` 가 워커도 본다
> typecheck 에 든다. `check:copy` 는 `src/` 만 보므로 리모컨 문구는 CLI 처럼 걸리지 않는다. 번들 예산은
> 클라이언트 것이라 무관하다.

### S-E4 CHANGELOG 에 적지 않는다
> 프로덕션에 나가는 것만 적는다.

## 문구

리모컨은 도구라 `copy.ts` 밖이고 `check:copy` 가 안 본다 — CLI 와 같다. 다만 ADR-89 의 어체는 따른다.
`이 스테이지에서는 쓸 수 없어요` 처럼 **안 된다고 말하는 문장**을 두는 이유는 하나다 — 조용히 무시하면 명령을 잘못 친 줄 안다.
