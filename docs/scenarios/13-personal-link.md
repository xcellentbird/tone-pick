# 슬라이스 13 — 참가 링크는 사람마다 다르다

**번호를 아는 사람이 그 사람이 될 수 있었다** (ADR-15 후기 2). 전화번호는 식별자이지
증명이 아닌데, 하필 같은 파티에 오는 사람들은 서로 번호를 아는 사이다.

명단 한 줄마다 토큰을 발급하고 그 토큰을 신원으로 쓴다. **참가자는 번호를 치지 않는다.**
결정과 대가는 `ADR-32`. 15(참가자 비밀번호)는 이 슬라이스로 닫혔다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 범위

**만든다**

| | |
|---|---|
| 명단 한 줄마다 **고유 토큰** | 번호를 넣는 순간 조용히 생긴다 |
| `/j/<회차id>/<토큰>` 이 **곧 신원** | 번호 칸이 `등록하기` 버튼이 된다 |
| 운영자 **안내문 템플릿** | `{장소}` `{일시}` `{링크}` 를 치환한다 |
| 명단 **행마다 복사 + 보냄 체크** | 한 명씩 보내니 어디까지 갔는지 알아야 한다 |
| 회차에 **장소** | 안내문에만 쓰인다 |

**안 만든다**
- **토큰 재발급 화면.** 잃으면 운영자가 안내문을 다시 보낸다. 정 필요하면 명단에서 빼고 다시 넣는다
- **자동 발송.** 붙여넣기 사고가 그대로 새어나간다. 복사까지만 돕는다
- **참가자 화면의 장소.** 지금처럼 안내문으로만 알린다 — 요청 범위 밖이다
- 참가자 비밀번호(15). 택일에서 졌다

---

## A. 문

### S-A1 ★ 토큰이 없으면 열리지 않는다
```
When   /j/<회차id> 를 연다 (토큰 없이)
Then   들어가지 못한다
```
> 경로만 없애는 것으로는 모자라다 — **`/api/events/by-id/:id` 도 토큰을 요구한다.**
> 안 그러면 회차 아이디만으로 파티 이름·일정이 열린다 (ADR-15 후기의 `by-code` 오라클과 같은 종류).

### S-A2 ★ 토큰이 곧 그 사람이다
```
Given  명단에 A(010-1111) 와 B(010-2222) 가 있다
When   B 의 토큰으로 등록을 마친다
Then   저장된 번호는 010-2222 다
```

### S-A3 ★ 번호를 밀어넣어도 토큰이 이긴다
```
When   등록 API 에 phone 을 함께 보낸다
Then   무시된다 — 번호는 서버가 토큰에서 꺼낸다
```
> `RegisterInput` 에 phone 키를 두지 않는 것이 방어다 (ADR-31). 폼을 우회해 API 로 바로 쏘는 참가자가 있다.

### S-A4 ★ 실패 문구는 하나뿐이다
```
When   토큰이 없다 / 토큰이 틀렸다 / 그런 회차가 없다 / 파기됐다
Then   넷 다 같은 문구다
```
> 구분해 주면 그 구분이 곧 "이 사람이 이 파티에 있나"의 답이 된다.

### S-A5 ★ 명단에서 지워도 등록한 사람은 들어온다
```
Given  A 가 등록을 마쳤다
When   운영자가 명단에서 A 의 번호를 지운다
Then   A 는 자기 링크로 계속 들어온다
```
> 명단은 문이지 자격이 아니다 (ADR-15). 등록할 때 토큰을 `players` 행에도 복사해 둔다.

### S-A6 등록 전에 열면 언제 열리는지 말한다
```
Given  등록 시작 시각이 아직 안 됐다
When   참가자가 링크를 연다
Then   토큰은 통과하고, 화면이 언제 열리는지 알려준다
```
> 안내문은 등록 시작 **전에** 보낸다. 일찍 연 사람에게 말할 자리가 있어야 한다.

### S-A7 이미 등록한 사람은 곧바로 자기 화면으로
```
When   등록을 마친 사람이 링크를 다시 연다
Then   /e/<코드> 로 간다 (replace — 뒤로 가기로 돌아오지 않는다)
```

## B. 안내문

### S-B1 ★ 명단에 번호를 넣어도 아무것도 발송되지 않는다
```
When   운영자가 번호를 붙여넣는다
Then   그 줄에 토큰이 생긴다. 그리고 그뿐이다
```
> 붙여넣기 사고가 문자로 새어나가면 되돌릴 수 없다.

### S-B2 안내문은 행마다 복사한다
```
Given  템플릿과 장소가 채워져 있다
When   운영자가 한 행의 복사를 누른다
Then   그 사람의 링크가 들어간 안내문이 클립보드에 담긴다
```
> 미리보기가 버튼 곁에 있으니 확인창은 두지 않는다 — 되돌릴 수 있는 행동이다.

### S-B3 보냄은 체크로 남는다
```
When   운영자가 보냄을 체크한다
Then   남는다. 새로고침해도, 다른 기기에서도
```
> 37명을 한 명씩 보내는데 어디까지 갔는지 모르면 못 한다. 전체 1회 복사였다면 없어도 됐을 것이다.

### S-B4 템플릿은 운영자 기본값에 하나만 둔다
```
Given  {장소} {일시} {링크} 를 쓴 템플릿
Then   회차마다 다시 쓰지 않는다 — 회차가 다른 값을 채운다
```
> 기본 문구는 `copy.ts`. 회차별 덮어쓰기는 만들지 않는다.

### S-B5 링크 하나를 통째로 복사하는 버튼은 없다
```
Then   참가자 탭의 옛 "참가 링크 복사" 는 사라진다
```
> 남겨두면 단톡방에 뿌리는 길이 그대로 남는다.

---

## C. 장소

### S-C1 회차 마법사 2단계에서 받는다
> "언제·어디서" 가 한 화면에 있다. 1단계는 이름만 받아 가볍게 시작하는 지금 구조를 지킨다.

### S-C2 ★ 참가자 응답에 장소가 없다
> 안내문으로만 나간다. 넣고 싶어지면 그건 범위를 넓히는 것이다.

---

## 무엇이 안 바뀌나

- `/e/<코드>` 아래 참가자 화면 전부
- 입장 시도 횟수 제한 (`ENTRY_TRIES`) — 문은 여전히 인증 없이 열려 있다.
  다만 **그것이 막던 "번호 넣어보기" 는 이제 일어나지 않는다.** 넣어볼 칸이 없다
- 명단 편집 — 더하기와 빼기만. 통째로 갈아치우는 길은 여전히 없다
- 입장 코드 여섯 자리 — 회차를 가리키는 이름일 뿐이다

## 남는 구멍

**링크를 본 사람은 그 사람이 될 수 있다.** 지인 파티에서 그건 대체로 친구다 —
링크가 카톡에 남아 있고, 폰을 보면 보인다. 알고 고른 대가다 (ADR-32).

가장 비싼 유출(연락처)은 발표 후에만 열리므로, 발표를 현장에서 누르는 운영이 완화책으로 남는다.
**사고가 한 번 나면 15(비밀번호)를 다시 연다.**
