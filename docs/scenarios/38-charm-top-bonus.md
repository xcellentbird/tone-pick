# 슬라이스 38 — 매력 투표 1위 보너스 콕 · 매력 투표는 파티 시작에 닫힌다

운영자가 회차 설정에서 켜면, **매력 투표에서 가장 많은 표를 받은 사람**이 파티에서 콕을 **한 번 더** 찌를 수 있다 (ADR-100).
그리고 매력 투표는 **자리 배정에 들어가지 않는다** — 그래서 마감 시각을 따로 둘 이유가 없어져,
매력 투표는 **파티가 시작될 때 닫힌다.**

`★` 는 반드시 테스트를 붙이는 것.

---

## 왜 되는가

- **1위는 본인만 안다.** 표 수도, 순위도 나가지 않는다. 다른 참가자에게는 아무것도 달라지지 않는다 —
  명단에도 프로필에도 표시가 없다 (`toPublic()` 그대로)
- **매력 투표는 원래 파티 시작에 닫혔다** (ADR-34). 마감 시각(ADR-39)은 자리를 짤 시간을 벌려고 붙인 것이고,
  표가 자리에 들어가지 않으면 그 시간이 필요 없다

## 범위

**만든다**

| | |
|---|---|
| 회차 설정 | `매력 투표 1위 보너스 콕` — `안 줌` / `1회`. 기본은 `안 줌`. 설정 탭 · 위저드 3스텝 · 회차 기본 설정 |
| 1위 정하기 | **파티가 시작되는 순간 한 번.** 성별마다 받은 표가 가장 많은 사람. 공동 1위는 모두. 가장 많은 표가 **2표 이상**일 때만 |
| 보너스 | 1위의 파티 콕 한도가 `maxParty + 1` |
| 1위 본인 화면 | 홈 소식 한 줄. 남은 콕이 한도째 늘어 보인다 |
| 운영자 화면 | 현황 탭 `✨ 매력 투표 TOP 5` — 파티 전 안내 한 줄, 파티 뒤 1위 옆 칩. 파티 시작 확인창에 누가 받는지 |
| 마감 | 매력 투표는 **파티 시작에 닫힌다.** 마감 시각 칸 · `매력 투표 마감` 버튼 · 마감 소식을 걷는다 |
| 자리 배정 | 매력 투표 표를 **보지 않는다** |

**안 만든다**

- **표 수 · 순위 공개.** 1위에게도 몇 표인지는 말하지 않는다. 그 숫자가 곧 *몇 명이 나를 골랐나* 다
- **다른 참가자에게 알리기.** 도움말에도 적지 않는다 — 매력 투표를 공개된 인기 경쟁으로 만들지 않는다.
  운영자가 진행 멘트로 말하는 건 운영자의 몫이다
- **왕관 · 배지.** 어깨 너머로 보이면 인기 표시가 된다
- **2위 이하에게 넘기기.** 1위가 파티 중에 빠져도 다른 사람이 이어받지 않는다
- **여러 회.** 보너스는 한 번뿐이다

## 시나리오

### A. 1위 정하기

#### S-A1 ★ 성별마다 가장 많은 표를 받은 사람
```
Given  보너스를 켠 회차 · 매력 투표에서 남 A 가 3표, 남 B 가 2표, 여 C 가 2표, 여 D 가 1표를 받았다
When   파티가 시작된다
Then   A 와 C 의 파티 콕 한도가 maxParty + 1 이다
And    B 와 D 는 maxParty 그대로다
```

#### S-A2 ★ 공동 1위는 모두 받는다
```
Given  여 C 와 여 E 가 같은 2표로 가장 많다
Then   둘 다 한도 +1
```

#### S-A3 ★ 가장 많은 표가 1표뿐이면 아무도 받지 않는다
> 작은 회차에서는 1표 받은 여러 명이 모두 "1위" 가 되어 보너스의 뜻이 없어진다.

#### S-A4 ★ 파티가 시작되는 순간 정해지고 바뀌지 않는다
```
Given  파티가 시작돼 A 가 1위로 정해졌다
When   운영자가 A 를 내보낸다
Then   다른 사람이 이어받지 않는다 — 남은 사람의 한도는 그대로다
```
> 매 요청마다 다시 세면 1위가 빠진 순간 2위의 한도가 파티 중에 조용히 늘어난다.
> 매력 투표를 건너뛰고 파티로 간 회차에는 1위가 없다.

#### S-A5 ★ 보너스를 끈 회차에서는 아무도 받지 않는다

#### S-A6 ★ 예약으로 열린 파티도 같다
> 파티는 운영자가 누르지 않아도 `partyAt` 이 연다 (ADR-93). 두 길이 같은 1위를 정한다.

### B. 보이는 것

#### S-B1 ★ 다른 참가자의 응답에는 아무 흔적이 없다
```
When   1위가 아닌 참가자가 자기 상태를 읽는다
Then   회차 정보에도, 명단에도 1위가 누구인지 없다
And    자기 파티 콕 한도는 maxParty 그대로다
```

#### S-B2 ★ 1위 본인에게는 표 수가 가지 않는다
```
When   1위가 자기 상태를 읽는다
Then   파티 콕 한도가 maxParty + 1 이고, 1위라는 표시 하나가 있다
And    받은 매력 투표 수는 매력 투표 알림(preNotify)을 끈 회차라면 여전히 0 이다
```
> 1위에게 알리는 것은 알림을 끈 회차에서도 된다 — 운영자가 보너스를 켠 것이 곧 그 선택이다 (ADR-100).
> 대신 **숫자는 끝까지 나가지 않는다.**

#### S-B3 1위의 홈 소식에 한 줄
```
매력 투표에서 가장 많은 표를 받았어요
파티에서 콕을 한 번 더 찌를 수 있어요
```
> 파티 시작 소식과 같은 순간에 선다. 모두의 화면이 함께 바뀌는 순간이라 옆 사람이 알아챌 신호가 없다 (ADR-64).

#### S-B4 운영자 현황 탭
- 파티 전: `✨ 매력 투표 TOP 5` 아래 `파티가 시작되면 1위에게 콕이 1회 더 생겨요`
- 파티 뒤: 1위 옆에 `+1 콕`

#### S-B5 파티 시작 확인창
```
매력 투표 1위   남 ○○ · 여 ○○ 에게 콕이 1회 더 생겨요
```
> 2표 이상 받은 사람이 없으면 `받을 사람이 없어요 (2표 이상 받은 사람이 없어요)`.

### C. 설정

#### S-C1 ★ 파티가 시작되면 굳는다
> 1위가 보너스 콕을 쓴 뒤에 끄면 쓴 횟수가 한도를 넘는다. 409 `locked`.

#### S-C2 ★ 다른 설정을 고쳐도 사라지지 않는다
> `meta.config` 는 통째로 교체된다 — 콕 횟수만 고치는 저장 하나로 이 값이 사라지면 안 된다.

#### S-C3 ★ 파티 콕 한도를 내릴 때 1위의 보너스는 바닥에 넣지 않는다
```
Given  maxParty 2 · 1위 A 가 3회를 썼다
When   운영자가 maxParty 를 2 로 저장한다
Then   통과한다 — A 의 한도는 3 이다
```

### D. 매력 투표는 파티 시작에 닫힌다

#### S-D1 ★ 매력 투표는 파티가 시작될 때까지 열려 있다
```
Given  매력 투표 중
Then   파티 일시 직전까지 투표할 수 있다
When   파티가 시작된다
Then   매력 투표는 닫히고 파티 콕이 열린다
```

#### S-D2 ★ 마감 시각은 받지 않는다
> 회차를 만들 때도 일정을 고칠 때도 마감 시각을 받지 않는다. 마감 시각이 적혀 있는 옛 회차도 그 시각에 닫히지 않는다 —
> 설정 화면에 그 칸이 없어서 운영자가 고칠 수 없는 마감이 되기 때문이다.

#### S-D3 자리 배정은 매력 투표를 보지 않는다
> 테스트가 아니라 **타입이 지킨다** — `BuildInput` 에 표를 넣을 자리가 없다.

#### S-D4 참가자 카운트다운은 매력 투표 중에 `파티까지` 를 센다
