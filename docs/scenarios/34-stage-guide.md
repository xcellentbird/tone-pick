# 슬라이스 34 — 단계가 열릴 때의 안내 화면

매력 투표가 열릴 때와 파티가 시작될 때, **그 단계에서 할 일 하나**를 전체 화면으로 보여주고
버튼으로 닫는다 (ADR-96).

운영자가 걸러낸 문제: *사람들이 안내문을 잘 읽지 않다보니, 진행 방식에 대해 매번 물어봅니다.
매력 투표와 콕 찌르기의 역할이 무엇인지 이해하지 못하고 있습니다.*

도움말(슬라이스 21)은 등록 직후에 네 단계를 한꺼번에 보여준다 — 매력 투표가 열리기 **며칠 전**이다.
이 화면은 행동이 열리는 **그 순간**에, **그 단계 하나만** 말한다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 왜 전체 화면인가 — 그리고 왜 그것만으로는 안 되는가

자리 확인 화면(`SeatTakeover`)이 이미 겪었다: *전체 화면이 덮치면 반사적으로 누르기 쉬운데,
그때 테이블 번호를 못 읽고 사라진다.* 버튼이 아래 있다고 읽지 않는다 — 스크롤한다.
그래서 셋으로 그 반사를 이긴다.

1. **스크롤이 없다.** 버튼까지 한 화면에 들어온다. 눈이 버튼으로 가는 길에 카드를 지난다
2. **카드가 내용이다.** 이모지 하나, 할 일 한 줄, 그래서 생기는 일 한 줄
3. **버튼이 다음 할 일이다.** `확인` 이 아니라 `참가자 보러 가기` — 누르는 순간이 곧 시작이다

## 범위

**만든다**

| | |
|---|---|
| 매력 투표가 열릴 때 (B) | 카드 하나 — `프로필을 보고 투표해보세요` / `내가 투표한 사람과 첫 자리에서 같은 테이블에 앉을 확률이 높아져요` |
| 파티가 시작될 때 (C) | 카드 하나 — `마음에 드는 사람을 콕 찔러보세요` / `서로 콕 찌르면 발표 때 두 사람에게만 실명이 공개돼요`. 그 아래 `콕 N회를 새로 받았어요` 와 알림 한 줄 |
| 봤다는 표시 | 참가자 행에 `seen_stage` 하나. 누르면 저장되고 다시 안 뜬다 — 탭이 갈려도 사람은 하나다 (ADR-44) |
| 순서 | **자리 확인이 먼저.** 둘 다 뜰 자리면 자리 화면이 먼저 뜨고, 확인한 뒤에 이 화면이 온다 |

**안 만든다**

- **등록 직후·투표 마감·발표의 안내.** 등록 직후는 도움말이(슬라이스 21), 마감은 자리 화면이,
  발표는 결과 카드가 이미 그 자리다. **새 행동이 열리는 순간은 둘뿐이다**
- **다음 단계 설명.** 매력 투표 화면에서 콕을, 파티 화면에서 투표를 말하지 않는다 —
  그 단계는 그 단계가 열릴 때 말한다. 안 묻는 답을 적는 만큼 묻는 답이 밀린다 (ADR-76)
- **두 칸 그림.** 두 행동을 나란히 놓고 `지금` 을 옮기는 안을 그려봤다. 화면 하나에 한 가지가 더 세다
- **되돌리기 안내.** 되돌리기는 언제나 된다(ADR-95) — 그건 확인창이 누르는 순간 말한다.
  여기는 한 가지만 말하는 자리다
- **콕이 자리에 미치는 이야기.** 일방 콕은 자리를 사실상 못 움직이고(ADR-91), 상호 콕은 움직이는데
  그건 말하면 안 되는 쪽이다 — 후반 테이블이 곧 발표가 된다 (ADR-51·52)
- **다시 여는 길.** 홈 카드가 같은 말을 이미 한다 (`HOME.todo`) — 그게 다시 여는 길이다
- **움직임.** 남이 일으킨 화면이다 (ADR-64). 그냥 나타난다
- **일러스트.** 이모지와 CSS 뿐이다 — 번들 예산이 94% 다

## A. 언제 뜨나

### S-A1 ★ 매력 투표가 열린 뒤 처음 열면 뜬다
```
Given  등록을 마쳤고 아직 안 봤다
When   단계가 매력 투표인 채로 앱을 연다
Then   전체 화면에 B 가 떠 있고, 버튼은 `참가자 보러 가기` 다
```
> **사건이 아니라 상태에 붙인다.** 매력 투표는 예약 시각에 열리고(ADR-38) 파티도 예약이 연다(ADR-93) —
> 그 순간 앱을 켜둔 사람이 없다. 슬라이스 21 처럼 사건에 붙이면 거의 아무도 못 본다.

### S-A2 ★ 파티가 시작된 뒤 처음 열면 C 가 뜬다 — B 를 봤든 안 봤든
```
Given  단계가 파티다
When   `seenStage` 가 없거나 `prevote` 인 사람이 앱을 연다
Then   C 가 떠 있다
```

### S-A3 ★ 한 번 누르면 다시 안 뜬다 — 새로고침해도, 다른 탭에서도
```
When   버튼을 누른다
Then   `seenStage` 가 그 단계로 저장되고, 화면은 참가자 탭이다
And    다시 읽어도, 다른 이름표(`x-tp-ref`)로 읽어도 안 뜬다
```
> **클라이언트가 어느 단계를 봤는지 보낸다.** 서버가 현재 단계를 저장하면, B 를 누르는 순간
> 파티가 시작된 사람에게 C 가 영영 안 뜬다.

### S-A4 ★ 자리 확인이 먼저다
```
Given  자리가 발행됐고 아직 확인 전이고, 파티 시작 안내도 안 봤다
Then   자리 확인 화면이 먼저 뜬다
When   자리를 확인한다
Then   그제야 C 가 뜬다
```

### S-A5 ★ 발표 뒤에는 뜨지 않는다
> 결과 카드가 그 자리다. 발표 뒤에 "콕 찔러보세요" 는 할 수 없는 일을 시키는 것이다.

### S-A6 ★ 늦게 등록한 사람에게도 뜬다
```
Given  파티가 시작된 뒤에 등록했다
Then   등록을 마친 화면 위에 C 가 있다
```
> 등록 직후 도움말(슬라이스 21)과 겹친다. **자리 화면과 같은 규칙이다** — 이 화면이 도움말 위에 선다.
> 누르면 도움말이 그 아래 있다.

## B. 무엇이 적혀 있나

### S-B1 ★ 콕 횟수는 회차 설정에서 온다
> `콕 2회를 새로 받았어요` 의 2 는 `maxParty` 다. 도움말이 이미 같은 방식이다.

### S-B2 ★ 알림 줄은 회차 설정을 본다
```
Given  pokeNotify 를 켠 회차     Then  `상대에게는 익명으로 알림이 가요`
Given  pokeNotify 를 끈 회차     Then  `찌른 사실은 상대에게 알려주지 않아요`
```
> 두 문장은 반대 말이고 어느 쪽이 참인지는 설정이 정한다 (ADR-43). 도움말이 같은 자리에서 같은 일을 한다.

### S-B3 ★ 참가자 응답에 새로 실리는 건 `seenStage` 하나다
> 명단(`roster`)에는 없다 — 남이 안내를 봤는지는 남의 일이다. 운영자 응답에도 넣지 않는다 —
> 묻는 사람이 없는 숫자는 쓰이는 줄 알게 된다.

## 문구 — `STAGE`

| 자리 | 문장 |
|---|---|
| B 제목 | 매력 투표가 열렸어요 |
| B 할 일 | 프로필을 보고 투표해보세요 |
| B 그래서 | 내가 투표한 사람과 첫 자리에서 같은 테이블에 앉을 확률이 높아져요 |
| C 제목 | 파티가 시작됐어요 |
| C 할 일 | 마음에 드는 사람을 콕 찔러보세요 |
| C 그래서 | 서로 콕 찌르면 발표 때 두 사람에게만 실명이 공개돼요 |
| C 횟수 | 콕 N회를 새로 받았어요 |
| C 알림 켬 | 상대에게는 익명으로 알림이 가요 |
| C 알림 끔 | 찌른 사실은 상대에게 알려주지 않아요 |
| 버튼 | 참가자 보러 가기 (`HOME.goPeople`) |

어체는 ADR-89 후기의 표를 따른다 — 제목 `~됐어요`, 할 일 `~해보세요`, 결과 `~돼요`, 안심 `~지 않아요`.
`B 그래서` 는 도움말의 문장과 **같은 문장**이다 — 출처가 하나다.
