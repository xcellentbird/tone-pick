# 슬라이스 17 — 콕이 눌린 것처럼 보이게

지금 콕을 보내면 **왕복을 두 번** 기다린 뒤에야 버튼이 바뀐다.

```js
await source.poke(target.id);   // ① 서버에 보낸다
toast(POKE.sent(...));
reload();                        // ② 화면 전체를 다시 읽는다
```

그동안 화면은 **아무 말도 하지 않는다.** 확인창은 이미 닫혔고, 버튼은 그대로고,
스피너도 없다. 파티장 망에서 이게 몇백 ms~몇 초다.

사람은 이때 **다시 누른다.** 눌렀는지 확신이 없어서다.
`콕 상한`이 있는 앱에서 이건 가벼운 문제가 아니다.

`★` 는 반드시 테스트를 붙이는 것.

---

## ADR-26 과 어디서 갈라지나

> 실시간은 **"다시 읽어라" 신호로만** 쓴다. 부분 갱신을 만들면 화면과 서버가 조용히 어긋난다.

이 규칙은 그대로다. 다만 **두 가지가 섞여 있었다.**

| | ADR-26 이 막는 것인가 |
|---|---|
| 서버가 **방금 돌려준 값**을 쓴다 | **아니다.** 서버가 진실을 말해줬는데 그걸 버리고 다시 묻고 있었다 |
| 서버가 답하기 전에 **결과를 미리 그린다** | **맞다.** 여기가 조용히 어긋날 수 있는 자리다 |

`source.poke()` 는 이미 `MyPokeState` 를 돌려준다. 그걸 쓰면 **왕복 하나가 통째로 없어진다** —
새로 지어내는 게 아니라 이미 받은 답을 쓰는 것뿐이다.

미리 그리는 쪽은 규칙과 부딪히므로, **범위를 좁게 못 박는다.**

```
미리 그려도 되는 것   내 콕 하나. 방금 내가 한 행동이고, 서버 답이 오면 곧바로 덮어쓴다
절대 안 되는 것       명단 · 받은 콕 · 매칭 · 남의 무엇이든
```

**판별 기준 한 줄: 내가 방금 한 행동의 결과만 미리 그린다.**
남이 한 일이나 서버만 아는 것은 여전히 다시 읽어야 안다.

---

## 범위

**만든다**

| | |
|---|---|
| 누르는 즉시 버튼이 바뀐다 | 왕복을 기다리지 않는다 |
| 서버 답이 오면 **그 값으로 확정** | `reload()` 한 번이 통째로 없어진다 |
| 실패하면 **되돌린다** | 숫자가 올라갔다 내려오고, 토스트가 이유를 말한다 |
| 보내는 중 **다시 못 누른다** | 왕복이 우연히 막아주던 걸 이제 명시적으로 막는다 |

**안 만든다**

- **명단·받은 콕·매칭의 부분 갱신.** 여기는 ADR-26 그대로다
- **스피너.** 즉시 바뀌면 기다림 자체가 없어서 보여줄 것이 없다
- **진동(햅틱).** 아래 "안 넣는 이유" 참고
- 되돌리기 애니메이션. 실패는 드물고, 화려하면 실패가 더 커 보인다

---

## A. 즉시 바뀐다

### S-A1 ★ 확인을 누르면 서버를 기다리지 않고 숫자가 오른다
```
Given  A 를 한 번 찔렀고 남은 콕이 2회다
When   확인을 누른다 (서버는 아직 답하지 않았다)
Then   A 의 버튼이 2회, 남은 콕이 1회로 **그 자리에서** 바뀐다
```
> **테스트는 서버 응답을 붙잡아둔 채로 확인한다.** 그래야 "빨라졌다" 가 아니라
> "기다리지 않는다" 를 재는 것이 된다.

### S-A2 ★ 서버 답이 오면 그 값으로 덮어쓴다
```
When   서버가 MyPokeState 를 돌려준다
Then   화면이 서버 값과 같아지고, 다시 읽기(reload)는 일어나지 않는다
```
> 미리 그린 값과 서버 값이 다를 수 있다 — 다른 기기에서 이미 찔렀거나,
> 운영자가 상한을 바꿨거나. **서버가 항상 이긴다.**
> 그리고 이 한 줄이 왕복 하나를 없앤다.

### S-A3 ★ 실패하면 되돌린다
```
When   서버가 거절한다 (상한 초과 · 단계 닫힘 · 망)
Then   숫자가 누르기 전으로 돌아가고, 토스트가 이유를 말한다
```
> 되돌리지 않으면 **쓰지도 않은 콕이 쓴 것으로 보인다.** 상한이 있는 앱에서
> 이건 그냥 틀린 화면이 아니라 **남은 기회를 잘못 알려주는 것**이다.

---

## B. 두 번 눌리지 않게

### S-B1 ★ 보내는 중에는 다시 안 보낸다
```
When   확인을 누른 직후 같은 사람을 또 누른다
Then   요청은 한 번만 나간다
```
> 지금은 왕복이 **우연히** 막고 있다 — 느려서 못 누르는 게 아니라
> 버튼이 안 바뀌어서 누를 마음이 안 드는 것뿐이다.
> 즉시 바뀌게 만들면 그 우연이 사라지므로 **명시적으로 막아야 한다.**
> 이걸 빼면 이 슬라이스는 콕을 두 번 보내는 기능이 된다.

---

## C. 미리 그리는 계산

### S-C1 ★ 순수 함수다 — `afterPoke(poke, toId, round)`
```
Given  임의의 MyPokeState
When   afterPoke 를 부른다
Then   sentTo[toId] 와 budget[round].used 만 1 늘어난다
And    받은 콕 · 매칭은 손대지 않는다
```
> **순수 함수라 먼저 쓰고 구현한다** (`buildSeating` 과 같은 예외).
> 화면 없이 테스트되고, 무엇을 건드리고 무엇을 안 건드리는지가 함수 하나에 다 드러난다.
> 여기가 흐려지면 "내 콕만" 이라는 경계가 코드 어디에도 없게 된다.

## 진동(햅틱)을 안 넣는 이유

체감 반응을 올리는 흔한 수단이고 `navigator.vibrate` 한 줄이면 된다. 그런데 —

- **소리가 난다.** 테이블에 놓인 폰은 진동이 들린다. 옆 사람이 *"쟤 방금 뭐 했다"* 를 안다.
  슬라이스 16 이 화면에서 막으려는 것을 **소리로 새게 하는 셈**이다
- **iOS 사파리는 지원하지 않는다.** 절반에게만 닿는 피드백은 기준이 될 수 없다

즉시 바뀌는 화면이 이미 같은 일을 하고, 소리를 내지 않는다.
