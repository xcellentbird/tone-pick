# 슬라이스 15 — 링크는 하나, 열쇠는 번호와 PIN 번호

**운영자가 스물여덟 명에게 링크를 하나씩 보내야 했다.** 사람마다 링크가 다르니
단톡방에 뿌릴 수 없고, 참가자용 단톡방도 없어서 1:1 로만 간다. 안내문과 링크가
따로 가므로 한 사람당 두 번, 그 사이에 앱으로 돌아와 다음 사람의 링크를 복사한다.

이 슬라이스는 **링크를 회차마다 하나로 되돌리고**, 잃어버린 열쇠를
**전화번호 + PIN 번호 4자리**로 바꾼다. 결정과 대가는 `ADR-75`.
ADR-32(개인별 링크)가 닫았던 문제를 다른 방법으로 다시 막는다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 범위

**만든다**

| | |
|---|---|
| 회차마다 **공용 참가 링크** | `/j/<회차id>` — 토큰이 없다 |
| **전화번호로 입장** | 초대 명단에 있어야 통과 |
| **PIN 번호 4자리** | 등록 마지막 걸음에서 정한다. 재입력 칸이 함께 있다 |
| **5회 잠금** | 번호 단위. 시간이 지나도 안 풀린다 |
| **운영자 초기화** | PIN 번호와 실패 횟수를 함께 지운다. 새 값은 참가자가 정한다 |
| 안내문에 **링크가 다시 들어간다** | 전원이 같은 글이라 한 메시지로 끝난다 |

**안 만든다**

- **개인별 링크.** 없앤다. 아직 아무에게도 보내지 않았다
- **참가자가 스스로 PIN 번호 바꾸기.** 한 번 정하면 못 고친다 — 그래서 재입력 칸이 있다
- **문자 인증(OTP).** 발신번호 사전등록·비용이 든다. 이 규모에는 아직 과하다 (ADR-75)
- **자동 잠금 해제.** 운영자만 푼다
- **삭제 후 재등록.** 복구 경로로 두지 않는다 — 받은 콕과 자리가 날아가고 매칭이 어긋난다 (ADR-29)
- **참가자가 자기 PIN 번호를 다시 보는 길.** 저장된 건 해시뿐이라 아무도 못 본다

## A. 문

### S-A1 ★ 링크만으로는 아무것도 못 한다
```
When   /j/<회차id> 를 연다
Then   회차 이름·단계·일시가 보인다. 그리고 그뿐이다 — 명단도 참가자도 없다
```
> 토큰이 사라졌으므로 **회차가 있다는 사실은 링크로 드러난다.** 이 설계가 치르는 대가다 (ADR-75).

### S-A2 ★ 초대 명단에 없는 번호는 못 들어온다
```
When   명단에 없는 번호를 넣는다
Then   들어가지 못하고, PIN 번호 칸이 나타나지 않는다
```

### S-A3 ★ 초대된 번호 + 맞는 PIN 번호면 들어온다
```
Given  A(010-1111)가 등록을 마쳤고 PIN 번호가 1234 다
When   010-1111 · 1234 를 넣는다
Then   A 의 화면으로 간다
```

### S-A4 ★ PIN 번호가 틀리면 못 들어온다
```
When   010-1111 · 9999 를 넣는다
Then   들어가지 못한다. 실패가 한 번 쌓인다
```

### S-A5 ★ 5회 틀리면 잠긴다 — 시간이 지나도 안 풀린다
```
When   같은 번호에 PIN 번호를 5회 틀린다
Then   그 번호는 잠긴다
When   한 시간 뒤에 다시 시도한다
Then   여전히 잠겨 있다
```
> **잠금은 번호에 건다.** 접속지에 걸면 망을 바꿔 빠져나간다.
> 대가는 *남의 번호를 5번 틀려 그 사람을 잠글 수 있다* 는 것이다 — 알고 고른 것이다 (ADR-75).

### S-A6 ★ 잠긴 번호는 맞는 PIN 번호로도 못 들어온다
```
Given  010-1111 이 잠겼다
When   맞는 PIN 번호를 넣는다
Then   들어가지 못한다
```
> 잠금이 PIN 대조보다 **먼저** 판정돼야 한다. 뒤에 두면 잠긴 뒤에도 맞는 값을 확인해 주는 셈이다.

### S-A7 ★ 접속지별 제한은 그대로다
```
When   한 접속지에서 여러 번호를 잇따라 넣는다
Then   ENTRY_TRIES 가 그대로 막는다 (10분에 8번)
```
> **번호 단계와 PIN 단계 둘 다에 건다.** PIN 단계에만 없으면 번호를 통과한 뒤 만 번을 두드릴 수 있다
> (`PLAN.md` 15 의 반드시 지킬 것).

### S-A8 ★ 세 가지 실패는 세 가지 문구다
```
회차가 없다        → 그런 회차가 없어요
초대된 번호가 아니다 → 초대된 번호가 아니에요
PIN 번호가 틀렸다   → 맞지 않아요 (남은 횟수와 함께)
```
> **일부러 가른다.** 뭉개면 번호를 잘못 친 사람이 PIN 번호를 계속 다시 쳐서
> **번호가 틀렸는데 잠금에 걸린다.** 잠금 해제는 운영자만 하므로 그 사고가 가장 비싸다.
> 대가는 *번호를 넣어보면 초대 여부를 알 수 있다* 는 것이다 (ADR-75).

### S-A9 ★ 세션은 30일이고 탭마다 갈린다
```
When   입장에 성공한다
Then   이 탭의 이름표를 응답이 준다 (ADR-44). 쿠키는 30일이다
```
> **"이미 등록했나" 를 브라우저 세션에 묻지 않는다** — 이제 그 답은 **번호**가 한다.

## B. 등록

### S-B1 ★ 아직 등록 안 한 번호는 PIN 번호를 묻지 않는다
```
Given  010-2222 가 명단에 있고 아직 등록하지 않았다
When   010-2222 를 넣는다
Then   PIN 번호 칸 없이 등록 폼으로 간다
```

### S-B2 ★ PIN 번호는 등록을 마쳐야 저장된다
```
Given  010-2222 로 등록 폼에 들어가 3걸음까지 채우고 나갔다
When   누군가 010-2222 로 다시 들어온다
Then   PIN 번호를 묻지 않는다 — 아직 걸린 것이 없다
```
> 중간에 나간 사람의 자리에 **자물쇠가 걸려 있으면 안 된다.**
> 이 규칙이 선점의 창을 좁힌다 (오타로 남의 번호를 넣고 나가도 그 사람이 잠기지 않는다).

### S-B3 ★ 두 번 입력이 다르면 등록이 안 된다
```
When   PIN 번호와 재입력이 다르다
Then   등록을 마칠 수 없다
```
> **재입력 칸과 "못 고친다" 는 한 몸이다** (`PLAN.md` 15). 4자리는 오타를 눈으로 못 잡고
> 고칠 길이 없으니, 재입력이 유일한 방어다. **둘 중 하나만 떼지 마라.**

### S-B4 ★ 등록 폼은 전화번호를 받지 않는다
```
When   등록 API 에 phone 을 함께 보낸다
Then   무시된다 — 번호는 서버가 초대 쿠키에서 꺼낸다
```
> `RegisterInput` 에 phone 키를 두지 않는 방어는 그대로다 (ADR-31).
> 바뀐 건 **쿠키가 무엇으로 만들어지나** 뿐이다 (토큰 → 번호+PIN 판정).

### S-B5 ★ PIN 번호는 해시로만 저장된다
```
When   PIN 번호를 정한다
Then   저장된 값에서 원래 네 자리를 되찾을 수 없다
```
> 사람들은 폰 잠금 PIN 을 그대로 쓴다 — 우리가 지킬 이유가 이 앱 밖에도 생긴다.
> 회차 DO 안에 둬서 파기가 DO 하나 지우는 일로 끝난다.

## C. 잠금과 재설정

### S-C1 ★ 초기화하면 PIN 번호와 실패 횟수가 함께 지워진다
```
Given  010-1111 이 잠겼다
When   운영자가 그 참가자의 PIN 번호를 초기화한다
Then   잠금이 풀리고, 다음 입장에서 PIN 번호를 새로 정한다
```
> **함께 지워야 한다.** PIN 만 지우고 실패 횟수를 남기면 새로 정하자마자 다시 잠긴다.

### S-C2 ★ 초기화는 삭제가 아니다
```
When   PIN 번호를 초기화한다
Then   그가 보낸 콕 · 받은 콕 · 자리 · 운세는 그대로다
```
> 삭제 후 재등록을 복구 경로로 두지 않는 이유가 이것이다 — 지우면 매칭이 통째로 어긋난다 (ADR-29).

### S-C3 ★ 운영자도 남의 PIN 번호를 볼 수 없다
```
When   운영자 응답을 연다
Then   PIN 번호도, 그 해시도 없다. 있는 것은 `정함 / 안 정함 / 잠김` 뿐이다
```

### S-C4 초기화는 확인을 거친다
```
When   운영자가 초기화를 누른다
Then   무엇이 어떻게 바뀌는지 보여준다 —
       `설정한 PIN 번호가 지워져요 · 다음 입장에서 새로 정해요`
```
> 되돌릴 수 없는 일이라 확인이 붙는다. 콕·자리가 그대로라는 것도 여기서 말한다.

## D. 화면

### 배너 (`/j/<회차id>`) — **손대지 않는다**

로고 · 단계 · 회차 이름 · 일시 · 버튼 하나. 지금 그대로다.
*"가운데의 빈 자리는 일부러 비운 것이다 — 이 화면이 하는 일이 '어느 파티인지 한 번 보여주는 것'
하나라서, 채우면 그 하나가 흐려진다"* (`theme.css`).

- **입력칸을 배너에 두지 마라.** 키보드가 뜨면 화면이 `100dvh - var(--kb)` 로 줄어
  로고가 잘린 채로 남는다. 실제로 그려서 확인했다
- 버튼 문구는 **하나다** (`들어가기`). 번호를 받기 전에는 첫 입장인지 재입장인지 모른다

### 입장 확인창 (`/j/<회차id>/enter`) — 가운데, 좁게

- `.dialog` 를 쓴다. **시트가 아니다** — *"시트는 여기 더 있다고 말하며 아래에서 올라오고,
  확인창은 지금 이걸 정해라 라고 말하며 있던 자리에서 커진다"* (`theme.css`). 이건 후자다
- 폭은 `min(340px, 100% - 56px)`. 확인창 기본값(420px)은 묻는 게 두 칸뿐인 자리에 넓다
- **열릴 때 번호 칸에 커서를 준다** — ADR-63 의 예외 1호. 그 ADR 이 *"구현이 둘 이상일 때 만든다"*
  고 적어둔 둘째가 여기다. 칠 것밖에 없는 창이라 커서가 없으면 탭이 순수하게 하나 낭비된다
- **11자리가 차면 자동으로 검증한다** (300ms 늦춘다 — 고치는 중에 요청이 나가면 문구가 깜빡인다)
- 등록한 사람이면 **PIN 번호 칸이 그 아래로 펼쳐진다.** 걸음을 가르지 않는다 —
  번호가 계속 보여야 원인이 번호일 때 그 자리에서 고친다
- **4자리가 차면 자동으로 제출한다.** 실패하면 PIN 칸만 비우고 번호는 남긴다
- 남은 횟수는 **2회 남았을 때부터** 말한다. 잠금이 운영자 호출로 끝나는 무거운 결과다
- 잠겨도 **번호 칸은 잠그지 않는다** — 남의 번호를 쳤을 수 있다

### 등록 4걸음 — 마지막이 PIN 번호다

`기본 정보 · 연락처 · 나를 소개 · 다시 들어올 때`

- 칸 둘: `PIN 번호 4자리` · `PIN 번호 재입력`
- 마지막에 두는 이유는 **등록을 마쳐야 저장되기 때문**이다 (S-B2)

### 운영자 콘솔 — 참가자 상세 시트

- `PIN 번호 초기화` 한 줄. 상태는 `정함 / 안 정함 / 잠김`
- **`잠김` 은 눈에 띄어야 한다** — 참가자가 말하기 전에 운영자가 먼저 보는 편이 낫다

### 초대 명단 시트 — 행에서 링크가 사라진다

- 사람마다 다른 것이 없어졌다. 행에 남는 건 `명단에서 빼기` 뿐이다
- 안내문에 **링크가 다시 들어간다** — 전원이 같은 글이라 ADR-32 후기 ① 의 전제가 안 깨진다.
  1인당 메시지가 둘에서 하나로 준다
- 장소에 지도 링크를 적는 회차에서는 한 메시지에 링크가 둘이 된다.
  안내문 고치는 화면에서 한 줄로 알린다
