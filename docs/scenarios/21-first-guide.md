# 슬라이스 21 — 등록 직후의 첫 안내

도움말은 이미 있다. 문제는 **그걸 여는 사람이 이미 질문이 생긴 사람**이라는 것이다.

```
/** src/client/ui/Help.tsx */
 * 운영자가 "앱에서 물음표 눌러보세요" 라고 말할 수 있는 게 이 화면의 값어치다 —
 * 안 묻는 사람은 어차피 안 읽는다. **묻는 사람에게 가리킬 곳**을 만드는 것이 목적이다.
```

그 판단은 그때 맞았다. 하지만 목표가 **"운영자에게 묻는 일을 줄이는 것"** 이면 방향이 반대다.
질문이 생기기 **전에** 한 번은 읽혀야 한다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 등록 직후가 이 앱에서 가장 비어 있는 화면이다

`Register.submit()` 은 `/e/:code` 로 갈아끼우고 토스트 하나를 띄운다. 그 화면에 있는 것은
`HOME.todo.reg` 두 줄이 전부다 — 명단은 안 열렸고(ADR-21), 오늘 탭도 없고(파티 후), 자리도 없다.

**참가자의 주의가 가장 높은 순간에 설명이 가장 적다.** 그리고 사전 콕 찌르기가 열릴 때까지
며칠 그 상태다. 그 며칠 동안의 질문이 전부 운영자에게 간다.

---

## 범위

**만든다**

| | |
|---|---|
| 등록을 마치면 도움말이 **한 번 자동으로** 열린다 | 뒤로 가기 한 번이면 홈이다 |
| 등록 중 홈 카드에 **`진행 방식 보기`** | 반사적으로 닫은 사람이 다시 여는 길 |
| 4단계 그림 — **`등록` 칸을 더한다** | 처음 읽는 사람이 자기 위치를 찾는다 |
| 동성 콕 금지 회차에만 문답 한 줄 | 지금은 **눌러봐야** 안다 |

**안 만든다**

- **새 화면.** 도움말은 한 벌이다. 온보딩 캐러셀을 따로 만들면 두 집 살림이 되고 하나가 반드시 낡는다
- **읽음 상태.** 저장하지 않는다 (ADR-4). "등록 완료" 라는 **사건**에 붙는다 —
  새로고침하면 안 뜨고, 다시 보려면 `?` 다
- **등록 4스텝.** 등록 폼은 이탈 지점이다. 스텝을 늘리면 안 읽고 넘기고 초안 가드까지 걸린다
- **운영자가 쓰는 자유 문구.** 아래 「경계」를 보라
- **`링크를 잃어버렸어요` 문답.** 답이 "운영자에게 말하세요" 뿐이라
  질문을 줄이는 게 아니라 **유도한다**

---

## 경계 — 도움말은 **회차마다 달라지면 안 되는 것**이다

그날 다른 것은 **운영자 알림**(슬라이스 14)이 맡는다. 이 선을 지금 그어둔다.

| | |
|---|---|
| 도움말 | 이 앱이 늘 그런 것 — 흐름 · 익명 규칙 · 결과가 나오는 자리 |
| 운영자 알림 | 오늘만 그런 것 — 와이파이 비번 · 2부 시작 · 자리 이동 |

**회차 설정에서 오는 것은 값뿐이다.** 문장 구조는 고정하고 숫자와 켬/끔만 갈아끼운다 —
`count.a(maxPre, maxParty)` 가 이미 그 방식이다. 도움말에 자유 입력 칸을 만들지 마라.

넣지 않기로 한 것과 이유:

- **일정 시각** — 상단 카운트다운이 이미 센다. 같은 숫자가 두 곳에 있으면 어느 쪽이 맞는지
  눈이 한 번 더 확인한다
- **장소** — 참가자 응답에 없다 (ADR-32). 안내문이 맡는다

## A. 등록 직후

### S-A1 ★ 등록을 마치면 도움말이 열려 있다
```
Given  등록 3스텝을 다 채웠다
When   등록하기를 누른다
Then   참가자 화면 위에 도움말이 떠 있다
```
> **이 슬라이스의 전부가 이 한 줄이다.** 나머지는 이걸 감당할 수 있게 만드는 것이다.

### S-A2 ★ 뒤로 가면 도움말만 닫히고 홈이다 — 등록 폼으로 돌아가지 않는다
```
When   도움말에서 뒤로 간다
Then   /e/:code 이고, 등록 폼은 어디에도 없다
```
> `등록 완료 → 메인` 은 `replace` 다 (ROUTES.md). 그 규칙을 지키면서 도움말을 얹으려면
> **갈아끼운 뒤에 밀어 넣어야** 한다. 순서가 뒤집히면 뒤로 가기가 3스텝을 밟는다.

### S-A3 ★ 새로고침하면 다시 뜨지 않는다
```
Given  등록 직후 도움말이 떴고, 닫았다
When   화면을 다시 읽는다 · 앱을 나갔다 돌아온다
Then   도움말은 안 뜬다
```
> 읽음 상태를 저장하지 않는 대신 **사건에 붙였다** — 붙일 곳이 없으면 안 뜬다.
> 매번 뜨는 안내는 안내가 아니라 방해다.

### S-A4 ★ 반사적으로 닫은 사람이 다시 여는 길이 보인다
```
Given  등록 중이다
Then   홈 카드에 `진행 방식 보기` 가 있다
```
> `SeatTakeover` 에서 이미 겪었다 — *"전체 화면이 덮치면 반사적으로 누르기 쉽고,
> 그러면 테이블 번호를 못 읽는다."* 그때 홈의 자리 카드가 다시 여는 길이 됐다. 같은 장치다.
>
> **등록 단계에만 둔다.** 사전 콕 찌르기부터는 그 자리에 `참가자 보러 가기` 가 있고,
> 한 카드에 버튼이 둘이면 어느 것이 지금 할 일인지 갈린다. 그 뒤로는 `?` 가 맡는다.

## B. 무엇이 적혀 있나

### S-B1 ★ 4단계 — `등록` 칸이 있고, 등록 중이면 거기 `지금` 이 붙는다
```
Given  등록 단계다
When   도움말을 연다
Then   `등록` 칸에 `지금` 이 글자로 붙어 있다
```
> 지금은 `prevote·party·done` 셋뿐이라 **등록 중에는 어디에도 `지금` 이 안 붙는다** —
> 하필 처음 읽는 사람이 자기 위치를 못 찾는다. `Help.tsx` 주석이
> *"등록 중에는 아직 아무 단계도 아니다"* 라고 적어둔 것이 그 자리다.
>
> 색으로만 말하지 않는 규칙은 그대로다.

### S-B2 `등록` 칸이 답하는 것은 **"지금 뭐 하면 돼요?"** 다
> 그래서 본문은 단계 설명이 아니라 **할 일의 끝**을 말한다 — 낸 것으로 준비가 끝났다는 것.
>
> 위에 `지금 …` 한 줄을 따로 두는 안을 검토하고 뺐다. `지금` 이 두 곳에 있으면
> 어느 쪽이 맞는지 눈이 한 번 더 확인한다 — 이 앱이 인원 수와 남은 콕에서 반복해 지킨 규칙이다.
> **한 칸이 늘고 블록은 안 는다.**

### S-B3 ★ 콕 횟수는 회차 설정에서 온다
> 이미 지켜지고 있다 (`qa.count.a(maxPre, maxParty)`). 테스트도 있다. 그대로 둔다.

### S-B4 ★ 동성에게 못 찌르는 회차에서만 그 줄이 보인다
```
Given  allowSameGender === false 인 회차
When   도움말을 연다
Then   누구에게 찌를 수 있는지 적혀 있다

Given  기본값(모두에게) 회차
Then   그 줄이 아예 없다
```
> 지금은 **눌러봐야 안다** — `People.tsx` 가 토스트로 `POKE.blocked.sameGender` 를 띄운다.
> 도움말에도 목록에도 없어서 "왜 안 찔러져요?" 가 운영자에게 간다.
>
> **기본값 회차에는 줄을 만들지 않는다.** "누구에게나 찌를 수 있어요" 는 아무도 안 묻는 답이고,
> 안 묻는 답을 적는 만큼 묻는 답이 뒤로 밀린다.

---

## 분량 — 무엇을 빼는지가 기준이다

시트 한 화면(스크롤 한 번 이내). **개수로 정하지 않는다.** 한 줄마다 이것만 묻는다:

> **이 줄이 없으면 운영자에게 묻게 되는가.**

아니면 뺀다. 이 슬라이스의 순증은 **두 줄**이다 — `등록` 칸 하나, 동성 콕 줄 하나(그 회차에만).
