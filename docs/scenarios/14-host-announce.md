# 슬라이스 14 — 운영자가 보내는 알림

운영자가 파티 중에 전원에게 무언가를 보낼 길이 없다. 지금은 목소리뿐인데,
목소리로 안 되는 게 셋 있다 — **다시 읽어야 하는 것**(와이파이 비번·2부 일정),
**늦게 온 사람**, **시끄러워서 안 들리는 것**.

두 가지를 보낸다.

```
📢 텍스트   한 칸에 쓴 글이 배너 + 소식에 남는다
📊 A/B 투표  두 선택지 중 하나를 고르게 하고, 집계가 실시간으로 보인다
```

`★` 는 반드시 테스트를 붙이는 것.

---

## ⚠️ 이 슬라이스의 첫 규칙 — **선택지에 사람을 넣지 않는다**

A/B 투표는 구조상 *"둘 중 뭐가 나아요?"* 다. **그 둘이 사람이 되는 순간**

> 일방적인 호감은 끝까지 드러나지 않는다 — 거절의 경험을 만들지 않는 게 이 앱의 존재 이유다

이 문장이 정면으로 깨진다. `축구 vs 디디, 누가 더?` 는 이 앱이 없애려고 만들어진 바로 그 경험이고,
**운영자가 좋은 뜻으로 올려도 결과가 그렇다.**

자유 텍스트라 코드로는 못 막는다. **설계로 줄인다** —

- **선택지를 참가자 목록에서 고르는 길을 만들지 마라.** 손으로 쳐야만 사람 이름이 들어간다
- 운영자 입력 화면이 무엇을 묻는 도구인지 말한다 (일정·순서·환경. 사람이 아니다)

### 실시간 집계는 **이 규칙에 기대고 있다**

집계를 실시간으로 보여주기로 한 근거가 여기 있다 — 묻는 대상이 *일정·음악·게임*이라
소수 쪽에 서는 게 아프지 않다. **사람을 묻기 시작하면 실시간 집계는 그 자리에서 흉기가 된다.**
`27 대 1` 이 누구에 대한 숫자냐가 전부다.

**두 결정은 한 몸이다.** 사람 규칙을 풀 일이 생기면 실시간 집계부터 다시 봐야 한다.

---

## ADR-4 의 예외는 **"알림"이 아니라 "보낸 것"이다**

`noticesOf(state)` 는 상태에서 소식을 **파생시키는 순수 함수**다. 그 성질은 그대로 둔다.

| | |
|---|---|
| **저장한다** | 운영자가 쓴 글 · 투표 선택지 · 참가자의 표 |
| **파생시킨다** | 소식 줄 — `noticesOf()` 는 여전히 순수하다 |
| **여전히 없다** | 읽음 플래그 · 알림 테이블 |

ADR-4 가 지키려던 성질도 남는다 — *"되돌리면 알림이 알아서 바뀐다."*
운영자가 알림을 지우면 소식 줄도 알아서 사라진다. 상태가 하나뿐이라 모순이 없다.

**참가자의 표는 `자리 확인(ackSeat)` 과 같은 모양이다** — 참가자당 응답 하나가 회차 DO 에 쌓이고
운영자가 집계를 본다. 새 개념이 아니다.

**이름을 겹치게 짓지 마라.** 기존 `Notice` 는 *파생된 소식 줄*이다.
운영자가 만든 것은 다른 이름을 쓰고(`Announcement`), 그것이 `Notice` 를 **만들어낸다.**

## 범위

**만든다**

| | |
|---|---|
| 텍스트 알림 — 한 칸 | 제목은 고정. 파티 중 운영자에게 두 칸은 부담이다 |
| A/B 투표 — 질문 한 칸 + 선택지 두 칸 | 실시간 집계. 운영자가 닫는다 |
| 배너 **3분** · 소식 목록에 계속 | 기존 창을 그대로 쓴다. 새 장치를 만들지 않는다 |
| 알림은 **쌓인다**. 지울 수 있다 | 와이파이 비번을 2부 공지가 덮으면 안 된다 |
| **열린 투표는 한 번에 하나** | 새 투표를 올리면 앞엣것이 닫힌다 |

**안 만든다**

- **푸시.** iOS 는 홈 화면에 추가한 사람만 받아 절반짜리가 된다.
  앱으로 돌아올 때 다시 읽는 구조가 이미 그 자리를 맡는다 (ADR-26)
- **개인에게 보내기.** 익명 채팅의 입구다 — 전원에게 같은 글 하나뿐이다
- **선택지 3개 이상.** A/B 다. 늘리면 화면이 목록이 되고, 파티 중에 읽을 게 늘어난다
- **읽음 표시·읽은 사람 수.** 안 읽은 사람을 세는 순간 운영자가 사람을 쫓게 된다
- **배너 안에서 투표하기.** 배너는 3분 뒤 사라진다 — 사라지는 것 위에 손가락을 올리게 하지 않는다

---

## A. 텍스트 알림

### S-A1 ★ 쓰면 전원의 소식에 뜬다
```
When   운영자가 한 칸에 쓰고 보낸다
Then   참가자 소식 맨 위에 📢 로 뜨고, 3분 안이면 배너로도 뜬다
```
> 전달은 기존 방송(ADR-26) 하나다 — "다시 읽어라" 만 보내고 참가자가 다시 읽는다.
> **자리를 비웠던 사람은 앱으로 돌아오는 순간 본다.** 푸시가 필요 없는 이유가 이것이다.

### S-A2 ★ 줄바꿈이 살아 있다
```
Given  "와이파이 TONE\n비번 12341234" 를 보냈다
Then   두 줄로 보인다
```
> 와이파이 비번은 줄을 나누는 게 읽힌다. 이미 `pre` 가 있다.

### S-A3 ★ 지우면 소식에서도 사라진다
```
When   운영자가 지운다
Then   참가자 소식에서 없어진다
```
> 틀린 비번이 파티 끝까지 남으면 안 된다. **파생이라 지우기만 하면 화면이 따라온다** —
> 지운 것을 따로 표시하거나 "취소된 알림" 을 남기지 않는다.

---

## B. A/B 투표

### S-B1 ★ 참가자는 한 번만 고른다. 바꿀 수는 있다
```
When   A 를 고른 뒤 B 를 고른다
Then   표는 하나이고 B 로 옮겨간다
```
> 두 번 눌러 두 표가 되면 집계가 거짓말이 된다. 콕과 달리 **표는 사람당 하나**다.

### S-B2 ★ 집계가 실시간으로 보인다
```
Then   내가 고르면 그 자리에서 숫자가 오른다
```
> **누가 무엇을 골랐는지는 어디에도 없다.** 응답에 담기는 건 숫자 둘과 *내* 선택뿐이다.
> 위의 사람 규칙과 함께 읽어야 한다 — 사람을 묻지 않기 때문에 숫자를 열 수 있다.

### S-B3 ★ 닫으면 더 못 고른다. 숫자는 남는다
```
When   운영자가 닫는다
Then   선택 버튼이 사라지고 결과만 남는다
```
> 시간으로 자동으로 닫지 않는다. **사람이 다 왔는지, 다 골랐는지는 시계가 모른다** (ADR-14).
> 파티 당일의 전환은 전부 운영자가 누른다.

### S-B4 ★ 새 투표를 올리면 앞엣것이 닫힌다
```
Given  투표 하나가 열려 있다
When   운영자가 새 투표를 올린다
Then   앞엣것이 닫히고, 열린 투표는 늘 하나다
```
> 둘이 동시에 열려 있으면 참가자는 무엇에 답해야 하는지, 운영자는 어느 집계를 보는지 헷갈린다.

### S-B5 투표도 소식에 남는다
```
Then   닫힌 뒤에도 질문과 결과가 소식 목록에 있다
```
> "2부 9시로 정해졌다" 를 나중에 확인할 수 있어야 한다.

---

## C. 운영자 화면

### S-C1 현황 탭에서 보낸다
> 파티 중 운영자가 이미 서 있는 자리다 (단계 넘기는 버튼이 거기 있다).
> **탭을 새로 만들지 않는다** — 파티 중에 찾아 들어가야 하는 화면을 늘리지 않는다.

### S-C2 ★ 지우기 확인창이 **무엇이 사라지는지 숫자로** 말한다
```
Then   "표 18개가 함께 사라져요" 같은 줄이 있다
```
> 투표를 지우면 모아둔 표가 함께 없어진다. 되돌릴 수 없는 행동이라 확인이 붙고,
> 확인창은 무엇이 어떻게 바뀌는지 숫자로 보여준다.
> 닫기·다시 열기는 **되돌릴 수 있으므로 확인을 붙이지 않는다.**

## 문구

`copy.ts` 에 넣는다. **"공지" 대신 "알림"** 으로 쓴다 — 운영자가 보내는 것이 텍스트만이 아니라
투표까지라, "공지" 는 절반만 가리키는 말이 된다.

| 자리 | 뜻 |
|---|---|
| 소식 줄 제목 (텍스트) | 운영자 알림 |
| 소식 줄 제목 (투표) | 운영자 투표 |
| 운영자 입력 안내 | 참가자 전원이 봅니다 |
| 투표 입력 안내 | **사람을 묻지 마세요.** 일정·순서·환경을 묻는 자리예요 |
| 투표 닫힘 표시 | 마감됐어요 |

마지막 두 줄이 이 슬라이스에서 가장 중요한 문구다. **코드가 못 막는 것을 문장이 막는다.**
