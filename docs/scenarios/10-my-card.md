# 슬라이스 10 — 참가자 탭의 내 카드

참가자 탭 맨 위, **필터 위에** 내가 남들에게 어떻게 보이는지를 다른 카드와 같은 모양으로 둔다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 범위

**만든다** — 참가자 탭 맨 위의 내 카드. 남들이 보는 것만 보여준다.

**안 만든다** — 서버 변경, 내 정보 탭의 미리보기, 자기 카드 눌러서 여는 시트,
자기 자신에게 콕. `toPublic()` 을 화면에서 다시 구현하는 것.
**요청받지 않은 기능을 미리 만들지 마라.**

---

## 왜

### 숫자가 어긋나 있었다
상단 인원수(`playerCount`)는 `SELECT COUNT(*)` 라 자기를 포함하는데, 명단(`roster`)은
서버에서 `.filter(p => p.id !== playerId)` 로 자기를 뺀다. **10명인데 9장**이었다.
등록 직후 혼자일 때는 "1명" 옆에 빈 화면이 뜬다.

### 고칠 수 있게 됐는데 확인할 자리가 없었다
ADR-31 로 등록 정보를 고칠 수 있게 됐지만, 매력 세 줄을 고치고 나서
그게 카드에서 어떻게 읽히는지 볼 방법이 없었다. 명단은 단계마다 열리는 만큼만 보이는데
(ADR-21) 참가자는 자기가 지금 어디까지 보이는지도 알 수 없었다.

---

## A. 무엇을 보여주나

### S-A1 ★ 남들이 보는 것만 보여준다
```
Given  회차가 사전 투표 단계다
When   참가자 탭을 연다
Then   맨 위 내 카드에 닉네임과 매력이 있다
And    나이·MBTI 는 없다 — 그 단계에 남들도 못 보기 때문이다
And    실명·전화번호·인스타는 어느 단계에도 없다
```
> 이 카드가 답하는 건 "내가 어떻게 보이나" 다. 내가 낸 것 전부는 **내 정보 탭**에 있다.

### S-A2 ★ 파티가 시작되면 나이와 MBTI 도 함께 보인다
```
Given  회차가 파티 단계다
Then   내 카드에 나이와 MBTI 가 있다
```

### S-A3 ★ 등록 중에는 **사전 투표 때 모습**을 미리 보여준다
```
Given  회차가 등록 중이다
Then   내 카드가 보인다 (남의 명단은 여전히 비어 있다)
And    나이·MBTI 는 없다
```
> **`toPublic(me, phase)` 를 그대로 부르면 틀린다.** 그 함수는 `prevote` 에서만
> 나이·MBTI 를 빼므로 등록 중에 부르면 나이가 나오는데, 정작 사전 투표에서는 안 보인다.
> "이렇게 보여요" 라고 말하는 자리에서 그러면 거짓말이 된다 —
> **남들이 나를 처음 보게 되는 상태**로 바꿔서 부른다.

### S-A4 아직 안 보이는 것을 말해준다
```
Given  나이·MBTI 가 아직 안 열린 단계다
Then   "나이·MBTI 는 파티가 시작돼야 보여요" 가 카드 아래 있다
```
> 빈자리를 그냥 두면 "내가 안 냈나" 로 읽힌다.

### S-A5 등록 중에는 문장이 다르다
```
Given  회차가 등록 중이다 — 아직 아무도 나를 못 본다
Then   "사전 투표가 열리면 이렇게 보여요" 다
When   사전 투표가 시작된다
Then   "다른 사람에게는 이렇게 보여요" 로 바뀐다
```

---

## B. 목록에서 어떻게 있나

### S-B1 ★ 맨 위, 필터보다도 위에 있다
```
Then   [내 카드] → [전체 | 이성만] → [남들 목록] 순서다
```
> 스무 명 목록 가운데에 있으면 확인이라는 목적이 사라진다.
> 그리고 **거르는 버튼은 걸러지는 것 바로 위**에 있어야 한다 — 한동안 내 카드가
> 필터와 목록 사이에 있었는데, `이성만` 을 눌러도 내가 남아 있으니
> 필터가 안 먹은 것으로 읽혔다.

### S-B2 ★ `이성만 보기` 에서도 사라지지 않는다
```
Given  이성만 보기를 켰다
Then   내 카드는 그대로 있다
```
> 필터 밖이라 자동으로 그렇다. 감추고 남은 콕만 어딘가에 따로 남기는 길로 가지 마라 —
> 그 숫자가 두 집 살림을 하게 된다.

### S-B2a ★ 이성이 0명이어도 필터는 남는다
```
Given  명단에 나와 같은 성별만 있다
When   이성만 보기를 켠다
Then   목록은 비지만 필터는 그대로 있다 — 전체로 돌아갈 수 있다
```
> 거를 게 없으면 필터를 감추되, 판단은 **거르기 전 명단**으로 한다.
> 걸러진 결과가 0명이라고 감추면 돌아갈 버튼째 사라져 화면이 잠긴다.

### S-B2b ★ 누르면 내 정보 탭으로 간다
```
When   내 카드를 누른다
Then   내 정보 탭으로 이동한다
```
> 남들 카드는 눌러서 프로필 시트를 연다. 내 카드로는 그 시트를 열 수 없고
> (시트는 `roster` 에서 상대를 찾는데 거기 나는 없다), 혼자 안 눌리면
> 매력 전문과 내가 낸 것 전부가 어디 있는지 알 길이 없다.
> 이동은 `onTab` 을 통한다 — 뒤로 가기 규칙이 거기 한 곳에 있다.

### S-B3 ★ 콕 버튼이 없다
```
Then   내 카드에는 콕 버튼이 없다 — 비활성이 아니라 아예 없다
```
> 자기를 못 찌르는 건 설명할 일이 아니다. 서버도 자기 자신은 어떤 설정에서도 막는다.

### S-B4 "나" 를 글자로 말한다
```
Then   내 카드에 "나" 가 글자로 있다
```
> 색·테두리만으로 구분하지 않는다. 그리고 **매칭 색(`--accent`)을 쓰지 않는다** —
> 목록에서 가장 눈에 띄어야 하는 건 서로 찌른 사람이다.

### S-B5 남의 명단이 비어도 내 카드는 있다
```
Given  회차가 등록 중이라 남의 명단이 비어 있다
Then   내 카드는 보이고, "사전 투표가 열리면 참가자를 볼 수 있어요" 도 그대로 있다
```
> 그 문구는 **남들에 대한 말**이라 내 카드가 생겼다고 지우지 않는다.

---

## C. 경계는 그대로다

### S-C1 ★ 서버 응답은 하나도 바뀌지 않는다
```
Then   참가자 응답에 새로 나가는 값이 없다
And    roster 는 여전히 남들만 담는다
```
> 화면이 이미 받은 `me` 를 `toPublic()` **같은 함수**로 줄여 그린다.
> 규칙을 화면에서 다시 짜면 두 곳이 갈라지고, 하필 "이렇게 보여요" 라고 말하는 자리라
> 갈라지는 순간 거짓말이 된다.
