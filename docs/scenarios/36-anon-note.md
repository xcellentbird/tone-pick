# 슬라이스 36 — 익명 쪽지: 익명으로 보내고, 답장은 없다

운영자가 요청했다: *익명 메시지 기능을 추가하려 합니다. 회차 운영자 설정을 통해 한 명당 쓸 수 있는
메시지 수 제한을 두면 좋겠습니다.*

이 앱에서 그 기능의 이름은 **익명 쪽지**다. 화면에서는 늘 이 네 글자로 부른다 — `쪽지` 로 줄이지 않는다.
`메시지` 는 초대 문자에 이미 쓰는 말이고(UI.md), `알림` 은 운영자가 보내는 것이다.
`익명` 은 새 낱말이 아니다 — 도움말이 이미 `상대에게는 익명으로 알림이 가요` 라고 말하고 있다.
이름이 기능을 설명하게 두면 화면에서 그 말을 다시 할 필요가 없다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 운영자가 정한 것

초안(v1)이 다섯을 추천했고 운영자가 둘을 바꿨다. 그 뒤 화면 시안을 보고 다섯을 더 고쳤다 (ADR-98 후기 1·2).
**아래가 확정이다.**

| | 확정 | |
|---|---|---|
| 언제 보내나 | **파티 시작 ~ 발표** (파티 콕과 같은 창) | v1 |
| 몇 장 | 회차 설정 `익명 쪽지`(0~5), 기본 2. **0 이면 이 회차에는 없다** | v1 |
| 같은 사람에게 | **여러 장** — 횟수 안에서 | 후기 1 |
| 누구에게 | **누구에게나.** 동성 콕 설정과 무관하다. 자기 자신만 안 된다 | 후기 1 |
| 발신자 | **끝까지 익명.** 발표 뒤에도, 서로 콕 찌른 쌍에게도 | v1 |
| **운영자가 보는 것** | **보낸 장 수뿐.** 본문도, 누가 누구에게 보냈는지도 못 본다 | 후기 2 |
| **보낸 사람이 보는 것** | 내가 보낸 **본문**과 `읽음`/`읽지 않음` | 후기 2 |
| **남은 장 수** | 버튼 **안**에 (`익명 쪽지 쓰기 · 2장 남음`) | 후기 2 |
| **작성 화면** | 제목·칸·버튼뿐. 글자수 안내도 하단 문구도 없다 | 후기 2 |
| 이름 | **익명 쪽지** — 이름이 기능을 설명한다 | 후기 2 |

## 왜 채팅이 아닌가 — 그리고 원칙 1

이 앱의 존재 이유는 **거절의 경험을 만들지 않는 것**이다 (원칙 1). 익명 쪽지는 일방적인 마음을 글로
실어 나르는 물건이라 그 원칙과 가장 가까이 부딪힌다. 셋으로 지킨다.

1. **답장이 없다.** 받은 쪽은 읽을 뿐이고, 아무것도 하지 않아도 된다 — 거절이라는 **행동**이 없다.
   보내는 쪽도 지킨다: 답이 올 길이 없으니 안 온 답을 기다리지 않는다. 반응 버튼도 없다
2. **끝까지 익명이다.** 피할 얼굴이 없다. 발표 뒤에 열리는 건 서로 콕 찌른 쌍의 실명 하나다 (ADR-42)
3. **본문은 두 사람만 본다.** 운영자도 못 본다 (ADR-98 후기 2)

그리고 셋을 관통하는 규칙이 하나 — **받는 사람이 고르는 것은 발신자에게 돌아가지 않는다.**
읽음 표시가 그 규칙의 시험대다. 읽음은 고르는 것이 아니라 **앱을 연 결과**라 통과하고,
반응 버튼은 고르는 것이라 통과하지 못한다. 지우는 것도 고르는 것이라 발신자에게 안 간다.

같은 사람에게 여러 장을 보낼 수 있어도 대화가 되지는 않는다 — 돌아오는 것이 없다. 뒤쫓기는 **상한**이
막는다: 한 사람이 쓸 수 있는 장 수(최대 5)가 곧 한 사람에게 갈 수 있는 최대다.

## 범위

**만든다**

| | |
|---|---|
| 보내기 | 참가자 탭 → 카드 → **프로필 시트**의 `익명 쪽지 쓰기 · N장 남음` → 작성 시트 → 확인창 → 보냄 |
| 보낸 것 확인 | 프로필 시트의 `내가 보낸 익명 쪽지` — 본문과 `읽음`/`읽지 않음` |
| 받기 | 홈의 소식 줄에 **한 장씩**, 본문 그대로. 시각 없음, 배너 없음, 움직임 없음 |
| 지우기 | **받는 사람**이 자기 소식 줄에서 지운다. 발신자에게는 아무것도 안 간다 |
| 남은 장 수 | 버튼 안 + 홈 할 일 카드의 kicker |
| 회차 설정 | `익명 쪽지 (0~5)` — 위저드 3단계 · 설정 탭 · 운영자 기본값. **0 으로는 언제나 내려간다** |
| 운영자 | 참가자 상세에 `보낸 익명 쪽지 N장` 한 줄. 그게 전부다 |
| 도움말 | 문답 하나 — `익명 쪽지는 누가 보낸 건지 알 수 있나요?` |

**안 만든다**

- **답장 · 대화 · 반응.** 어떤 모양으로도. 이게 익명 쪽지와 채팅의 경계다
- **발신자 공개.** 발표 뒤에도, 서로 콕 찌른 쌍에게도. `MatchInfo` 에 자리가 없다
- **운영자의 본문 열람 · 쌍 열람 · 지우기.** 콘솔에 본문이 뜨는 순간 누가 누구를 좋아하는지가 적힌다
- **보낸 것 되돌리기.** 보내면 끝이다 — 확인창이 그 사실을 말한다
- **읽은 시각.** `읽음` 이지 `21:05에 읽음` 이 아니다. 읽음 전환을 broadcast 하지도 않는다
- **매력 투표 중 · 발표 뒤 보내기.** 파티 콕의 창과 같다
- **참가자 탭 목록의 버튼·표시.** 입구는 프로필 시트 하나다
- **자리 · 매칭에 닿는 것.** `buildSeating` 입력에 없고, 매칭은 여전히 파티 콕만 센다
- **콕 로그 파일에 쌓는 것.** 본문은 회차 DO 밖으로 안 나간다 — 예외는 콕 로그 하나뿐이다 (ADR-84)
- **현황 탭의 숫자 · 순위.** 받은 장 수는 어느 응답에도 없다
- **지표.** `pulse` 에 익명 쪽지를 더하지 않는다 (ADR-56 · 58)
- **푸시 알림.** 앱으로 돌아올 때 다시 읽는 구조가 그 자리다 (ADR-26)

**아직 답이 없는 자리 — 한 사람에게 몰리는 것**

상한은 **발신자당**이라 한 사람에게 가는 것을 못 막는다. 다섯 명이 한 사람에게 보내면 열 장이고
아무도 상한을 어기지 않았다. 콕에는 대응물이 있다 — `hostState` 가 받은 수를 싣고 현황 탭의
`받은 콕 TOP` 이 몰림을 운영자에게 보여 준다. 익명 쪽지는 그 필드를 통째로 뺐으므로
**피해자가 입으로 말하기 전에는 아무도 모른다.**

받은 장 수를 운영자에게 다시 여는 것은 이 결정을 되돌리는 일이라 하지 않았다. 대신 **받는 쪽에
`익명 쪽지 그만 받기` 를 주는 길**이 있다 — 켜면 새 쪽지가 조용히 버려지고, 발신자에게는 보낸 것으로
보이며 예산도 그대로 빠진다(영영 `읽지 않음`). 발신자에게 아무 신호도 안 가므로 관통 규칙을 안 깬다.
**참가자 설정이 하나 느는 일이라 운영자에게 묻고 정한다** — 지금 범위 밖이다.

## A. 보내기

### S-A1 ★ 파티 중에만 보낸다
```
Given  단계가 등록·매력 투표·발표 뒤다
When   익명 쪽지를 보낸다
Then   409 closed. 파티 중에만 200
```

### S-A2 ★ 횟수는 회차 설정이 정한다 — 0 이면 길 자체가 없다
```
Given  maxNotes: 2
Then   두 장까지 200, 셋째는 409 no_budget
Given  maxNotes: 0 (옛 회차처럼 값이 없는 것도 0 이다)
Then   첫 장부터 409 — 화면에는 버튼도, 남은 장 수도, 도움말 문답도 없다
```

### S-A3 ★ 같은 사람에게 여러 장 — 횟수 안에서
```
Given  maxNotes: 2. A 가 B 에게 한 장 보냈다
When   A 가 B 에게 또 보낸다
Then   200. 셋째는 누구에게든 409 no_budget
And    B 의 소식에는 두 줄이 따로 선다 — 합쳐서 `2장` 으로 세지 않는다
```

### S-A4 ★ 대상은 누구에게나 — 동성 콕 설정과 무관
```
Given  allowSameGender: false 인 회차
When   A(남) 가 C(남) 에게 익명 쪽지를 보낸다
Then   200 — 콕이면 409 였을 자리다
When   A 가 A 에게 보낸다
Then   400
```

### S-A5 ★ 120자까지, 글자만
> 비면 400, 넘치면 400. 줄바꿈은 그대로 두고(`pre`), 링크를 눌리게 만들지 않는다.
> **화면은 글자수를 말하지 않는다** — `maxLength` 가 조용히 막는다.

### S-A6 확인창은 무엇이 어떻게 바뀌는지 말한다 (CLAUDE.md 4)
> `받는 사람 · 달빛` / `남은 익명 쪽지 · 2장 → 1장`. 문단은 `보낸 뒤에는 되돌릴 수 없어요.`
> 이미 보낸 사람에게는 제목이 `한 장 더 보낼까요?` 다.

## B. 보낸 쪽 — 본문과 읽음

### S-B1 ★ 내가 보낸 본문은 프로필 시트에서 다시 볼 수 있다
```
Given  A 가 B 에게 두 장 보냈다
When   A 가 B 의 프로필 시트를 연다
Then   `내가 보낸 익명 쪽지` 에 두 줄, 각각 본문과 `읽음` 또는 `읽지 않음`
And    C 의 프로필 시트에는 그 묶음이 없다 — 보낸 적이 없다
```

### S-B2 ★ 읽음은 고르는 것이 아니다 — 그리고 **덮개 뒤에서는 안 선다**
```
Given  A → B 쪽지. B 는 아직 앱을 안 열었다
Then   A 에게 `읽지 않음`
When   B 가 홈을 연다 (소식 줄이 화면에 뜬다)
Then   B 가 무엇을 누르지 않아도 `읽음` 이 된다
And    B 화면에는 읽음 상태가 아예 안 보인다 — 알아야 할 사람은 보낸 쪽이다
Given  B 화면을 자리 확인(`SeatTakeover`)이나 단계 안내(`StageTakeover`)가 덮고 있다
Then   그 아래에서 홈이 그려지고 있어도 **읽음으로 치지 않는다**
Given  B 가 어깨너머 가리기를 켜 두어 본문이 안 보인다
Then   그것도 **읽음으로 치지 않는다** — 제목만 보이는 것은 읽은 것이 아니다
```
> ⚠️ **덮개는 홈을 가리지만 언마운트하지 않는다** (`Participant.tsx` 의 `{tab === "home" && <Home/>}` 이
> 덮개와 나란히 산다). 그대로 두면 **본문을 볼 수 없는 사람이 읽은 것으로 찍힌다** —
> 배지가 말하는 것과 코드가 재는 것이 갈리는 순간 `문구가 코드보다 넓게 말하면 거짓말` 에 걸린다.
> 판정에 `!needsSeatAck && !needsStage` 를 함께 건다.
>
> 반대쪽(파티 내내 참가자 탭에만 머문 사람이 영영 `읽지 않음`)은 **거짓이 아니다** — 그 사람은
> 정말 그 글을 안 봤다. 고칠 것이 없다.

### S-B3 ★ 지워도 발신자 화면은 그대로다
```
Given  A → B 쪽지, B 가 읽었다
When   B 가 그 쪽지를 지운다
Then   A 에게는 계속 `읽음`. 지웠다는 것이 어디에도 안 간다
Given  B 가 가리기를 켠 채(제목만 보고) 지웠다
Then   A 에게는 계속 `읽지 않음` — **앱을 안 연 것과 구별되지 않는다**
```
> 이것이 읽음 표시가 거절 신호가 되지 않게 하는 장치다. `읽지 않음` 이 뜻하는 것은 하나뿐이다.
>
> ⚠️ **안 읽고 지우는 길이 화면에 실제로 있어야 한다.** 본문이 소식 줄에 펼쳐져 있고 그것이
> 뜨는 순간 읽음이 서면, `지우기` 를 누르려면 **반드시 읽음을 지나야 한다** — 괴롭히는 쪽은
> 언제나 `읽음` 을 받고 이 장치는 글로만 남는다. 가리기가 그 길이다(S-B2): 켜면 제목만 보이고,
> 제목만 본 것은 읽은 것이 아니다.

### S-B4 ★ 읽음 배지는 **시트를 연 순간의 값으로 굳는다**
```
Given  A 가 B 의 프로필 시트를 열어 두고 있다 (`읽지 않음`)
When   B 가 홈을 열어 읽음이 서고, 그 사이 A 화면이 어떤 이유로든 다시 읽힌다
Then   A 의 배지는 시트를 **닫았다 다시 열 때까지** 안 바뀐다
```
> 남이 일으킨 변화에 움직임을 넣지 않는다 (ADR-64). 그리고 실시간으로 바뀌면 **그 순간 누가 폰을
> 보고 있었는지**와 맞출 수 있다 — 받은 콕에 시각을 안 붙이는 것과 같은 이유다.
>
> ⚠️ **`broadcast` 를 안 하는 것만으로는 모자라다.** `realtime.ts` 는 화면이 다시 보일 때마다
> 소켓을 다시 붙이고, `Participant.tsx` 가 그 신호로 `reload()` 를 부른다 — 공지·설문·자리 발행·
> 단계 전환의 신호도 같은 재조회를 태운다. 그래서 **발신자 화면은 가만히 있어도 최신값을 받는다.**
> 막는 자리는 소켓이 아니라 **시트**다: 열 때 읽음 값을 한 번 읽고 그 값으로 그린다.
> 닫았다 다시 여는 것은 A 가 고른 행동이라, 거기까지는 준다.
>
> ⚠️ **화면만으로는 폴링을 못 막는다.** 여닫을 때마다 새 값이 오므로 30초마다 열면 읽은 시각이
> 30초까지 좁혀진다 — `21:05에 읽음` 을 버린 이유가 절반쯤 되살아나고, 그건 곧
> **저 사람이 방금 앱을 열었다**를 아는 것이다. 시끄럽고 어두운 자리에서 발신자는 상대가 누군지
> 이미 안다. 고개만 들면 된다.
>
> **그래서 서버가 늦춘다** (아래 S-B6).
>
> ⚠️ **작성 시트에서 돌아오는 길은 '다시 여는 것'이다.** 방금 보낸 줄이 안 보이면 보낸 사람이
> 안 갔다고 읽는다 — 굳히는 값을 `참가자 아이디` 하나에만 묶으면 그 줄이 안 뜬다.
> 작성 시트가 닫히는 것도 다시 여는 것으로 세라 (F3 의 *시트는 겹치지 않는다* 와 한 몸이다).

### S-B6 ★ 읽음은 **5분이 지나야 발신자에게 보인다**
```
Given  A → B 쪽지. B 가 방금 홈을 열어 읽음이 섰다
When   A 가 곧바로 프로필 시트를 연다
Then   아직 `읽지 않음`
When   5분이 지난 뒤 A 가 다시 연다
Then   `읽음`
```
> 서버는 읽은 시각(`read_at`)을 적되 **응답의 `read` 는 `now - read_at > 5분` 일 때만 참**이다.
> 배지가 답하는 질문은 *갔고 봤나* 이지 *지금 보고 있나* 가 아니다 — 늦춰도 그 답은 그대로고,
> **지금 보고 있다** 만 사라진다. 답장이 없으니 늦게 알아도 잃을 것이 없다.
>
> 이것이 첫 관점이 *읽음을 아예 빼라* 고 한 자리에 대한 답이다. 관찰(화면만으로는 실시간 전환을
> 못 막는다)은 맞았고, 요청받은 것을 없애는 대신 **신호를 무디게** 했다.
> ⚠️ 5분 동안은 `읽지 않음` 이 사실과 다르다. **코드가 문구보다 좁게 말하는 쪽**이라 안전하고
> (넓게 말하는 것이 거짓말이다), 5분 뒤에 스스로 맞는다.

### S-B5 ★ 가리기 중에는 묶음도 **쓰기 버튼도** 잠긴다
```
Given  어깨너머 가리기가 켜져 있다
When   달빛의 프로필 시트를 연다
Then   `내가 보낸 익명 쪽지` 묶음이 없고, `익명 쪽지 쓰기` 는 눌리지 않는다
When   `/e/:code/p/:pid/note` 를 주소로 직접 연다
Then   프로필 시트로 갈아끼운다
```
> 묶음만 감추면 모자라다 — 버튼을 누르면 시트 제목과 확인창이 상대 이름을 말하고 그 사이 내내 글을 친다.
> **콕 한 번보다 훨씬 오래 드러난다.**

## C. 받는 쪽

### S-C1 ★ 발신자는 어느 응답에도 없다 — 발표 뒤에도
```
Given  A 가 B 에게 보냈다. 발표까지 지났고 둘은 서로 콕을 찔렀다
When   B 가 `/api/me` 를 읽는다
Then   받은 쪽지에 `fromId` 도 닉네임도 성별도 없다 — 본문과 아이디와 순서뿐이다
And    명단(`roster`)·`MatchInfo` 어디에도 익명 쪽지가 없다
```

### S-C2 ★ 시각이 없고 배너로 뜨지 않는다
> 받은 콕과 같다 (`at: 0`, `order` 는 파티가 시작된 순간 + 차례). 여러 장이면 위가 최신이다 (ADR-48).
> **진짜 도착 시각을 순서에도 쓰지 마라** (notices.ts 의 경고 그대로).

### S-C3 ★ 누를 수 있는 것은 지우기 하나다 — 그리고 **발신자 화면은 한 칸도 안 바뀐다**
```
Given  받은 익명 쪽지 한 장
Then   답장·반응·신고 버튼 어느 것도 없다. `지우기` 하나뿐이다
When   지우기를 누른다
Then   확인창 — 항목은 `이 쪽지 · 사라져요` 하나. 문단이 상대에게 안 간다는 것을 말한다
And    지우면 그 줄이 사라지는 것이 곧 알림이다 (토스트 없음, ADR-65)
When   그 뒤 발신자가 `/api/me` 를 읽는다
Then   `budget` 도 `sent` 도 `read` 도 **지우기 전과 똑같다**
```
> ⚠️ **행을 지우면 안 된다.** 이 저장소의 관용구는 행 세기다 — `sentCount()` 가
> `SELECT COUNT(*) FROM pokes WHERE from_id = ?` 이고, 참가자를 지울 때 `DELETE ... WHERE to_id = ?` 로
> 찌른 사람의 예산이 **실제로 돌아온다**. 같은 꼴로 짜면 받는 사람이 지우는 순간 발신자 화면에
> `1장 남음` → `2장 남음` 이 뜨고 보낸 줄이 사라진다 — **상대가 내 쪽지를 지웠다** 로만 읽히고,
> 그건 `읽지 않음` 보다 훨씬 또렷한 거절 신호다. 읽음을 정당화한 규칙이 바로 그 자리에서 깨진다.
>
> 그래서 `hidden_at` 만 찍는다. 받는 사람 응답(`received`)에서만 거르고 `sent`·`budget.used`·`read_at` 은
> 건드리지 않는다. **참가자를 지울 때도 같다** — `to_id` 줄을 지우지 않고 본문만 비운다(`body = ''`,
> `hidden_at`). 예산도 돌아가지 않는다. 콕과 반대 방향이고, 이유는 S-E1 에 있다.
>
> *(2026-09-24 고침 — 처음 이 자리에는 "참가자를 지울 때는 `to_id` 줄을 진짜로 지우고 예산도 돌아간다
> (콕과 같다)" 고 적혀 있었다. 그 뒤 S-E1 이 뒤집었고 코드도 S-E1 을 따른다.)*

### S-C4 움직임이 없다 (ADR-64)
> broadcast 로 오는 것이라 그냥 나타난다. 옆 사람이 그 순간을 알면 안 된다.

## D. 운영자

### S-D1 ★ 운영자는 본문도 상대도 못 본다
```
Given  A → B 익명 쪽지
When   운영자가 A 의 상세를 연다
Then   `보낸 익명 쪽지 1장` 한 줄뿐이다 — 본문도, `→ B` 도 없다
When   운영자가 B 의 상세를 연다
Then   받은 장 수조차 없다
And    `hostState` 응답에 본문도 쌍도 받은 수도 없다 (개발자 도구로 열어도)
```
> 원칙 2 의 예외는 이미 있었다 — `hostState` 는 **한쪽만 찌른 콕을 안 싣는다**.
> 익명 쪽지 본문은 같은 종류라 그 예외에 들어간다 (ADR-98 후기 2).

### S-D2 ★ 0 으로는 언제나 내려간다
```
Given  이미 3장 보낸 참가자가 있다 (maxNotes: 5)
When   운영자가 4 로 내린다
Then   409 conflict — 이미 쓴 장 수가 바닥이다
When   운영자가 0 으로 내린다
Then   200. 이 회차의 익명 쪽지가 닫힌다 — 버튼도 kicker 도 도움말 문답도 사라진다
And    이미 온 쪽지는 소식에 그대로 남는다
```
> **0 은 바닥에 걸리지 않는다.** 걸리면 꺼야 할 때 못 끈다 — 운영자의 유일한 레버다.
> 1~5 사이에서만 이미 쓴 장 수가 바닥이다 (콕 횟수와 같은 규칙).

### S-D3 회차 설정
> `익명 쪽지 (0~5)` 는 위저드 3단계 규칙 묶음 **맨 끝**, 설정 탭 같은 자리, 운영자 기본값 화면에 선다.
> 굳지 않는다 — 콕 횟수처럼 파티 중에 올릴 수 있다 (ADR-35).

## E. 삭제 · 발표 · 자리

### S-E1 ★ 참가자를 지워도 **발신자의 장 수는 안 줄어든다**
```
Given  A → B, A → C 익명 쪽지 (A 는 2장을 다 썼다)
When   운영자가 A 를 지운다
Then   B·C 의 소식에 그 줄이 그대로 있다. A 가 받은 쪽지는 함께 사라진다
When   운영자가 B 를 지운다
Then   A → B 의 본문은 사라지지만 A 의 `보낸 익명 쪽지` 는 **2장 그대로다**
And    A 의 `budget.used` 도 그대로다 (다시 보낼 수 있게 되지 않는다)
```
> ⚠️ **콕과 다르다.** 콕은 받은 사람을 지우면 행을 지우고 찌른 사람의 예산을 돌려준다
> (*없는 사람에게 쓴 횟수를 물릴 이유가 없다*). 익명 쪽지에 그대로 쓰면 사고가 난다 —
> **신고한 사람을 내보내는 것이 운영자의 첫 동작**이라, B 를 내보내는 순간 운영자 화면에서
> A 의 `보낸 익명 쪽지` 가 2장 → 1장이 된다. 기본 2장짜리 회차에서는 그 한 번으로 **발신자가
> 한 명까지 좁혀진다** — 개정안이 적은 대가(*실마리는 보낸 장 수뿐*)를 넘는다.
>
> 저장소는 같은 모양의 사고를 콕에서 이미 겪고 문장으로 박아 뒀다 (`DELETE_PLAYER.note`:
> *받은 쪽 숫자가 줄면 누가 골랐는지 드러나거든요*). 방향만 반대다.
>
> 그래서 **본문만 비우고 행은 남긴다** (`body = ''`, `hidden_at`). 사람은 지워지고, 발신자가
> 보던 숫자는 안 흔들린다.
>
> ⚠️ **예산을 돌려주면 재장전이 된다.** 콕은 받은 사람을 지울 때 *없는 사람에게 쓴 횟수를 물릴
> 이유가 없다* 며 예산을 돌려준다. 익명 쪽지에 그대로 쓰면, **가해자를 못 찾은 채 피해자를
> 내보내는 것**(당일 가장 흔한 조치)이 가해자에게 두 장을 되돌려 주고 그는 다른 사람에게 다시 쓴다.
> 운영자는 본문도 상대도 못 보므로 **자기가 무엇을 되돌려 줬는지조차 모른다.**
> 쪽지는 이미 전달된 말이다 — 돌려주지 않는다.

### S-E2 ★ 발표 뒤에는 닫히고, 받은 것은 읽힌다
```
Given  파티 중에 A → B 쪽지. 발표가 지났다
Then   B 의 소식에 그대로 있다 — 발표가 지운 것이 아니다
When   C 가 D 에게 새로 보낸다
Then   409 closed. 프로필 시트의 버튼도, 홈의 kicker 도 사라진다
And    `내가 보낸 익명 쪽지` 묶음은 남는다 — 보낸 것을 되볼 수는 있다
```

### S-E3 ★ 자리 · 매칭에 닿지 않는다
> 익명 쪽지를 주고받은 쌍의 동석률이 오르지 않는다 (씨앗 여러 개 평균, ADR-57). 매칭은 파티 콕만 센다 (ADR-34).

### S-E4 ★ 콕 로그 파일에 없다
> R2 의 `poke-logs/<회차id>.csv` 에 익명 쪽지 줄이 생기지 않는다.

## F. 화면 설계

시안은 `docs/mock/36-anon-note.html` 로 그렸다 — 앱의 `theme.css` 를 그대로 읽어 그린 정적 HTML 로,
열한 화면을 골라 볼 수 있었다. **구현이 끝나고 지웠다** (2026-09-24) — 목업 전용 클래스로 이미 구현과
갈라져 있었다. 지금 모습의 원본은 화면 코드와 화면 테스트다. 아래 글은 그때 정한 것이다.
폰 폭(390px) 기준이다. 새 부품은 없다 — 있는 것(`Num` · `Sheet` · `confirm` · `.banner` · `.fact`)에 줄을 더한다.

```
운영자   위저드 3스텝 · 설정 탭 · 회차 기본 설정  ──  `익명 쪽지 (0~5)` 스테퍼 한 줄
보내기   참가자 탭 → 카드 → 프로필 시트 → [익명 쪽지 쓰기 · N장 남음] → 작성 시트 → 확인창 → 프로필 시트
받기     홈 → 지금까지의 소식 → ✉️ `익명 쪽지가 왔어요` + 본문 + [지우기]
운영자   참가자 탭 → 상세 시트 → `보낸 익명 쪽지 N장` 한 줄
```

### F1. 운영자 설정 — `익명 쪽지 (0~5)` 한 줄

**세 화면 같은 부품.** 위저드 3스텝(`투표·콕 설정`) · 설정 탭 같은 묶음 · 회차 기본 설정 —
셋 다 `파티 콕 (1~10)` 과 같은 스테퍼(`Num`)다. 라벨은 `익명 쪽지 (0~5)`.

**자리는 묶음의 맨 끝이다** — 위저드와 설정 탭에서 `콕 알림` 토글 **아래**. 콕의 다섯(횟수 둘 · 대상 · 알림 둘)은
콕 하나의 규칙이라 붙어 있어야 하고, 굳는 셋(ADR-35)이 한 덩어리로 잠기는 모양도 그대로 남는다.
익명 쪽지는 그 뒤에 혼자 선다 — 콕이 아니고, 굳지도 않는다.

- **위저드에는 설명 줄이 없다** (ADR-54). `0~5` 가 0 을 말한다
- **설정 탭에는 한 줄이 붙는다** — `0으로 내리면 이 회차의 익명 쪽지가 닫혀요. 이미 온 익명 쪽지는 그대로 남습니다.`
  이 줄이 남는 기준(ADR-54 후기 2: *왜 이 칸을 지금 못 쓰는지*)에 맞는 이유는, **0 이 하는 일이 숫자가 아니라
  스위치**라서다. 화면이 스스로 못 말하는 유일한 것이고, 운영자가 사고 났을 때 누르는 자리다
- **굳지 않는다.** `rulesLocked` 밖이다. 토글 셋이 잠긴 뒤에도 이 줄은 산다
- **바닥은 1~5 에만 있다.** 0 으로는 언제나 내려간다 (S-D2)
- **옛 회차는 0 이다.** 값을 채워 넣지 않는다
- **확인창들.** 설정 적용 `익명 쪽지 · 2장 → 3장` · 기본값 되돌리기 `익명 쪽지 · 3장 → 2장` ·
  회차 삭제 `익명 쪽지 · N장 → 삭제` · 참가자 내보내기 `보낸 익명 쪽지 · N장 → 남겨둠` **과**
  `받은 익명 쪽지 · 사라짐`.
  ⚠️ **받은 쪽 줄에는 숫자를 싣지 마라** — 받은 장 수는 운영자 응답에 없는 값이다(F6). 줄만 세우면
  사라진다는 사실은 말하면서 새는 것은 없다. 이 줄이 없으면 **되돌릴 수 없는 행동에서 사라지는 것 하나가
  확인창에서 빠진다** — `DELETE_EVENT` 가 `콕 로그 파일 · 남음` 을 굳이 적어 둔 이유와 같은 자리다.
  `DELETE_PLAYER.note` 의 `받은 표·콕과 배정된 자리가 사라지고` 에도 익명 쪽지를 함께 적는다.
  이 두 줄은 `maxNotes > 0` 이거나 **그 회차에 오간 쪽지가 있을 때** 선다.
  단위는 **장**이다 (`UNIT.sheets`) — 콕의 `회` 와 갈라야 두 줄이 다른 것으로 읽힌다
- **묶음 이름은 그대로다** (`투표·콕 설정`). 위저드 스텝 이름과 짝이라(테스트) 한 줄 때문에 늘리지 않는다

### F2. 보내는 쪽 — 프로필 시트

**입구는 프로필 시트 하나다.** 참가자 탭 목록에는 아무것도 더하지 않는다 — 카드 오른쪽은 👉 하나라야 하고
(*한 줄에 둘이면 카드가 화면 밖으로 밀린다*, UI.md), 목록에 보낸 표시가 서면 가리기가 덮어야 할 자리가 하나 는다.
콕은 손끝이고 익명 쪽지는 마음먹는 것이라 두 번 눌러 들어가는 것이 맞다.

```
[아바타] 달빛                              [👉 1]
         28세 ENFP
이 사람의 매력
( 웃음이 많아요. 같이 있으면 분위기가 밝아진대요 )
( 여행 이야기라면 밤새 할 수 있어요 )
( 커피 내리는 걸 좋아해요 )
내가 보낸 익명 쪽지                                   ← 보낸 적이 있을 때만
( 아까 웃는 모습이 좋았어요. 오늘 재밌게 보내세요 🙂    읽음 )
( 커피 이야기 더 듣고 싶어요                      읽지 않음 )
[ 익명 쪽지 쓰기 · 1장 남음 ]
[ 닫기 ]
```

- **남은 장 수가 버튼 안에 있다.** 버튼 아래 설명 줄을 두면 `익명 쪽지 쓰기` 와 `닫기` 사이에 글이 끼어
  **버튼 둘이 한 묶음으로 안 읽힌다.** 숫자는 버튼이 하는 일에 딸린 값이라 안에 있는 것이 맞다
  (콕 버튼이 찌른 횟수를 버튼 안에 넣은 것과 같은 판단이다)
- **다 썼으면 글자가 바뀌고 잠긴다** — `익명 쪽지를 다 썼어요`, `disabled`. 그 글자가 왜 못 누르는지를
  스스로 말하므로 죽은 버튼이 아니다. 콕 버튼과 달리 열어 둘 이유가 없다 — **되돌리기가 없다**
  (콕은 되돌리기가 그 창 안에만 있어서 다 쓴 뒤에도 창이 열린다 — ADR-34 후기)
- **`내가 보낸 익명 쪽지` 는 보낸 적이 있을 때만 선다.** 본문은 `pre`, 오른쪽에 `읽음`/`읽지 않음`.
  **둘 다 같은 흐린 글씨다** — 색으로 좋고 나쁨을 말하지 않는다. 글줄(baseline)에 맞춰 첫 줄 옆에 선다
- **시각이 없다.** `읽음` 이지 `21:05에 읽음` 이 아니다
- ⚠️ **가리기 중에는 묶음도 버튼도 함께 잠긴다** (S-B5). 묶음만 감추면 모자라다 —
  `익명 쪽지 쓰기` 를 누르면 시트 제목이 `달빛님에게 익명 쪽지` 이고 확인창이 `받는 사람 · 달빛` 이며
  그 사이 내내 글을 친다. **콕 한 번보다 훨씬 오래, 훨씬 또렷하게 상대가 드러난다.**
  콕 버튼을 가린 동안 잠그는 이유(*남이 보는 중에 누르면 지금 찌르는 상대가 실시간으로 샌다*)가
  여기서 더 세게 성립한다. 글자는 그대로 두고 `disabled` — 🙈 로 바꾸지 않는다(콕 버튼이 이미 그 말을 한다).
  `/e/:code/p/:pid/note` 를 **가린 채로 직접 열면 프로필 시트로 갈아끼운다**
- **파티 전에는 묶음도 버튼도 없다.** 잠긴 버튼을 미리 세우지 않는다 — 매력 투표 화면에서 파티의 일을
  말하지 않는 것이 ADR-96 의 방향이다. 발표 뒤에는 버튼만 사라지고 보낸 묶음은 남는다
- ⚠️ **버튼 둘은 `.sheetFoot` 으로 시트 바닥에 붙인다.** 흔한 경우는 안 넘지만 **상한에서는 넘는다** —
  390×844 에서 재 봤다:

  | | 필요한 높이 | 한도 743px |
  |---|---|---|
  | 아직 안 보낸 사람 | 365px | 안 넘음 |
  | 매력 셋 + 쪽지 둘 (흔한 경우) | 551px | 안 넘음 |
  | 긴 매력 셋 + 긴 쪽지 둘 | 698px | 안 넘음 |
  | **매력 100자 셋 + 쪽지 120자 다섯** | **1151px** | **넘음** |

  그냥 두면 상한에서 셋이 한꺼번에 깨진다 — (1) 한 장 더 보내려는 사람이 **자기가 쓴 글을 전부
  지나쳐** 스크롤해야 버튼에 닿고, (2) `닫기` 가 화면 밖으로 내려가며(UI.md 가 *처음 들어온 사람이
  나갈 곳을 찾아 헤맸다* 고 일부러 맨 아래 둔 버튼이다), (3) 한 칸이라도 스크롤하면
  `Sheet` 의 `el.scrollTop > 0` 때문에 **끌어서 닫기가 통째로 안 먹는다** — 닫는 길 하나가 조용히 사라진다.
  배정 시트가 같은 문제를 `.sheetFoot` 으로 풀었다. 붙이면 1151px 에서도 `닫기` 가 보인다

### F3. 작성 시트 — 제목과 칸과 버튼뿐

```
달빛님에게 익명 쪽지
( ........................................ )   ← rows 4, 120자, 보이는 라벨 없음
[ 익명 쪽지 보내기 ]
```

- **글자수 안내도, 하단 안심 문구도 없다.** 안심은 **이름이 한다** — `익명 쪽지` 라는 말이
  *누가 보냈는지 안 보인다* 를 그 자리에서 말한다. 이름을 그렇게 고른 값을 여기서 받는다
- **라벨은 `.srOnly` 다.** 제목이 `달빛님에게 익명 쪽지` 라 보이는 라벨은 같은 말을 두 번 한다.
  화면 낭독기에는 남긴다
- **자리 표시 문구를 두지 않는다.** 예문이 있으면 그 결로 쓴다 — 무슨 말을 할지는 앱이 정할 일이 아니다
- **열릴 때 글 칸에 커서를 준다** — ADR-63 예외 2호. 입장 확인창처럼 **칠 것밖에 없는 창**이고,
  사람이 `익명 쪽지 쓰기` 를 눌러 들어왔다. 시트는 `--kb` 만큼 올라오므로 키보드 위에 선다
- ⚠️ **프로필 시트 위에 쌓지 않는다.** 이 저장소의 시트는 겹치지 않는다 —
  운영자 콘솔의 떨어뜨리기 시트가 `!!picked && !atApart` 로 상세 시트를 닫고 자기가 선다 (ROUTES.md).
  작성 시트도 같다: 열리면 프로필 시트가 닫히고, 뒤로 가면 프로필 시트가 되살아난다
- **뒤로 가기 = 취소. 쓰던 글은 버려진다** — 내 정보 고치기와 같다. 이탈 방지를 걸지 않는다.
  맨 위에서 끌어 닫는 것도 같은 취소다 (글 칸에서 시작한 끌기는 `Sheet` 가 안 잡는다)
- **조건이 안 맞는 주소를 직접 열면** 프로필 시트로 **갈아끼운다** — `/seat` 와 같은 규칙이다

### F4. 확인창

```
익명 쪽지를 보낼까요?          (이미 보낸 사람에게는  한 장 더 보낼까요?)
( 받는 사람   달빛 )
( 남은 익명 쪽지   2장 → 1장 )
보낸 뒤에는 되돌릴 수 없어요.
[ 보내기 ]
[ 취소 ]
```

- 되돌릴 수 없는 행동이라 확인이 붙는다. 항목은 둘 — **누구에게**와 **무엇이 얼마나 바뀌나**
- 본문은 항목에 안 넣는다 — 바로 뒤 작성 시트에 그대로 있다
- **히스토리** — 프로필 시트(push) → 작성 시트(push) → 확인창(push). `보내기` 는 실행 **전에**
  확인창을 `navigate(-1)` 하고, 성공하면 작성 시트도 `navigate(-1)` → 프로필 시트.
  실패하면 작성 시트에 남고 버튼 아래 `.err` 한 줄, 글은 그대로다
- **토스트 없음** — 돌아간 프로필 시트의 `내가 보낸 익명 쪽지` 에 줄이 생긴 것이 곧 알림이다 (ADR-65)
- **보내는 중에는 다시 안 보낸다** (`sending` ref). 콕과 달리 화면을 먼저 바꾸지 않는다 —
  서버 답(`MyNoteState`)이 그 묶음을 채운다

### F5. 홈 — 보내는 쪽과 받는 쪽

**보내는 쪽** — 파티 중 할 일 카드의 kicker 줄에 한 줄 더.

```
콕 1회 남음
익명 쪽지 1장 남음          ← 0 이면 줄이 없다
[ 참가자 보러 가기 ]
```

- 콕 줄과 나란히 선다. 둘 다 예산이라 같은 무게로 읽혀도 된다
  (카운트다운을 카드 밖으로 뺀 이유 *하나는 시계고 하나는 예산*이 여기는 안 걸린다)
- **파티 시작 소식**의 몸글에 둘째 줄이 붙는다 — `익명 쪽지 2장도 새로 받았어요` (`maxNotes > 0` 일 때만).
  ⚠️ **과거형이어야 한다.** 소식은 저장이 아니라 파생이고 파티 줄에 단계 조건이 없어서
  **발표 뒤에도 목록에 남는다.** 같은 몸글의 콕 줄이 `파티 라운드 콕 N회를 새로 받았어요` 로 과거형인
  이유가 그것이다 — 일어난 사건을 적으면 나중에 거짓이 되지 않는다. `보낼 수 있어요` 로 적으면
  버튼도 kicker 도 사라진 뒤에 소식만 계속 보낼 수 있다고 말한다
- 단계 안내 전체 화면(ADR-96)은 손대지 않는다 — 한 화면에 한 가지다

**받는 쪽**

```
지금까지의 소식
| ✉️  익명 쪽지가 왔어요                       [지우기]
|     아까 웃는 모습이 좋았어요. 오늘 재밌게 보내세요 🙂
| 👉  누군가 콕! 찔렀어요
|     누구인지는 비밀이에요
```

- **제목이 `익명` 을 말하므로 아래 `누구인지는 비밀이에요` 줄은 없다.** 같은 말을 두 번 하지 않는다
- 한 장에 한 줄. 합쳐서 `2장` 으로 세지 않는다 — 본문이 있으니 합칠 수도 없다
- **본문은 `dim` 이 아니다.** 다른 소식의 몸글은 곁설명이지만 이건 **내용**이다
- 시각 없음. 차례는 `fired.party + 2` — 받은 콕(`+1`) **위**, 파티 시작 알림 위다
- 배너 안 뜸(`bannerable: false`) · 움직임 없음 · 탭 배지 없음 · 소리 없음
- **누를 수 있는 것은 `지우기` 하나다.** `.coverToggle` 과 같은 수를 쓴다 — 보이는 건 12px 이고
  손가락은 44px 을 받는다. 눈에 띄면 안 되는 버튼이다.
  ⚠️ **제목 줄 안이 아니라 `.banner` 의 직계로 두고 위쪽에 정렬한다** (`align-self: flex-start`).
  제목 줄 안에 넣으면 `button` 의 `min-height: 44px` 가 그 줄을 21px → 44px 로 부풀려 쪽지 줄만
  다른 소식보다 커지고, 음수 여백으로 눌러 담으면 **44px 타겟이 본문 첫 줄 위로 겹쳐서** 본문
  오른쪽 끝을 짚은 손가락이 지우기 확인창을 연다. 직계로 빼면 제 칸을 가져 겹치지 않는다 —
  재 봤다: 탭 영역 55×44px, 본문과 겹침 0, 본문 오른쪽 끝을 짚으면 본문이 잡힌다
- 발표 뒤에도 남는다. `maxNotes` 가 0 이 돼도 남는다 — 온 것은 온 것이다
- ⚠️ **어깨너머 가리기가 여기도 덮는다** (슬라이스 16). 지금 `News()` 는 `covered` 를 안 보고
  토글은 참가자 탭에만 있다 — 그대로 두면 **120자짜리 글이 홈에 상시로 서 있다.** 받은 콕 줄과 달리
  쪽지 본문에는 발신자를 좁히는 말(`아까 파란 셔츠`)이 들어갈 수 있고, 그건 **발신자가 고르지 않은
  제3자에게** 드러나는 것이라 스스로를 밝히는 것과 종류가 다르다. 마흔 명이 나란히 앉은 자리다.
  - 가릴 때 **줄을 지우지 말고 본문만 덮는다** — 제목(`익명 쪽지가 왔어요`)은 남긴다.
    가린 사람이 온 줄도 모르면 안 된다
  - **토글을 홈에도 세운다.** 소식 머리 줄(`지금까지의 소식`) 오른쪽에 참가자 탭과 **같은 부품**으로.
    상태는 `useCovered()` 하나(localStorage)라 두 화면이 같은 값을 본다 — 두 집 살림이 아니다.
    쪽지 줄이 하나도 없으면 토글도 안 그린다 (덮을 것이 없다)

### F6. 운영자 — 참가자 상세

```
낸 표 1회
보낸 콕 1회
보낸 익명 쪽지 2장        ← 이 한 줄이 전부다
```

- **받은 장 수 줄은 없다.** 받은 콕을 참가자 탭 개인 행에 안 두는 것과 같은 이유다 (ADR-22·30) —
  알면 그 사람을 다르게 대하게 된다
- **본문 묶음도 지우기 버튼도 없다.** 현황 탭에도 익명 쪽지가 없다
- 남는 `보낸 장 수` 는 운영자가 `0` 을 누를지 판단하는 값이고, **동시에 익명이 새는 유일한 틈**이다 —
  신고가 들어왔을 때 많이 보낸 사람을 좁혀볼 수 있다. 알고 고른 값이다 (ADR-98 후기 2)

### F7. 도움말

`상대가 아나요` 바로 아래 — 같은 질문(익명)의 자리다.

```
Q  익명 쪽지는 누가 보낸 건지 알 수 있나요?
A  아니요. 끝까지 익명이에요. 답장이 없어서 읽기만 하면 돼요. 내가 읽으면 상대에게 '읽음' 으로 보여요.
```

- **셋째 문장이 읽음 표시의 유일한 고지다.** 작성 시트에서 하단 문구를 뺐으므로 여기가 그 자리다.
  받는 쪽도 보는 화면이라, 안 적으면 **앱이 문구보다 넓게 하는 일**이 생긴다
- **주어가 나로 선다.** 이 문답은 받는 쪽만 보는 글이 아니다 — 보내는 사람도 *내 익명이 지켜지나* 를
  묻고 여기를 연다. `보낸 사람은 내가 읽었는지` 로 쓰면 그 사람에게는 한 문장 안에서 같은 사람이
  두 이름(`보낸 사람`·`내가`)으로 불린다. 그리고 참가자 화면이 쓰는 낱말은 `상대` 다
  (`상대에게는 익명으로 알림이 가요`) — `보낸 사람` 은 운영자 콕 로그 CSV 머리글에만 있다.
  배지 낱말(`읽음`)을 그대로 인용해 다른 화면과 어긋나지 않게 한다
- 장 수는 안 적는다 — 버튼과 홈 kicker 가 이미 말한다
- ⚠️ **조건은 `maxNotes > 0` 이 아니다.** `내가 주고받은 익명 쪽지가 하나라도 있으면` 을 함께 본다.
  운영자가 **0 으로 내린 회차가 곧 괴롭힘이 있었던 회차**인데(ADR-98 의 유일한 레버), 거기서
  이미 온 쪽지는 소식에 그대로 남고(S-D2) 읽음도 계속 돈다 — 그런데 조건이 `maxNotes > 0` 이면
  **고지가 통째로 사라진다.** 피해자가 앱을 열 때마다 상대 화면에 `읽음` 이 서는데 그 말이 앱 어디에도 없다

### F8. 라우트 · 히스토리 (ROUTES.md 에 옮길 줄)

| URL | 화면 |
|---|---|
| `/e/:code/p/:pid/note` | **익명 쪽지 작성 시트** (모달). 프로필 시트에서 push 로 열고 **프로필 시트는 닫힌다**. 뒤로 가기가 곧 취소이고 프로필 시트가 되살아난다. 조건이 안 맞으면 `/e/:code/p/:pid` 로 **갈아끼운다** |

⚠️ **주소 쪼개기를 고쳐야 한다.** 지금 `Participant.tsx` 는 `pathname.split("/p/")[1]` 을 통째로
참가자 아이디로 쓴다 — `/p/abc/note` 를 열면 아이디가 `abc/note` 가 되어 **프로필을 못 찾는다.**
뒤 조각을 갈라서 앞은 아이디, 뒤는 `note` 인지로 읽어야 한다. 닉네임이 아니라 아이디를 주소에 담는
규칙(ROUTES.md)은 그대로다.

| 전환 | 방식 | 이유 |
|---|---|---|
| 프로필 시트 → 작성 시트 | push | 뒤로 가기 = 취소. 쓰던 글은 버려진다 |
| 작성 시트 → 확인창 | push (state) | `Overlays` 규칙 그대로 — 실행 전에 `navigate(-1)` |
| 보내기 성공 → 프로필 시트 | `navigate(-1)` | 갈아끼우면 히스토리에 작성 시트가 남아 뒤로 가기가 빈 칸을 다시 연다 |

### F9. 응답과 저장 모양

**참가자** — `ParticipantState.note: MyNoteState`. 만드는 곳은 하나다 (`toMyNotes`, `toPublic` 옆).

```ts
interface MyNoteState {
  budget: { max: number; used: number };          // max 는 회차의 maxNotes (없으면 0)
  sent: Record<string, Array<{ text: string; read: boolean }>>;  // 받는 사람별. 내 것이라 담아도 된다
  received: Array<{ id: string; text: string }>;                 // fromId 없음. at 없음. 최신이 앞
}
```

- **담을 자리가 없는 것이 방어다** (`MatchInfo` 의 논리). `received` 에 발신자를 넣을 칸이 아예 없다
- `read` 는 boolean 이지 시각이 아니다. 그리고 **`read_at` 이 5분보다 오래됐을 때만 참**이다 (S-B6) —
  서버가 그 판정을 하고 응답에는 boolean 만 나간다
- ⚠️ **`received` 에 `seen` 을 두지 마라.** 안 본 줄을 가려 `/note/seen` 호출을 아끼려고
  넣었다가 뺐다 — `seen: false` 는 **이 줄이 내가 마지막으로 홈을 연 뒤에 왔다**를 응답이
  확정해 주는 값이다. 참가자 탭 URL 이 유지되므로(`Participant.tsx`) 콕을 찌르러 참가자 탭에
  머문 사람은 `false` 로 남고 홈에 들른 순간 한꺼번에 `true` 가 되는데, 홈과 참가자 탭을
  오가면 그 창이 **초 단위까지 좁아진다.** 그때 누가 폰을 들고 있었는지와 맞추면 발신자가 좁혀진다 —
  `받은 콕에 시각을 붙이지 마라` 와 **같은 누출이 칸 이름만 바꿔 들어온 것**이다.
  아끼려던 호출은 `received.length` 로 똑같이 아끼고, 서버는 바뀐 것이 없으면 아무것도 안 쓴다
- `id` 는 지우기에만 쓴다. **추측할 수 없는 값**이어야 한다 — 차례로 만들면 남의 것을 지워볼 수 있다
- ⚠️ **`used` 는 줄이 사라져도 안 줄어든다.** `sent` 와 `budget.used` 는 `hidden_at` 을 무시하고
  `from_id` 가 나인 줄을 전부 센다 (아래 S-C3 의 이유)
- ⚠️ **`meta.config` 는 병합이 아니라 통째로 교체다.** 교체 리터럴에 `maxNotes` 를 안 적으면
  **저장 한 번에 사라진다** — 운영자가 파티 중에 콕 횟수를 올리는(허용된 동작) 흔한 저장 하나로
  값이 없어져 0 이 되고, 규칙상 0 은 *이 회차에는 없다* 라 **버튼·홈 kicker·도움말이 전원 화면에서
  사라진다.** 에러도 확인창도 없다. 이 저장소는 그 사고를 이미 겪었다 — 옛 회차의 `allowUndo` 가
  그렇게 없어졌고(ADR-95) 코드 주석이 그 사실을 적어 두고 있다.
  `allowSameGender`·`preNotify`·`pokeNotify` 가 쓰는 꼴을 그대로 따른다:
  `const maxNotes = patch.config.maxNotes ?? meta.config.maxNotes` 로 받아 **안 보내면 지금 값을 지키고**,
  리터럴에 `...(maxNotes ? { maxNotes } : {})` 로 적는다. *옛 회차는 키가 없어 0* 은 그대로 산다
- `EventConfig.maxNotes?: number` — **없으면 0.** `LIMITS.maxNotes = { min: 0, max: 5 }` ·
  `LIMITS.noteMax = 120` · `DEFAULTS.maxNotes = 2`

**운영자** — `HostState.noteSent: Record<string, number>` · `noteUsedMax: number`. **그뿐이다.**
본문도, 쌍도, 받은 수도 없다.

**API**

| | |
|---|---|
| `POST /api/note` `{ toId, text }` | → `MyNoteState`. 409 `closed` · 409 `no_budget`(`max` 를 실어) · 400(비었거나 120자 초과, 자기 자신, 없는 사람) |
| `POST /api/note/seen` | → `MyNoteState`. 안 본 것 전부 읽음으로 (`read_at IS NULL` 에만 찍는다 — 다시 열 때마다 새로 찍으면 5분이 영영 안 지난다). **덮개가 덮고 있거나 가리기가 켜져 있으면 부르지 않는다** |
| `POST /api/note/remove` `{ id }` | **받는 사람만.** `to_id` 가 나인 줄에 `hidden_at` 만 찍는다 (**지우지 않는다**) → `MyNoteState` |
| `PUT /host/events/:id` `config.maxNotes` | 1~5 로 내릴 때만 바닥을 본다. **0 은 언제나 통과** |

**저장** — 회차 DO 의 새 표 `notes(id, from_id, to_id, body, at, read_at, hidden_at)`.
**새 표라 `CREATE TABLE IF NOT EXISTS` 로 충분하다** — 옛 표에 칸을 더하는 것이 아니므로
CLAUDE.md 의 인덱스 함정(`no such column`)에 안 걸린다.
⚠️ **그래서 `hidden_at` 을 첫 `CREATE TABLE` 에 넣는다.** 나중에 더하면 이미 표를 가진 회차에
`ALTER` 를 걸어야 하고, 그 칸을 가리키는 인덱스를 `SCHEMA` 에 올리는 순간 **DO 가 통째로 죽는다.**
`id` 는 콕과 같은 `randomHex(8)` 로 만들고, 소유 검사는 서버가 `to_id` 로 한다. 콕 로그에는 안 쓴다. 지표에도 안 더한다.

⚠️ **소켓으로 아무것도 밀지 않는다.** `broadcast()` 도, `toPlayer()` 도 쓰지 마라.

- `broadcast()` 는 **회차 전체**에 간다. 익명 쪽지 한 장에 방 안의 모든 폰이 그 순간 재조회하면,
  네트워크를 보는 사람에게 **도착 시각이 그대로 나간다** — 그때 누가 폰에 글을 치고 있었는지와 맞추면
  발신자가 좁혀진다. 콕이 `broadcast` 가 아니라 `toPlayer` 를 쓰는 이유가 이것이다
  (`broadcast()` 주석: *콕처럼 수신자별로 내용이 달라야 하는 건 toPlayer 를 쓴다*)
- **`toPlayer()` 도 안 쓴다.** 받는 사람에게만 밀어도 **그 사람에게 도착 시각을 주는 것**이다 —
  고개를 들면 방금 폰을 든 사람이 보인다. 콕은 그걸 회차 설정(`pokeNotify`)으로 운영자가 고르게 했는데,
  익명 쪽지에는 그 설정이 없다(쪽지 자체가 알림이다). 그러면 **안 미는 쪽**이 맞다
- **그래서 받는 사람은 다음에 스스로 읽을 때 본다.** 앱으로 돌아올 때·다른 신호가 올 때 다시 읽는
  구조가 이미 그 자리를 맡는다 (ADR-26). 답장이 없으니 급할 것도 없다

## 문구 — `NOTE`

| 자리 | 문장 |
|---|---|
| 프로필 시트 버튼 | `익명 쪽지 쓰기 · ${n}장 남음` |
| 〃 다 썼을 때 | 익명 쪽지를 다 썼어요 |
| 프로필 시트 묶음 | 내가 보낸 익명 쪽지 |
| 읽음 배지 | 읽음 / 읽지 않음 |
| 작성 시트 제목 | `${nick}님에게 익명 쪽지` |
| 〃 칸 라벨(`.srOnly`) | 익명 쪽지 |
| 〃 보내기 | 익명 쪽지 보내기 |
| 확인창 제목 | 익명 쪽지를 보낼까요? / 한 장 더 보낼까요? |
| 〃 항목 | 받는 사람 · 남은 익명 쪽지 (`2장 → 1장`) |
| 〃 문단 | 보낸 뒤에는 되돌릴 수 없어요. |
| 〃 버튼 | 보내기 |
| 홈 kicker | `익명 쪽지 ${n}장 남음` |
| 파티 소식 둘째 줄 | `익명 쪽지 ${n}장도 새로 받았어요` (**과거형** — 발표 뒤에도 남는 줄이다) |
| 받은 줄 제목 | 익명 쪽지가 왔어요 |
| 받은 줄 지우기 | 지우기 |
| 지우기 확인창 | 이 익명 쪽지를 지울까요? / `이 쪽지 · 사라져요` / 지운 익명 쪽지는 되돌릴 수 없어요. 지운 것은 상대에게 알려지지 않아요. |
| 닫힘 (서버) | 지금은 익명 쪽지를 보낼 수 없어요 |
| 다 씀 (서버) | `익명 쪽지를 다 썼어요 (최대 ${max}장)` |
| 도움말 | 익명 쪽지는 누가 보낸 건지 알 수 있나요? / 아니요. 끝까지 익명이에요. 답장이 없어서 읽기만 하면 돼요. 내가 읽으면 상대에게 '읽음' 으로 보여요. |
| 운영자 라벨 | `익명 쪽지 (0~5)` |
| 〃 설명 줄 | 0으로 내리면 이 회차의 익명 쪽지가 닫혀요. 이미 온 익명 쪽지는 그대로 남습니다. |
| 〃 바닥 | `이미 ${n}장 보낸 참가자가 있어요. ${n}장보다 적게는 줄일 수 없습니다.` |
| 〃 0 으로 내릴 때(확인창 항목) | `익명 쪽지 · 2장 → 0장` / `지금부터` · `아무도 못 보내요` / `이미 간 익명 쪽지` · `그대로예요` |
| 〃 상세 줄 | `보낸 익명 쪽지 ${n}장` |
| 〃 내보내기 확인창 | `보낸 익명 쪽지 · N장 → 남겨둠` / `받은 익명 쪽지 · 사라짐`(숫자 없음) |
| 단위 | `UNIT.sheets = (n) => ${n}장` |

어체는 ADR-89 후기의 표를 따른다 — 안심은 `~지 않아요`, 할 수 있는 것은 `~할 수 있어요`, 버튼은 명사형.
**화면에서는 늘 `익명 쪽지` 다.** 줄이지 마라 — 확인창 항목도 `남은 익명 쪽지` 다.
같은 숫자를 버튼(`익명 쪽지 쓰기 · 1장 남음`)·홈(`익명 쪽지 1장 남음`)과 다른 이름으로 부르면
**다른 숫자로 읽힌다.** 콕이 그 사고를 이미 겪었다 (`POKE.confirm.rowBudget` 주석:
*한동안 카드는 `남은 콕`, 창은 `파티 남은 횟수` 라고 불렀다*).
예외는 **제목이 무엇인지 이미 말한 뒤의 본문** 하나다 — 지우기 확인창의 `이 쪽지 · 사라져요`.
⚠️ **그래서 그 창의 제목은 줄이지 않는다** (`이 익명 쪽지를 지울까요?`). 제목까지 줄이면
창 어디에도 `익명 쪽지` 가 없어서, 기댈 것이 없어진 항목만 남는다.
