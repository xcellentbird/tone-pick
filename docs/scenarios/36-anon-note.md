# 슬라이스 36 — 쪽지: 익명으로 한 장, 답장은 없다

운영자가 요청했다: *익명 메시지 기능을 추가하려 합니다. 회차 운영자 설정을 통해 한 명당 쓸 수 있는
메시지 수 제한을 두면 좋겠습니다.*

이 앱에서 그 기능의 이름은 **쪽지**다. `메시지` 는 초대 문자에 이미 쓰는 말이고(UI.md), `알림` 은 운영자가
보내는 것이다. 쪽지는 참가자가 참가자에게 **익명으로 한 장** 보내는 것이고, **답장이 없다** (ADR-98).
답장이 없어서 채팅이 아니다 — 슬라이스 24 가 경고한 *참가자끼리 열리면 익명 채팅이다* 를 그 한 줄이 막는다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 운영자가 정할 것 — 초안의 추천과 함께

| | 추천 | 다른 길 |
|---|---|---|
| 언제 보내나 | **파티 시작 ~ 발표** (파티 콕과 같은 창) | 매력 투표부터 — 프로필만 보고 쓰는 쪽지는 무겁다. 발표 뒤 — 위로 편지가 된다 (아래 ADR-98) |
| 몇 장 | 회차 설정 `쪽지 횟수`, **0 이면 이 회차에는 쪽지가 없다.** 상한 5, 운영자 기본값 2 | — |
| 같은 사람에게 | **한 장.** 둘째 장부터가 대화다 | 여러 장 — 횟수 안이면 허용 |
| 누구에게 | 콕과 같은 대상 규칙 (`allowSameGender`). 자기 자신은 안 된다 | 쪽지만 따로 — 개념이 하나 는다 |
| 발신자 | **끝까지 익명.** 발표 뒤에도, 서로 콕 찌른 쌍에게도. 운영자만 본다 | 서로 콕이면 발표 때 열기 — 규칙이 하나 더 생기고, 안 열린 쪽지가 *상대는 나를 안 찔렀다* 를 말한다 |

아래는 추천대로 적었다. 바뀌면 그 줄만 바꾼다.

## 왜 채팅이 아닌가 — 그리고 원칙 1

이 앱의 존재 이유는 **거절의 경험을 만들지 않는 것**이다 (원칙 1). 쪽지는 일방적인 마음을 글로 실어
나르는 물건이라 그 원칙과 가장 가까이 부딪힌다. 셋으로 지킨다.

1. **답장이 없다.** 받은 쪽은 읽을 뿐이고, 아무것도 하지 않아도 된다 — 거절이라는 **행동**이 없다.
   보내는 쪽도 지킨다: 답이 올 길이 없으니 안 온 답을 기다리지 않는다
2. **끝까지 익명이다.** 피할 얼굴이 없다. 발표 뒤에 열리는 건 서로 콕 찌른 쌍의 실명 하나다 (ADR-42) —
   쪽지는 거기 끼지 않는다
3. **한 사람에게 한 장이다.** 뒤쫓을 수 없다. 반응 버튼(좋아요 같은 것)도 없다 — 반응은 곧 수락·거절의 신호다

받는 쪽이 아는 건 *누군가 나에게 이 말을 남겼다* 까지다. 받은 콕 수가 이미 같은 종류의 것을 말하고 있다
(알림을 켠 회차). 운영자가 회차마다 `0` 으로 끌 수 있다.

## 범위

**만든다**

| | |
|---|---|
| 보내기 | 참가자 탭의 사람 카드에서 `쪽지` → 시트(글 한 칸, 120자) → 확인창(받는 사람, 남는 장 수, 되돌릴 수 없음) → 보냄 |
| 받기 | 홈의 소식 줄에 **한 장씩**. 받은 콕과 같은 규칙 — 시각 없음, 배너 없음, 움직임 없음, 파티 시작 알림 위 |
| 남은 장 수 | 홈 상태 줄에 `쪽지 N장 남았어요` (콕 남은 횟수와 같은 자리) |
| 회차 설정 | `쪽지 횟수` — 위저드 3단계 · 설정 탭 규칙 묶음 · 운영자 기본값. 이미 쓴 장 수 아래로 못 내린다 |
| 운영자 | 참가자 상세 시트에 그 사람이 **보낸 · 받은** 쪽지 (상대 이름까지) + `지우기` |
| 도움말 | 문답 하나 — *쪽지는 누가 보낸 건지 알 수 있나요?* |

**안 만든다**

- **답장 · 대화 · 반응.** 어떤 모양으로도. 이게 쪽지와 채팅의 경계다
- **발신자 공개.** 발표 뒤에도, 서로 콕 찌른 쌍에게도. `MatchInfo` 에 쪽지 자리가 없다
- **되돌리기.** 보내면 끝이다 — 확인창이 그 사실을 말한다. 읽었는지도 안 보여준다
- **매력 투표 중 · 발표 뒤 보내기.** 파티 콕의 창과 같다
- **자리 · 매칭에 닿는 것.** `buildSeating` 입력에 없고, 매칭은 여전히 파티 콕만 센다
- **콕 로그 파일에 쌓는 것.** 본문은 회차 DO 밖으로 안 나간다 — 예외는 콕 로그 하나뿐이다 (ADR-84)
- **전체 쪽지 목록 화면.** 운영자는 사람의 상세에서 본다. 신고가 오면 그 사람을 연다
- **지표.** `pulse` 에 쪽지 수를 더하지 않는다 (ADR-56 · 58 을 읽기 전에는)
- **푸시 알림.** 앱으로 돌아올 때 다시 읽는 구조가 그 자리다 (ADR-26)

## A. 보내기

### S-A1 ★ 파티 중에만 보낸다
```
Given  단계가 등록·매력 투표·발표 뒤다
When   쪽지를 보낸다
Then   409 closed. 파티 중에만 200
```

### S-A2 ★ 횟수는 회차 설정이 정한다 — 0 이면 길 자체가 없다
```
Given  `maxNotes: 2`
Then   두 장까지 200, 셋째는 409 no_budget
Given  `maxNotes: 0`
Then   첫 장부터 409 — 화면에는 쪽지 버튼도, 남은 장 수도, 도움말 문답도 없다
```
> 콕 횟수와 같은 바닥이 있다 — **이미 쓴 장 수 아래로 못 내린다** (409 conflict, 지금 가장 많이 쓴 수를 실어).

### S-A3 ★ 같은 사람에게는 한 장이다
```
Given  A 가 B 에게 한 장 보냈다
When   A 가 B 에게 또 보낸다
Then   409 — 횟수가 남아 있어도. 화면은 그 카드의 쪽지 버튼을 `보냈어요` 로 바꾼다
```

### S-A4 ★ 대상은 콕과 같은 규칙이다
> `allowSameGender === false` 면 이성에게만. 자기 자신은 어떤 설정에서도 안 된다 (400).

### S-A5 ★ 120자까지, 글자만
> 비면 400, 넘치면 400. 줄바꿈은 그대로 두고(`pre`), 링크를 눌리게 만들지 않는다.

### S-A6 확인창은 무엇이 어떻게 바뀌는지 말한다 (CLAUDE.md 4)
> `받는 사람 → 달빛` · `남는 쪽지 → 2장 → 1장` · `되돌리기 → 안 돼요`. 되돌릴 수 없는 행동이라 확인이 붙는다.

## B. 받기

### S-B1 ★ 발신자는 어느 응답에도 없다 — 발표 뒤에도
```
Given  A 가 B 에게 보냈다. 발표까지 지났고 둘은 서로 콕을 찔렀다
When   B 가 `/api/me` 를 읽는다
Then   받은 쪽지에 `fromId` 도 닉네임도 성별도 없다 — 본문과 순서뿐이다
And    명단(`roster`)·`MatchInfo` 어디에도 쪽지가 없다
```

### S-B2 ★ 시각이 없고 배너로 뜨지 않는다
> 받은 콕과 같다 (`at: 0`, `order` 는 파티가 시작된 순간 + 차례). "21:03 에 왔다" 를 알면 그때 누가 폰을 보고
> 있었는지와 맞춰 발신자가 좁혀진다. **진짜 도착 시각을 순서에도 쓰지 마라** (notices.ts 의 경고 그대로).

### S-B3 ★ 답장할 길이 없다
```
Given  받은 쪽지 한 장
Then   누를 것이 없다 — 답장·반응·신고 버튼 어느 것도. 읽는다
```
> 신고는 운영자에게 말로 한다. 파티 중엔 눈앞에 있다.

### S-B4 움직임이 없다 (ADR-64)
> broadcast 로 오는 것이라 그냥 나타난다. 옆 사람이 그 순간을 알면 안 된다.

## C. 운영자

### S-C1 ★ 운영자는 발신자까지 본다
```
Given  A → B 쪽지
When   운영자가 A 의 상세를 연다
Then   `보낸 쪽지` 에 `→ B` 와 본문. B 의 상세에는 `받은 쪽지` 에 `← A` 와 본문
```
> 원칙 2 — 운영자만 전체를 본다. 괴롭힘을 잡는 자리다.

### S-C2 ★ 지우면 받는 쪽에서 사라진다
```
When   운영자가 쪽지 하나를 지운다 (확인창: 본문 · 받는 쪽 화면에서 사라짐)
Then   B 의 소식에서 그 장이 없어진다. A 의 쓴 장 수는 그대로다 — 되돌려 주지 않는다
```

### S-C3 회차 설정
> `쪽지 횟수` 는 위저드 3단계 규칙 묶음과 설정 탭 규칙 묶음, 운영자 기본값 화면에 선다.
> 굳는 쪽이 아니라 **열린 쪽**이다 — 콕 횟수처럼 파티 중에 올릴 수 있다 (ADR-35).

## D. 삭제 · 발표 · 자리

### S-D1 ★ 참가자를 지워도 그가 보낸 쪽지는 남는다
```
Given  A → B, A → C 쪽지
When   운영자가 A 를 지운다
Then   B·C 의 소식에 그 장이 그대로 있다. A 가 받은 쪽지는 함께 사라진다
```
> ADR-29 와 같은 논리 — 받은 것이 사라지면 명단에서 사라진 사람과 맞춰 발신자가 드러난다.

### S-D2 ★ 발표 뒤에는 닫히고, 받은 것은 읽힌다
```
Given  파티 중에 A → B 쪽지. 발표가 지났다
When   B 가 `/api/me` 를 읽는다
Then   받은 쪽지는 그대로 있다 — 발표가 지운 것이 아니다
When   C 가 D 에게 새로 보낸다
Then   409 closed. 홈의 `쪽지 N장 남았어요` 도 사라진다
```
> 발표 뒤에는 콕도, 자리 이동 확인도 뜨지 않는다 (CLAUDE.md). 쪽지도 그 줄에 선다 —
> 받은 것은 남고, 보내는 길만 닫힌다.

### S-D3 ★ 자리 · 매칭에 닿지 않는다
> 쪽지를 주고받은 쌍의 동석률이 오르지 않는다 (씨앗 여러 개 평균, ADR-57). 매칭은 파티 콕만 센다 (ADR-34).

### S-D4 ★ 콕 로그 파일에 없다
> R2 의 `poke-logs/<회차id>.csv` 에 쪽지 줄이 생기지 않는다.

## E. 화면

- **참가자 탭 카드** — 콕 버튼 옆에 `쪽지`. 보냈으면 `보냈어요` 로 굳는다. 시트는 라우트다 — 뒤로 가기로 닫히고,
  열렸다고 커서를 주지 않는다 (ADR-63)
- **홈** — 소식 줄에 한 장씩 (✉️). 상태 줄에 `쪽지 N장 남았어요`. `maxNotes: 0` 이면 둘 다 없다
- **단계 안내 화면**(ADR-96)은 손대지 않는다 — 한 화면에 한 가지다. 홈 카드가 쪽지를 말한다
- **운영자 참가자 상세** — `보낸 쪽지` · `받은 쪽지` 묶음, 장마다 `지우기`
- **도움말** — `쪽지는 누가 보낸 건지 알 수 있나요?` / `아니요. 끝까지 익명이에요. 답장도 없어서 읽기만 하면 돼요.`
