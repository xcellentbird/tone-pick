# 슬라이스 36 — 쪽지: 익명으로 보내고, 답장은 없다

운영자가 요청했다: *익명 메시지 기능을 추가하려 합니다. 회차 운영자 설정을 통해 한 명당 쓸 수 있는
메시지 수 제한을 두면 좋겠습니다.*

이 앱에서 그 기능의 이름은 **쪽지**다. `메시지` 는 초대 문자에 이미 쓰는 말이고(UI.md), `알림` 은 운영자가
보내는 것이다. 쪽지는 참가자가 참가자에게 **익명으로** 보내는 짧은 글이고, **답장이 없다** (ADR-98).
답장이 없어서 채팅이 아니다 — 슬라이스 24 가 경고한 *참가자끼리 열리면 익명 채팅이다* 를 그 한 줄이 막는다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 운영자가 정한 것

초안이 다섯을 추천하고 운영자가 둘을 바꿨다 (ADR-98 후기). **아래가 확정이다.**

| | 확정 | |
|---|---|---|
| 언제 보내나 | **파티 시작 ~ 발표** (파티 콕과 같은 창) | 초안대로 |
| 몇 장 | 회차 설정 `쪽지`(0~5), 운영자 기본값 2. **0 이면 이 회차에는 쪽지가 없다** | 초안대로 |
| 같은 사람에게 | **여러 장** — 횟수 안에서 | **바뀜.** 초안은 한 장이었다 |
| 누구에게 | **누구에게나.** 동성 콕 설정(`allowSameGender`)과 무관하다. 자기 자신만 안 된다 | **바뀜.** 초안은 콕과 같은 규칙이었다 |
| 발신자 | **끝까지 익명.** 발표 뒤에도, 서로 콕 찌른 쌍에게도. 운영자만 본다 | 초안대로 |

## 왜 채팅이 아닌가 — 그리고 원칙 1

이 앱의 존재 이유는 **거절의 경험을 만들지 않는 것**이다 (원칙 1). 쪽지는 일방적인 마음을 글로 실어
나르는 물건이라 그 원칙과 가장 가까이 부딪힌다. 둘로 지킨다.

1. **답장이 없다.** 받은 쪽은 읽을 뿐이고, 아무것도 하지 않아도 된다 — 거절이라는 **행동**이 없다.
   보내는 쪽도 지킨다: 답이 올 길이 없으니 안 온 답을 기다리지 않는다. 반응 버튼(좋아요 같은 것)도 없다 —
   반응은 곧 수락·거절의 신호다
2. **끝까지 익명이다.** 피할 얼굴이 없다. 발표 뒤에 열리는 건 서로 콕 찌른 쌍의 실명 하나다 (ADR-42) —
   쪽지는 거기 끼지 않는다

같은 사람에게 여러 장을 보낼 수 있어도 대화가 되지는 않는다 — 돌아오는 것이 없다. 뒤쫓기는 **상한**이 막는다:
한 사람이 쓸 수 있는 장 수(최대 5)가 곧 한 사람에게 갈 수 있는 최대이고, 그게 한 사람에게 몰리면 운영자 상세에
그대로 줄로 선다. 받는 쪽이 아는 건 *누군가 나에게 이 말을 남겼다* 까지다. 운영자가 회차마다 `0` 으로 끌 수 있다.

## 범위

**만든다**

| | |
|---|---|
| 보내기 | 참가자 탭 → 사람 카드 → **프로필 시트**의 `쪽지 쓰기` → 작성 시트(글 한 칸, 120자) → 확인창(받는 사람, 남는 장 수, 되돌릴 수 없음) → 보냄 |
| 받기 | 홈의 소식 줄에 **한 장씩**, 본문 그대로. 받은 콕과 같은 규칙 — 시각 없음, 배너 없음, 움직임 없음 |
| 남은 장 수 | 홈 할 일 카드에 `쪽지 N장 남음` (콕 남은 횟수 아래), 프로필 시트의 버튼 아래 한 줄 |
| 회차 설정 | `쪽지 (0~5)` — 위저드 3단계 · 설정 탭 규칙 묶음 · 운영자 기본값. 이미 쓴 장 수 아래로 못 내린다 |
| 운영자 | 참가자 상세 시트에 그 사람이 **보낸 · 받은** 쪽지 (상대 이름까지) + `지우기` |
| 도움말 | 문답 하나 — *쪽지는 누가 보낸 건지 알 수 있나요?* — `쪽지` 가 0 이 아닌 회차에만 |

**안 만든다**

- **답장 · 대화 · 반응.** 어떤 모양으로도. 이게 쪽지와 채팅의 경계다
- **발신자 공개.** 발표 뒤에도, 서로 콕 찌른 쌍에게도. `MatchInfo` 에 쪽지 자리가 없다
- **되돌리기.** 보내면 끝이다 — 확인창이 그 사실을 말한다. 읽었는지도 안 보여준다
- **매력 투표 중 · 발표 뒤 보내기.** 파티 콕의 창과 같다
- **참가자 탭 목록의 버튼·표시.** 한 줄에 버튼이 둘이면 카드가 밀리고(UI.md), 보낸 표시는 새는 자리가 하나 는다.
  입구는 프로필 시트 하나다
- **자리 · 매칭에 닿는 것.** `buildSeating` 입력에 없고, 매칭은 여전히 파티 콕만 센다
- **콕 로그 파일에 쌓는 것.** 본문은 회차 DO 밖으로 안 나간다 — 예외는 콕 로그 하나뿐이다 (ADR-84)
- **전체 쪽지 목록 화면 · 현황 탭 숫자.** 운영자는 사람의 상세에서 본다. 신고가 오면 그 사람을 연다
- **지표.** `pulse` 에 쪽지 수를 더하지 않는다 (ADR-56 · 58 을 읽기 전에는)
- **푸시 알림.** 앱으로 돌아올 때 다시 읽는 구조가 그 자리다 (ADR-26)

## A. 보내기

### S-A1 ★ 파티 중에만 보낸다
```
Given  단계가 등록·매력 투표·발표 뒤다
When   쪽지를 보낸다
Then   409 closed. 파티 중에만 200
```

### S-A2 ★ 횟수는 회차 설정이 정한다 — 0 이면 길 자체가 없다
```
Given  `maxNotes: 2`
Then   두 장까지 200, 셋째는 409 no_budget
Given  `maxNotes: 0` (옛 회차처럼 값이 없는 것도 0 이다)
Then   첫 장부터 409 — 화면에는 쪽지 버튼도, 남은 장 수도, 도움말 문답도 없다
```
> 콕 횟수와 같은 바닥이 있다 — **이미 쓴 장 수 아래로 못 내린다** (409 conflict, 지금 가장 많이 쓴 수를 실어).
> 굳는 쪽이 아니라 **열린 쪽**이다 — 콕 횟수처럼 파티 중에 올릴 수 있다 (ADR-35).

### S-A3 ★ 같은 사람에게 여러 장 — 횟수 안에서
```
Given  `maxNotes: 2`. A 가 B 에게 한 장 보냈다
When   A 가 B 에게 또 보낸다
Then   200. 셋째는 누구에게든 409 no_budget
And    B 의 소식에는 두 줄이 따로 선다 — 합쳐서 `2장` 으로 세지 않는다
```

### S-A4 ★ 대상은 누구에게나 — 동성 콕 설정과 무관
```
Given  `allowSameGender: false` 인 회차
When   A(남) 가 C(남) 에게 쪽지를 보낸다
Then   200 — 콕이면 409 였을 자리다
When   A 가 A 에게 보낸다
Then   400
```

### S-A5 ★ 120자까지, 글자만
> 비면 400, 넘치면 400. 줄바꿈은 그대로 두고(`pre`), 링크를 눌리게 만들지 않는다.

### S-A6 확인창은 무엇이 어떻게 바뀌는지 말한다 (CLAUDE.md 4)
> `받는 사람 → 달빛` · `남은 쪽지 → 2장 → 1장`. 문단은 `보낸 뒤에는 되돌릴 수 없어요.` —
> 되돌릴 수 없는 행동이라 확인이 붙는다. 이미 보낸 사람에게는 제목이 `한 장 더 보낼까요?` 다.

## B. 받기

### S-B1 ★ 발신자는 어느 응답에도 없다 — 발표 뒤에도
```
Given  A 가 B 에게 보냈다. 발표까지 지났고 둘은 서로 콕을 찔렀다
When   B 가 `/api/me` 를 읽는다
Then   받은 쪽지에 `fromId` 도 닉네임도 성별도 없다 — 본문과 순서뿐이다
And    명단(`roster`)·`MatchInfo` 어디에도 쪽지가 없다
```

### S-B2 ★ 시각이 없고 배너로 뜨지 않는다
> 받은 콕과 같다 (`at: 0`, `order` 는 파티가 시작된 순간 + 차례). "21:03 에 왔다" 를 알면 그때 누가 폰을 보고
> 있었는지와 맞춰 발신자가 좁혀진다. **진짜 도착 시각을 순서에도 쓰지 마라** (notices.ts 의 경고 그대로).

### S-B3 ★ 답장할 길이 없다
```
Given  받은 쪽지 한 장
Then   누를 것이 없다 — 답장·반응·신고 버튼 어느 것도. 읽는다
```
> 신고는 운영자에게 말로 한다. 파티 중엔 눈앞에 있다.

### S-B4 움직임이 없다 (ADR-64)
> broadcast 로 오는 것이라 그냥 나타난다. 옆 사람이 그 순간을 알면 안 된다.

## C. 운영자

### S-C1 ★ 운영자는 발신자까지 본다
```
Given  A → B 쪽지
When   운영자가 A 의 상세를 연다
Then   `쪽지` 묶음에 `→ B` 와 본문. B 의 상세에는 `← A` 와 본문
```
> 원칙 2 — 운영자만 전체를 본다. 괴롭힘을 잡는 자리다.

### S-C2 ★ 지우면 받는 쪽에서 사라진다
```
When   운영자가 쪽지 하나를 지운다 (확인창: 보낸 사람 · 받는 사람 · 받는 쪽 화면에서 사라짐)
Then   B 의 소식에서 그 장이 없어진다. A 의 쓴 장 수는 그대로다 — 되돌려 주지 않는다
```

### S-C3 회차 설정
> `쪽지 (0~5)` 는 위저드 3단계 규칙 묶음과 설정 탭 규칙 묶음, 운영자 기본값 화면에 선다.
> 굳는 쪽이 아니라 **열린 쪽**이다 — 콕 횟수처럼 파티 중에 올릴 수 있다 (ADR-35).

## D. 삭제 · 발표 · 자리

### S-D1 ★ 참가자를 지워도 그가 보낸 쪽지는 남는다
```
Given  A → B, A → C 쪽지
When   운영자가 A 를 지운다
Then   B·C 의 소식에 그 장이 그대로 있다. A 가 받은 쪽지는 함께 사라진다
And    운영자가 B 의 상세를 열면 그 줄의 상대가 `지워진 참가자` 다
```
> ADR-29 와 같은 논리 — 받은 것이 사라지면 명단에서 사라진 사람과 맞춰 발신자가 드러난다.

### S-D2 ★ 발표 뒤에는 닫히고, 받은 것은 읽힌다
```
Given  파티 중에 A → B 쪽지. 발표가 지났다
When   B 가 `/api/me` 를 읽는다
Then   받은 쪽지는 그대로 있다 — 발표가 지운 것이 아니다
When   C 가 D 에게 새로 보낸다
Then   409 closed. 홈의 `쪽지 N장 남음` 도, 프로필 시트의 `쪽지 쓰기` 도 사라진다
```
> 발표 뒤에는 콕도, 자리 이동 확인도 뜨지 않는다 (CLAUDE.md). 쪽지도 그 줄에 선다 —
> 받은 것은 남고, 보내는 길만 닫힌다.

### S-D3 ★ 자리 · 매칭에 닿지 않는다
> 쪽지를 주고받은 쌍의 동석률이 오르지 않는다 (씨앗 여러 개 평균, ADR-57). 매칭은 파티 콕만 센다 (ADR-34).

### S-D4 ★ 콕 로그 파일에 없다
> R2 의 `poke-logs/<회차id>.csv` 에 쪽지 줄이 생기지 않는다.

## E. 화면 설계

세 자리를 설계한다 — **운영자 설정** · **보내는 쪽** · **받는 쪽**. 새 부품은 없다. 있는 것(스테퍼 `Num` ·
`Sheet` · 확인창 `confirm` · 소식 줄 `.banner` · 상세 시트의 `Row`)에 줄을 더한다.
시안은 `docs/mock/36-anon-note.html` 이다 — 앱의 `theme.css` 를 그대로 읽어 그린 정적 HTML 이라 파일로 바로 열리고,
`?v=` 로 화면을 고른다 (`&mark=1` 이면 새로 더한 자리에 점선). 폰 폭(390px)에서 본다.

```
운영자   위저드 3스텝 · 설정 탭 `투표·콕 설정` · 회차 기본 설정  ──  `쪽지 (0~5)` 스테퍼 한 줄
보내기   참가자 탭 → 카드 → 프로필 시트 → [쪽지 쓰기] → 작성 시트 → 확인창 → (닫힘) → 프로필 시트
받기     홈 → 지금까지의 소식 → ✉️ `누군가 쪽지를 보냈어요` + 본문 + `누구인지는 비밀이에요`
운영자   참가자 탭 → 상세 시트 → `쪽지` 묶음 (→ 상대 / ← 상대 · 본문 · 시각 · 지우기)
```

### E1. 운영자 설정 — `쪽지 (0~5)` 한 줄

**세 화면 같은 부품.** 위저드 3스텝(`투표·콕 설정`) · 설정 탭 `투표·콕 설정` 묶음 · 회차 기본 설정 —
셋 다 `파티 콕 (1~10)` 과 같은 스테퍼(`Num`)다. 라벨은 `쪽지 (0~5)`. 콕 라벨이 범위를 괄호로 말하는 꼴 그대로다.

**자리는 묶음의 맨 끝이다** — 위저드와 설정 탭에서 `콕 알림` 토글 **아래**. 콕의 다섯(횟수 둘 · 대상 · 알림 둘)은
콕 하나의 규칙이라 붙어 있어야 하고, 굳는 셋(ADR-35)이 한 덩어리로 잠기는 모양도 그대로 남는다. 쪽지는 그 뒤에
혼자 선다 — 콕이 아니고, 굳지도 않는다. 기본 설정 화면에는 토글이 없으므로 `파티 콕` 바로 아래다.
위저드의 예상 매칭 문구(`적당해요`)는 매력 투표 횟수 아래 그대로다 — 쪽지가 그 문구 위로 끼어들지 않는다.

- **설명 줄은 없다** (ADR-54). `0~5` 가 0 을 말한다 — 0 장이면 아무도 못 보내는 것이고, 그게 곧 *이 회차에는 없다* 다
- **굳지 않는다.** `rulesLocked` 밖이다 — 콕 횟수처럼 파티 중에 올릴 수 있다. 토글 셋이 `표와 콕이 오가기
  시작해서 바꿀 수 없어요` 로 잠긴 뒤에도 이 줄은 산다
- **바닥이 있다.** 설정 탭에서는 `min = max(0, noteUsedMax)` — 이미 3장 보낸 사람이 있으면 2 로 못 내린다.
  서버도 같은 규칙으로 거절한다 (`noteFloor`: `이미 3장 보낸 참가자가 있어요. 3장보다 적게는 줄일 수 없습니다.`)
- **옛 회차는 0 이다.** `maxNotes` 가 없는 회차는 쪽지가 없는 회차다 — 값을 채워 넣지 않는다.
  새 회차는 기본 설정의 값(기본 2)을 들고 시작한다
- **확인창들.** 설정 적용 `쪽지  2장 → 3장` · 기본 설정 되돌리기 `쪽지  3장 → 2장` · 회차 삭제 `쪽지  N장 → 삭제` ·
  참가자 내보내기 `보낸 쪽지  N장 → 남겨둠`(문단의 *받은 표와 콕* 에 쪽지를 더한다). 단위는 **장**이다 (`UNIT.sheets`) —
  콕의 `회` 와 갈라야 확인창에서 두 줄이 다른 것으로 읽힌다
- **묶음 이름은 그대로다** (`투표·콕 설정`). `투표·콕·쪽지` 는 가운뎃점 셋을 잇는 것이라 문구 규칙에 걸리고,
  위저드 스텝 이름과 짝이라(테스트) 바꾸면 둘을 같이 바꿔야 한다. 쪽지 한 줄 때문에 이름을 늘리지 않는다

### E2. 보내는 쪽 — 프로필 시트 · 작성 시트 · 확인창 · 홈

**입구는 프로필 시트 하나다.** 참가자 탭 목록에는 아무것도 더하지 않는다 — 카드 오른쪽은 👉 하나라야 하고
(*한 줄에 둘이면 카드가 화면 밖으로 밀린다*, UI.md), 목록에 `보냈어요` 같은 표시가 서면 가리기가 덮어야 할
자리가 하나 는다. 쪽지는 글을 쓰는 일이라 두 번 눌러 들어가는 것이 맞다 — 콕은 손끝이고 쪽지는 마음먹는 것이다.

**프로필 시트** (파티 중 · `maxNotes > 0` · 발표 전) — 매력 전문 아래, `닫기` 위에 한 묶음이 선다.

```
이 사람의 매력
[ 매력 1 ]  [ 매력 2 ]  [ 매력 3 ]

[ ✉️ 쪽지 쓰기 ]                              ← .btn block (채우지 않는다 — 이 시트의 주인공은 👉 다)
쪽지 2장 남았어요                              ← 아래 한 줄 (small dim)
  · 보낸 적 있으면  이 사람에게 1장 보냈어요 · 1장 남았어요
  · 다 썼으면       쪽지를 다 썼어요             (0장이라고 쓰지 않는다)

[ 닫기 ]
```

- **버튼은 늘 눌린다.** 다 썼어도 눌리고, 누르면 토스트 `쪽지를 다 썼어요 (최대 2장)` — 콕 버튼과 같은 규칙이다
  (*눌러도 아무 일이 없으면 고장으로 읽힌다*). 되돌리기는 없으므로 콕처럼 창이 열리지는 않는다
- **파티 전에는 묶음 자체가 없다.** 잠긴 버튼을 미리 세우지 않는다 — 콕 버튼은 목록의 주인이라 자리를 지키지만
  이 버튼은 아니고, 매력 투표 화면에서 파티의 일을 말하지 않는 것이 ADR-96 의 방향이다. 발표 뒤에도 없다
- **가리기 중에는 `이 사람에게 N장 보냈어요` 를 그리지 않는다** (슬라이스 16). 남은 장 수만 남는다 —
  누구에게 보냈는지가 새는 자리는 이 한 줄뿐이다. 콕 버튼의 숫자가 가려지는 것과 같은 이유다
- **보낸 뒤 이 줄이 곧 알림이다** (ADR-65). 토스트를 띄우지 않는다 — 시트 위에 뜨는 토스트는 `닫기` 를 덮는다.
  작성 시트가 닫히며 돌아온 자리에서 `이 사람에게 1장 보냈어요` 로 바뀐 줄을 본다

**작성 시트** `/e/:code/p/:pid/note` — 프로필 시트 위에 **push** 로 열리는 시트. 뒤로 가기가 곧 취소다.

```
달빛님에게 쪽지                                ← sheetTitle
쪽지 (120자까지)                               ← label
┌────────────────────────────────────────┐
│                                        │   ← textarea rows=4 · maxLength 120
│                                        │
└────────────────────────────────────────┘
상대에게는 누가 보냈는지 보이지 않아요.        ← tiny dim, 두 줄
답장은 오지 않아요.
[ 쪽지 보내기 ]                                ← .btn primary block · 비면 disabled
```

- **열릴 때 글 칸에 커서를 준다** — ADR-63 의 예외 2호 (`Sheet` 의 `autoFocus`). 입장 확인창처럼 **칠 것밖에
  없는 창**이고, 사람이 `쪽지 쓰기` 를 눌러 들어왔다. 시트는 `--kb` 만큼 올라오므로 키보드 위에 선다
- **글자 수 세는 줄은 없다.** `maxLength` 가 막고 라벨이 `120자까지` 를 말한다 — 매력 칸(100자)과 같다
- **자리 표시 문구(placeholder)를 두지 않는다.** 예문이 있으면 그 결로 쓴다 — 무슨 말을 할지는 앱이 정할 일이 아니다
- **첫 줄의 안심은 `POKE.confirm.note` 와 같은 꼴이다** — `상대에게는 누가 골랐는지 보이지 않아요` 를
  `누가 보냈는지` 로. 둘째 줄이 답장이 없다는 것을 **보내는 쪽에** 먼저 말한다 — 안 온 답을 기다리지 않게
- **뒤로 가기 = 취소. 쓰던 글은 버려진다** — 내 정보 고치기와 같다 (ROUTES.md). 120자에 이탈 방지를 걸지 않는다.
  시트를 맨 위에서 끌어 닫는 것도 같은 취소다 — 글 칸에서 시작한 끌기는 잡지 않는다 (`Sheet`)
- **조건이 안 맞는 주소를 직접 열면**(파티 중이 아님 · 0장 · 발표 뒤) 프로필 시트로 **갈아끼운다** —
  `/seat` 와 같은 규칙이다. 직접 연 사람에게는 뒤로 갈 자리가 없다

**확인창** — `쪽지 보내기` 를 누르면 작성 시트 위에 뜬다 (`confirm`, 가운데 창).

```
쪽지를 보낼까요?            (이미 보낸 사람에게는  한 장 더 보낼까요?)
┌ 받는 사람   달빛                 ┐
└ 남은 쪽지   2장 → 1장            ┘
보낸 뒤에는 되돌릴 수 없어요.
[ 보내기 ]
[ 취소 ]
```

- 되돌릴 수 없는 행동이라 확인이 붙는다 (전역 원칙). 항목은 둘 — **누구에게**와 **무엇이 얼마나 바뀌나**.
  `남은 쪽지` 는 홈과 시트의 숫자와 같은 이름·같은 왼쪽 값이다 (콕 확인창이 배운 것)
- 본문은 항목에 넣지 않는다 — 바로 뒤 작성 시트에 그대로 있다
- **히스토리** — 작성 시트(push) 위에 확인창(push). `보내기` 는 실행 **전에** 확인창을 `navigate(-1)` 하고,
  보내기가 **성공하면** 작성 시트도 `navigate(-1)` 로 닫는다 → 프로필 시트. 실패하면 작성 시트에 남고 버튼 아래
  `.err` 한 줄, 글은 그대로다 — 서버가 준 문장(`지금은 쪽지를 보낼 수 없어요` · `쪽지를 다 썼어요 (최대 2장)`)
- **보내는 중에는 다시 안 보낸다** (`sending` ref) — 콕과 같은 이유. 다만 콕처럼 화면을 먼저 바꾸지는 않는다.
  보낸 뒤 화면이 바뀌는 자리가 프로필 시트의 한 줄이라, 서버 답(`MyNoteState`)으로 그 줄을 갈아끼운다

**홈** — 파티 중 할 일 카드의 kicker 줄에 한 줄 더.

```
이제 직접 만나보고 콕 찔러보세요
나이와 MBTI 도 함께 볼 수 있어요.
발표 때 이어지는 건 여기서 보낸 콕이에요.
콕 2회 남음                                    ← STATUS.pokeLeft (있던 것)
쪽지 2장 남음                                   ← 새 kicker. 0 이면 줄이 없다
[ 참가자 보러 가기 ]
```

- 카운트다운 카드가 할 일 카드 밖으로 나간 이유(*하나는 시계고 하나는 예산*)는 여기 걸리지 않는다 —
  둘 다 예산이라 같은 무게로 나란히 서는 것이 맞다
- 콕을 다 써서 제목이 `콕을 다 보냈어요` 로 바뀌어도 쪽지가 남았으면 이 줄은 남는다. 쪽지가 0장이면 줄이 없다 —
  `0장` 을 들이대지 않는다
- **파티 시작 소식**(`NOTICE.party`)의 몸글에 둘째 줄이 붙는다 — `쪽지 2장도 보낼 수 있어요` (`maxNotes > 0` 일 때만).
  단계 안내 전체 화면(ADR-96)은 손대지 않는다 — 한 화면에 한 가지다. 쪽지가 있다는 것을 참가자가 처음 만나는
  자리는 이 소식 줄과 홈 카드의 kicker, 그리고 프로필 시트의 버튼이다

### E3. 받는 쪽 — 홈 소식

```
지금까지의 소식
┃ ✉️  누군가 쪽지를 보냈어요                    ← .banner. 제목은 받은 콕 줄과 같은 주어(누군가)
┃     아까 웃는 모습이 좋았어요.                ← 본문 그대로 (small pre — dim 이 아니다, 이게 내용이다)
┃     오늘 재밌게 보내세요
┃     누구인지는 비밀이에요                     ← tiny dim · POKE.receivedNote 그대로
┃ 👉  누군가 콕! 찔렀어요
┃     누구인지는 비밀이에요
┃ 🎉  파티가 시작됐어요                        ← 시각 있음
┃     파티 라운드 콕 2회를 새로 받았어요
┃     쪽지 2장도 보낼 수 있어요
```

- **한 장에 한 줄.** 합쳐서 `쪽지 2장` 으로 세지 않는다 — 받은 콕과 같다. 본문이 있으니 합칠 수도 없다
- **시각이 없다** (`at: 0`). 차례는 `fired.party + 2` — 받은 파티 콕(`+ 1`) **위**, 파티 시작 알림 위다.
  말이 실린 줄이 똑같은 콕 줄들보다 위에 서는 것이 읽기 순서에 맞고, 어느 쪽이든 시각을 말하지 않는다.
  쪽지끼리는 서버가 저장한 순서의 역순이다 — 위가 최신 (ADR-48). ⚠️ 진짜 도착 시각을 순서에 쓰지 마라
- **배너 없음** (`bannerable: false`) · **움직임 없음** (ADR-64) · 탭에 숫자 배지 없음 · 소리 없음
- **누를 것이 없다.** 홈의 소식 줄은 `<div>` 다 — 답장·반응·신고 어느 버튼도 없다. 링크도 안 눌린다
- 본문은 `pre` 로 줄바꿈만 살리고, 120자가 넘어가지 않으니 접지 않는다. `overflow-wrap: anywhere` 가 공백 없는 글을 받는다
- 발표 뒤에도 남는다. 운영자가 지우면 다음 읽기에서 사라진다 — `broadcast()` 가 다시 읽게 한다.
  보낸 사람이 지워져도 남는다 (S-D1)

### E4. 운영자 — 참가자 상세

`보낸 콕 N회` 아래 두 줄, 그리고 떨어뜨려 앉히기 위에 한 묶음.

```
낸 표 1회
보낸 콕 2회
보낸 쪽지 2장                                   ← Row (라벨만)
받은 쪽지 1장

쪽지                                            ← kicker mt
┌ → 달빛 · 이하늘            21:03  [지우기] ┐    ← .fact. 첫 줄: 방향 + 닉네임 · 실명 + 시각, 오른쪽 ghost 버튼
│   아까 웃는 모습이 좋았어요. 오늘 재밌게…    │    ← 본문 (pre)
└─────────────────────────────────────────┘
┌ ← 별빛 · 김민수            21:10  [지우기] ┐
│   …                                      │
└─────────────────────────────────────────┘
┌ → 지워진 참가자            21:12  [지우기] ┐    ← 상대가 지워졌으면 이름 자리에 이 말
```

- **운영자만 전체를 본다** (원칙 2). 방향·상대·시각까지 — 여기는 참가자 응답이 아니다. 시각은 신고를 받았을 때
  *방금인가 아까인가* 를 가르는 데 쓴다
- **`지우기` 는 확인창을 거친다** (되돌릴 수 없다). 설문 지우기와 같은 꼴 —
  `보낸 사람  이하늘` · `받는 사람  달빛` · `받는 쪽 화면  사라져요`, 문단 `지운 쪽지는 되돌릴 수 없어요.
  보낸 사람이 쓴 장 수는 그대로예요.` 지운 줄이 목록에서 사라지는 것이 곧 알림이다 — 토스트 없음
- 같은 사람에게 여러 장 간 것은 **줄이 여럿 선 것으로** 보인다. 요약 문구(`한 사람에게 3장`)는 따로 두지 않는다 —
  줄이 이미 말한다
- **현황 탭에는 아무것도 없다.** 순위도 합계도 — 받은 쪽지 수는 받은 콕과 같은 이유로 사람마다 세어 보여주지 않는다 (ADR-22·30)

### E5. 도움말

`maxNotes > 0` 인 회차에만 문답 하나. `상대가 아나요` 바로 아래 — 같은 질문(익명)의 자리다.

```
Q  쪽지는 누가 보낸 건지 알 수 있나요?
A  아니요. 끝까지 익명이고 답장도 없어요. 파티 중에 한 사람이 2장까지 보낼 수 있어요.
```

- 숫자는 회차 설정에서 온다 — 문구에 박아두면 곧 거짓말이 된다 (`count` 문답과 같다)
- 0 인 회차에는 줄 자체가 없다. 안 묻는 답을 적는 만큼 묻는 답이 뒤로 밀린다 (`sameGender` 문답의 규칙)
- 한 문답에 셋을 답한다 — 누가(익명) · 답장(없음) · 몇 장. 셋으로 가르면 문답 넷 중 셋이 쪽지가 된다

### E6. 라우트 · 히스토리 (ROUTES.md 에 옮길 줄)

| URL | 화면 |
|---|---|
| `/e/:code/p/:pid/note` | **쪽지 작성 시트** (모달). 프로필 시트에서 push 로 열고, 뒤로 가기가 곧 취소다. 보내면 `navigate(-1)` 로 닫혀 프로필 시트로 돌아온다. 파티 중이 아니거나 `쪽지` 가 0 이거나 발표 뒤면 `/e/:code/p/:pid` 로 **갈아끼운다** |

| 전환 | 방식 | 이유 |
|---|---|---|
| 프로필 시트 → 작성 시트 | push | 뒤로 가기 = 취소. 쓰던 글은 버려진다 |
| 작성 시트 → 확인창 | push (state) | `Overlays` 규칙 그대로 — 실행 전에 `navigate(-1)` |
| 보내기 성공 → 프로필 시트 | `navigate(-1)` | 뒤로 가기와 같은 길이다. 갈아끼우면 히스토리에 작성 시트가 남아 뒤로 가기가 빈 칸을 다시 연다 |

### E7. 응답과 저장 모양

**참가자** — `ParticipantState.note: MyNoteState`. 만드는 곳은 하나다 (`toMyNotes`, `toPublic` 옆).

```ts
interface MyNoteState {
  budget: { max: number; used: number };   // max 는 회차의 maxNotes (없으면 0)
  sentTo: Record<string, number>;          // playerId → 내가 보낸 장 수. 프로필 시트의 한 줄이 쓴다
  received: string[];                      // 본문만, 최신이 앞. fromId 도 id 도 at 도 없다
}
```

- `received` 가 문자열 배열인 것이 방어다 — 담을 자리가 없으면 새지 않는다 (`MatchInfo` 의 논리).
  React 키는 차례다. 목록은 다시 읽을 때만 바뀐다
- `EventConfig.maxNotes?: number` — **없으면 0.** `LIMITS.maxNotes = { min: 0, max: 5 }` · `LIMITS.noteMax = 120` ·
  `DEFAULTS.maxNotes = 2`
- `NOTICE.party` 의 둘째 줄과 도움말·홈 kicker 는 `config.maxNotes` 로 판정한다 — 한 값이 세 자리를 연다

**운영자** — `HostState.notes: HostNote[]` (최신이 앞) · `noteUsedMax: number` · `noteCount: number`.

```ts
interface HostNote { id: string; fromId: string; toId: string; text: string; at: number }
```

- 지워진 참가자의 `fromId` 는 `players` 에 없다 — 화면이 `지워진 참가자` 로 그린다

**API**

| | |
|---|---|
| `POST /api/note` `{ toId, text }` | → `MyNoteState`. 409 `closed`(파티 중 아님) · 409 `no_budget`(다 씀, `max` 를 실어) · 400(비었거나 120자 초과, 자기 자신, 없는 사람) |
| `PUT /host/events/:id` `config.maxNotes` | 있는 경로. 이미 쓴 장 수 아래면 409 `conflict` + `noteFloor` 문장 |
| `DELETE /host/events/:id/notes/:nid` | 지우기. `broadcast()` |

**저장** — 회차 DO 의 새 표 `notes(id, from_id, to_id, body, at)`. **새 표라 `CREATE TABLE IF NOT EXISTS` 로 충분하다** —
옛 표에 칸을 더하는 것이 아니므로 CLAUDE.md 의 인덱스 함정(`no such column`)에 안 걸린다. 참가자를 지울 때
`to_id` 가 그 사람인 줄만 지운다 (S-D1). 콕 로그에는 쓰지 않는다 (S-D4). 보내고 지운 뒤 `broadcast()` 한 번 —
받는 쪽이 다시 읽는다. 지표(`pulse`)에는 아무것도 더하지 않는다.

## 문구 — `NOTE`

| 자리 | 문장 | 어체 |
|---|---|---|
| 프로필 시트 버튼 | 쪽지 쓰기 | 버튼 = 명사형 |
| 버튼 아래 · 남은 장 수 | 쪽지 2장 남았어요 | |
| 버튼 아래 · 보낸 적 있음 | 이 사람에게 1장 보냈어요 · 1장 남았어요 | |
| 버튼 아래 · 다 씀 | 쪽지를 다 썼어요 | `0장` 을 쓰지 않는다 |
| 작성 시트 제목 | `${nick}님에게 쪽지` | |
| 칸 라벨 | 쪽지 (120자까지) | |
| 칸 아래 안심 | 상대에게는 누가 보냈는지 보이지 않아요.\n답장은 오지 않아요. | 안심 = `~지 않아요` |
| 보내기 버튼 | 쪽지 보내기 | |
| 확인창 제목 | 쪽지를 보낼까요? / 한 장 더 보낼까요? | 콕 확인창과 같은 꼴 |
| 확인창 항목 | 받는 사람 · 남은 쪽지 (`2장 → 1장`) | |
| 확인창 문단 | 보낸 뒤에는 되돌릴 수 없어요. | |
| 확인 버튼 | 보내기 | |
| 홈 kicker | 쪽지 2장 남음 | `STATUS.pokeLeft` 와 같은 꼴 |
| 파티 소식 둘째 줄 | 쪽지 2장도 보낼 수 있어요 | 할 수 있는 것 = `~할 수 있어요` |
| 받은 줄 제목 | 누군가 쪽지를 보냈어요 | `POKE.received` 와 같은 주어 |
| 받은 줄 아래 | 누구인지는 비밀이에요 | `POKE.receivedNote` **그대로** |
| 닫힘 (서버) | 지금은 쪽지를 보낼 수 없어요 | |
| 다 씀 (토스트·서버) | 쪽지를 다 썼어요 (최대 2장) | `POKE.blocked.noBudget` 과 같은 꼴 |
| 도움말 | 쪽지는 누가 보낸 건지 알 수 있나요? / 아니요. 끝까지 익명이고 답장도 없어요. 파티 중에 한 사람이 2장까지 보낼 수 있어요. | |
| 운영자 라벨 | 쪽지 (0~5) | `파티 콕 (1~10)` 과 같은 꼴 |
| 운영자 바닥 | 이미 3장 보낸 참가자가 있어요. 3장보다 적게는 줄일 수 없습니다. | `pokeFloor` 와 같은 꼴 |
| 운영자 상세 줄 | 보낸 쪽지 2장 · 받은 쪽지 1장 | `sent` 와 같은 꼴 |
| 운영자 상세 묶음 | 쪽지 · 지워진 참가자 · 지우기 | |
| 지우기 확인창 | 이 쪽지를 지울까요? · 보낸 사람 · 받는 사람 · 받는 쪽 화면 (`사라져요`) · 지운 쪽지는 되돌릴 수 없어요. 보낸 사람이 쓴 장 수는 그대로예요. | 설문 지우기와 같은 꼴 |
| 단위 | `UNIT.sheets = (n) => \`${n}장\`` | 콕의 `회` 와 가른다 |

어체는 ADR-89 후기의 표를 따른다 — 안심은 `~지 않아요`, 할 수 있는 것은 `~할 수 있어요`, 버튼은 명사형.
`쪽지` 는 이 슬라이스가 앱에 들이는 유일한 새 낱말이다 — `메시지`·`편지`·`DM` 을 섞어 쓰지 마라.
