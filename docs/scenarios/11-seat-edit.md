# 슬라이스 11 — 앉힌 자리 고치기

발행한 라운드는 지금까지 **손댈 수 없는 것**이었다. 유일한 수단이 새 라운드 발행이라,
한 명이 늦게 왔다고 전원이 자리를 옮기고 전원이 확인 화면을 다시 받았다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 범위

**만든다** — 라운드 하나에 대한 조작 셋. **초안에도, 발행된 라운드에도** 똑같이 된다.

| | 하는 일 |
|---|---|
| **앉히기** | 이 라운드에 자리 없는 사람을 넣는다. **테이블은 서버가 고른다** |
| **맞교환** | 앉은 두 사람을 바꾼다 (있던 것을 발행된 라운드까지 넓힌다) |
| **자리 비우기** | 한 사람을 이 라운드 자리에서 뺀다. 참가자를 지우는 게 아니다 |

**안 만든다**
- **참석 상태.** 사람에게 붙는 `불참` 플래그를 만들지 않는다 — 상태는 시간이 지나면 틀리고,
  틀린 상태는 다음 라운드에서 사람을 **조용히** 빠뜨린다. 라운드마다 고치는 방식은 기억이 없어 낡지 않는다
- **배정 입력 좁히기.** `buildSeating` 은 계속 전원을 앉힌다. 그래서 지난 라운드에서 비운 사람도
  다음 배정에는 다시 들어온다 — 상태를 만들지 않는 대가이고, 지금은 그 값을 치른다
- **운영자가 테이블을 고르는 앉히기.** 그건 `SEATING.md` 가 금지한 단일 이동 API 다
- 자리 없는 사람에게 "당신은 자리가 없습니다" 라고 알리는 것

---

## A. 앉히기

### S-A1 ★ 테이블은 서버가 고른다
```
Given  이 라운드에 자리가 없는 남성 참가자가 있다
When   운영자가 그를 앉힌다
Then   그의 성별이 가장 덜 찬 테이블에 앉는다
```
> 운영자가 테이블을 고르게 하면 그게 곧 **한 명만 옮기는 API** 다.
> 성비는 "지키려고 노력"하는 게 아니라 깨질 방법이 없어야 한다 (`SEATING.md`).
> 같으면 사람이 적은 테이블, 그것도 같으면 낮은 번호 — **난수를 쓰지 않는다.**

### S-A2 ★ 이미 앉은 사람은 앉히지 않는다
```
Then   같은 사람이 두 자리에 있지 않다
```

### S-A3 발행된 라운드에서도 된다
```
Given  이미 발행한 라운드다
When   늦게 온 사람을 앉힌다
Then   그 사람 화면에 테이블 번호가 뜬다
```

---

## B. 자리 비우기

### S-B1 ★ 참가자를 지우는 것이 아니다
```
When   한 사람의 자리를 비운다
Then   그는 명단에도, 콕 대상에도 그대로 있다
And    그가 주고받은 콕과 매칭은 아무것도 바뀌지 않는다
```
> 지우면 그가 만든 매칭이 **상대에게서도 사라진다** (`FLOWS.md`).
> 집에 간 사람도 서로 찔렀으면 발표에서 서로의 **이름**을 보는 게 이 앱의 목적이다 (ADR-42 — 연락처는 나가지 않는다).

### S-B2 비운 자리는 다시 앉힐 수 있다
```
Then   되돌릴 수 있으므로 확인창을 붙이지 않는다 (ADR-6)
```

---

## C. 알림

### S-C1 ★ 발행된 라운드를 고쳐도 자리 이동 확인이 뜨지 않는다
```
Given  발행된 라운드에서 두 사람을 맞바꾼다
Then   그 둘의 화면에 확인 화면이 뜨지 않는다
And    테이블 번호는 다시 읽어서 바뀐다
```
> 전원이 한꺼번에 움직이는 건 **발행**뿐이고, 그때만 확인 화면이 뜬다.
> 라운드 하나를 고치는 건 운영자가 그 사람 앞에 서서 하는 일이라 앱이 대신 말할 게 없다.
>
> **`acks` 의 뜻이 "이 자리를 안다" 로 넓어진다** — 앱이 확인을 받았거나, 운영자가 직접 앉혔거나.
> 발행된 라운드에 앉히면 `acks` 에 함께 넣는다. 안 그러면 그 사람만 확인 화면이 뜬다.

### S-C2 ★ 화면은 조용히 어긋나지 않는다
```
Then   고친 즉시 `seating` 방송이 나가고 참가자가 다시 읽는다
```
> 실시간은 "다시 읽어라" 신호로만 쓴다 (ADR-26). 알림을 안 보내는 것과
> 화면을 안 고치는 것은 다른 일이다.

---

## D. 닫히는 때

### S-D1 ★ 발표 후에는 셋 다 막힌다
```
Then   409
```
> 발표만이 자리를 끝낸다. 확정은 끝내지 않는다 (ADR-28).

### S-D2 ★ 쌍을 떼는 맞교환은 무엇이 깨지는지 말한다

> 커플 자리 라운드에서만 그랬는데 **모든 라운드로 넓혔다** (ADR-51).
> 쌍을 붙이는 일이 알고리즘에서 운영자의 손으로 옮겨왔기 때문이다.
```
Then   떨어지는 쌍을 이름으로 보여주는 확인창을 거친다 (ADR-23)
```
> 있던 규칙을 발행된 라운드까지 넓히는 것뿐이다.
> `앉히기`·`자리 비우기` 는 아무도 옮기지 않으므로 쌍을 깨지 않는다.
