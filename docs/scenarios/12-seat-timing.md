# 슬라이스 12 — 자리는 파티가 시작돼야 보인다

> **⚠️ A 절은 폐기됐다 (ADR-37 · 슬라이스 29).** 자리는 이제 **발행하면** 보인다 —
> 파티가 시작되기 전에도. 짜는 동안 새지 않게 하는 일은 **초안**이 맡는다.
> 방어가 둘이었고 하나면 충분했다. B·C 절은 그대로다.

운영자가 자리를 미리 짤 수 없었다. **짜는 순간 참가자에게 나갔기 때문**이다 —
`mySeat()` 이 단계를 보지 않아서, 사전 투표 중에 발행하면 그 자리에서
테이블 번호가 뜨고 전체 화면 확인창이 덮쳤다.

그래서 지금은 파티가 시작된 뒤에 급히 배정하게 되는데, 그게 정확히 피하려던 상황이다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 범위

**만든다**

| | |
|---|---|
| 자리는 **파티 시작부터** 참가자에게 보인다 | 그 전에 발행해둬도 응답에 없다 |
| 파티 시작 확인창이 **배정 인원을 숫자로** 말한다 | 자리 없이 시작하려는 걸 그 자리에서 안다 |
| 자리 확인 화면을 **다시 열 수 있다** | 실수로 눌러도 잃는 게 없다 |

**안 만든다**
- 자동 배치. 테이블 수는 배정을 **누를 때** 묻는 값이다 (ADR-5) — 자동으로 하면 그 값을 설정으로 되돌리는 일이다
- 자리 발행을 파티 시작 전에 막는 것. **미리 짜두는 게 목적**이라 반대로 가면 안 된다
- 늦게 온 사람에게 확인창을 안 띄우는 것. 띄우되 **다시 열 수 있으면** 충분하다

---

## A. 언제 보이나

### S-A1 ★ 사전 투표 중에 발행해도 참가자 응답에 자리가 없다
```
Given  사전 투표 단계다
When   운영자가 자리를 배정하고 발행한다
Then   참가자 응답의 seat 가 비어 있다
And    전체 화면 확인창도 뜨지 않는다
```
> **화면에서 감추는 것으로는 부족하다** — 개발자 도구를 여는 참가자가 있다.
> 남의 테이블까지 보이면 누가 어디 앉는지가 파티 전에 다 새어 나간다.

### S-A2 ★ 파티가 시작되면 그 순간 보인다
```
When   운영자가 파티 시작을 누른다
Then   참가자 응답에 seat 가 있고, 확인창이 뜬다
```
> 단계 전환 방송이 이미 전원 재조회를 부른다 (ADR-26).
> **파티 시작 버튼이 그대로 자리 알림이 된다** — 새 장치를 만들지 않는다.

### S-A3 발표 후에도 자리는 남는다
```
Then   seat 는 그대로 있고, 확인창만 안 뜬다
```
> 매칭 상대와 같은 테이블이었는지를 발표 화면이 쓴다 (`MatchInfo.sameTable`).

---

## B. 자리 없이 시작하려 할 때

### S-B1 ★ 파티 시작 확인창이 배정 인원을 말한다
```
Then   "배정된 자리  50명 중 50명" 또는 "아직 없어요"
```
> 자리 없이 시작하면 참가자 전원이 `자리가 정해지면 여기에 알려드려요` 만 본다.
> 운영자는 누른 뒤에야 그걸 알았다. **막지는 않는다** — 자리 없이 여는 회차도 있다.

---

## C. 다시 열기

### S-C1 ★ 홈의 자리 카드를 누르면 확인 화면이 다시 열린다
```
Given  이미 확인을 눌렀다
When   홈의 자리 카드를 누른다
Then   같은 전체 화면이 다시 뜬다
```
> 늦게 도착해 앱을 처음 켜는 사람에게 전체 화면이 덮치면 **반사적으로 누르기 쉽다.**
> 막는 쪽(확인을 어렵게)으로 풀면 나머지 사람이 불편해진다 — 되돌릴 수 있게 한다.

### S-C2 ★ 라우트다 — 뒤로 가기로 닫힌다
```
/e/:code/seat
```
> 모달·시트는 라우트다 (`ROUTES.md`). 자동으로 뜨는 쪽은 라우트가 아니다 —
> 참가자가 연 게 아니라 **아직 안 본 것**이라서 주소를 바꿀 일이 아니다.

### S-C3 다시 연 화면에서는 확인을 다시 받지 않는다
```
Then   이미 확인한 사람에게는 닫기만 있다
```
> 이미 센 사람을 또 세지 않는다. `acks` 의 뜻은 **"이 자리를 안다"** 하나여야 한다.
