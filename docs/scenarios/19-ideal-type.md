# 슬라이스 19 — 이상형 찾기

파티에서 "이상형 연예인 누구예요?" 는 흔한 질문이고 대답하기 어려운 질문이다.
떠오르는 이름이 없어서가 아니라 **말하는 순간 그 이름이 나를 설명해 버려서**다.
그래서 앱이 대신 답을 찾아준다 — 끌리는 얼굴을 세 번 고르면 가장 가까운 연예인이 나온다.

**답을 찾는 건 앱이 하고, 말하는 건 본인이 한다.** 결과는 본인 화면에만 있다.
가림(슬라이스 16)과 같은 자세다 — 앱은 재료를 주고, 언제 누구에게 꺼낼지는 사람이 정한다.

`★` 는 반드시 테스트를 붙이는 것.

---

## 범위

**만든다**

|                                                         |                                                  |
| ------------------------------------------------------- | ------------------------------------------------ |
| 재미 탭 **세 번째 카드**                                | 운세 · 미션 아래. 파티 시작 후. 재미는 한 자리에 |
| 여·남 중 고르기 → 얼굴 여섯 중 둘 × 3라운드 → 연예인 셋 | 1분 안에 끝난다                                  |
| 결과는 회차 DO 에 1인 1행. **한 번 찾으면 그대로**      | 운세와 같은 규칙, 같은 저장 모양                 |
| 계산은 **기기에서**. 서버는 결과만 받는다               | DO 는 한 번 쓰고 끝. 파티 중 줄이 서지 않는다    |
| 얼굴 자료는 정적 자산. **열 때** 받는다                 | 안 여는 사람은 1바이트도 안 받는다               |

**안 만든다**

- **점수·퍼센트·유사도.** 순서만 있다. 운세에 점수가 없는 이유 그대로다 (ADR-20)
- **남에게 보이는 결과.** 명단·내 카드·프로필 시트 어디에도 없다. 보여주고 싶으면 폰을 보여준다.
  공개를 _본인이 고르게_ 하는 건 다음 슬라이스다 — 이번엔 없다
- **운영자 화면.** 운영에 필요 없는 건 운영자도 안 본다 (ADR-22 와 같은 결)
- **다시 하기.** 라운드 안에서 뒤로 가는 건 된다. 결과를 본 뒤에는 끝이다
- **사진 업로드 · 참가자 얼굴.** 위의 첫 규칙
- **고른 얼굴 저장.** 결과 셋만 남긴다. 고른 여섯은 결과보다 생생한 취향 자료인데 쓸 데가 없다
- **실시간 신호.** 내 결과는 나만 다시 읽으면 된다. `broadcast()` 를 건드리지 않는다
- **LLM.** 벡터 내적뿐이다. 외부 서비스가 없으니 파티 당일에 죽을 것도 없다

## A. 고르기

### S-A1 처음에 어느 쪽 얼굴을 볼지 고른다

```
Then   '여자' · '남자' 두 버튼이 같은 크기로 있고, 어느 쪽도 미리 눌려 있지 않다
```

> 누구에게 마음이 가는지는 앱이 정할 일이 아니다 (ADR-17). 내 성별의 반대를 미리 골라두지 않는다.

### S-A2 ★ 한 라운드에 얼굴 여섯, 3개 이하 고른다. 세 라운드

```
Then   얼굴 6개가 보이고, 1개 이상 골라야 '다음' 이 눌린다.
       마지막 라운드의 버튼은 '결과 보기' 다
```

> 여섯은 한 화면에 얼굴이 읽히는 크기로 들어가는 수다 (3×2, 한 칸 100px 이상).
> 얼굴 여섯은 최대한 다양한 얼굴들이 나와야한다.
> 사용자의 외적 이상형이 딱히 특정되지 않거나, 반대로 많이 특정되어 있을 수도 있다. 또는 이상형이 여러 개일 수도 있다. 그래서 1~3개 고를 수 있도록 한다. 4개 이상은 고를 수 없도록 한다.
> 세 라운드면 1분이다. 파티 테이블에서 폰을 보는 시간으로 그 이상은 길다. 세 라운드 만에 사용자 이상형에 부합한 연예인을 찾도록 해야한다.

### S-A3 ★ 같은 얼굴이 두 번 나오지 않는다

```
Given  1라운드에 나온 얼굴
Then   2·3라운드에 다시 나오지 않는다
```

> 다시 나오면 고장으로 읽힌다. 고르는 함수가 순수 함수라 이 규칙은 **테스트를 먼저 쓴다**
> (`buildSeating` 과 같은 예외).

### S-A4 뒤로 가면 이전 라운드다. 고른 건 남아 있다

> 라운드마다 push. 뒤로 가기 = 이전 라운드 (등록 스텝과 같다). 잘못 누른 건 여기서 고친다 —
> 그래서 결과 뒤에 '다시 하기' 가 없어도 된다.
> 카드를 닫고 나가면 고르던 건 버려진다. 1분짜리라 이어 하기를 만들지 않는다.

### S-A5 골랐음은 색으로만 말하지 않는다

> 테두리와 함께 ✓ 표시.

## B. 결과

### S-B1 ★ 연예인 셋. 첫 사람이 답이다

```
When   3라운드를 마치면
Then   가장 가까운 순서대로 사진을 나열한다.
```

> 첫 이름이 낯설 때 두 번째가 구해준다. **퍼센트는 없다.** 화면에 `%` 가 없는 것을 테스트로 고정한다 (운세와 같다).

### S-B2 ★ 고르는 동안 본 얼굴은 결과에서 나오지 않고, 밑에 따로 볼 수 있도록 되어있다.

```
Then   결과 셋은 라운드 화면에 나왔던 얼굴이 아니다. 그리고 따로 고른 얼굴도 볼 수 있도록 한다.
```

> 방금 고른 얼굴을 그대로 돌려주는 건 답이 아니다 — 그건 본인이 이미 아는 것이다.
> 답은 **안 본 사람 중에서** 나와야 "찾아줬다" 가 된다.
> 골랐던 얼굴도 이상형에 가까운 얼굴들이다. 결과와 따로 고른 선택 얼굴들도 볼 수 있도록 한다.

### S-B3 ★ 한 번 찾으면 그대로 남는다

```
Given  결과를 봤다
When   카드를 다시 연다 · 다시 읽는다 · 다른 기기에서 연다
Then   같은 결과다. 다시 고르는 길이 없다
```

> 두 번 저장돼도 먼저 온 것이 남는다 (`ON CONFLICT DO NOTHING`, 운세와 같다).
> 열 때마다 달라지면 테이블에서 한 말이 거짓말이 된다.
> **시작 화면에서 미리 말한다** — "한 번 찾으면 그대로 남아요". 운세가 뒷면에서 말하는 것과 같다.
> 확인창은 따로 띄우지 않는다 — 되돌릴 수 없는 행동이지만, 미리 말한 재미 기능에는 운세도 확인창이 없다.

### S-B4 결과 사진은 출처에 달렸다

> 이름은 항상 있다.

## C. 저장과 공개 범위

### S-C1 ★ 내 결과는 내 응답에만 있다

```
Then   roster 의 PublicPlayer 에 없다 · 프로필 시트에 없다 · HostState 에 없다
```

> `toPublic()` 을 건드리지 않는다. `ParticipantState.ideal` 한 칸이 전부다.

### S-C2 ★ 참가자를 지우면 결과도 사라진다

> 운세와 같다. 그 사람의 것은 그 사람과 함께 간다. 보낸 콕만 남는다 (ADR-29).
> ~~파기 Cron 은 DO 째 지우므로 저절로 따라간다.~~ **자동 파기는 걷어냈다 (ADR-36).**
> 회차는 운영자가 지울 때까지 남고, 지우면 DO 하나로 다 사라지는 것은 그대로다.

### S-C3 서버는 id 셋만 받는다. 계산하지 않는다

> 기기가 고른 결과를 `{ pool, result: [id, id, id] }` 로 보내고 DO 는 저장만 한다.
> 개발자 도구로 결과를 지어내 보내는 참가자가 있을 수 있다 — **그래서 뭐.** 본인만 보는 본인 결과다.
> 서버가 벡터를 들고 다시 계산하면 워커 번들이 수백 KB 무거워지고,
> 얻는 건 "본인이 본인을 못 속인다" 뿐이다. 이름은 기기가 자산에서 찾는다 — DO 에는 이름이 없다.

### S-C4 회차 DO 밖으로 나가지 않는다

> 운영 지표(`METRICS`)에 **결과를 넣지 않는다.** "이 파티 이상형 1위" 는 결과 통계다 — 운영 카운터가 아니다.
> 몇 명이 했는지(횟수)는 넣어도 된다. 누가 누구를 골랐는지는 안 된다.

## 숫자

|                    | 값                      | 왜                                                          |
| ------------------ | ----------------------- | ----------------------------------------------------------- |
| 라운드 M           | 3                       | 1분. 군집 단계와 같다 — 거칠게 → 가늘게 → 낱낱이            |
| 한 라운드의 얼굴 N | 6                       | 한 화면, 읽히는 크기                                        |
| 고르는 수 I        | 2                       | S-A2                                                        |
| 결과 J             | 3                       | 답 하나 + 구해주는 둘                                       |
| 풀                 | 성별마다 **200명 이상** | N^M = 216 — 셋째 단계가 낱낱이 되는 크기. 그보다 적으면 M=2 |

**고르는 방식 — 평균을 따라간다**

```
1라운드  1단계 대표 6 — 모두에게 같다. "첫 화면에서 누구 골랐어?" 가 된다
2라운드  지금까지 고른 것의 평균에 가장 가까운 2단계 대표 6 (본 얼굴 제외)
3라운드  같은 방법으로 3단계(= 풀 전체) 에서 6
결과     전체 평균에 가장 가까운 연예인 3 (본 얼굴 제외)
```

가지를 타고 내려가는 방식(고른 군집의 자식만 보여주기)도 검토했다. 둘을 골라 가지가 둘이 되면
어느 쪽 자식을 몇 개 보여줄지가 규칙이 되고, 그 규칙이 결과를 흔든다. 평균을 따라가면 규칙이 하나다 —
**가까운 것부터.** 취향이 둘로 갈리는 사람은 3라운드의 선택이 평균을 한쪽으로 끌고 간다.
계층 군집은 그대로 쓴다 — 단계마다 "얼마나 거친 후보 집합에서 고르나" 를 정하는 게 그 일이다.

## 먼저 확인할 것 — 화면을 만들기 전에

이 기능은 **"고른 얼굴 벡터의 평균에 가까운 연예인 = 내 이상형"** 이라는 가정 위에 서 있다.
얼굴 인식 모델의 벡터는 *누구인가*를 맞추도록 배운 것이지 *끌리는가*를 배운 게 아니다.
같은 사람의 사진은 모이고 다른 사람은 멀어지지만, **"내 취향" 이 그 공간의 한 점인지는 아무도 보장하지 않는다.**

그래서 화면 전에 종이로 잰다.

| 잰다                           | 방법                                                                                     | 판단                                                                            |
| ------------------------------ | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 결과가 그럴듯한가              | 성별당 60명짜리 작은 풀로 파이프라인을 돌리고, 다섯 명에게 노트북으로 세 라운드를 시킨다 | **다섯 중 넷**이 "내 취향 맞다" 가 아니면 벡터를 바꾼다 (인식 모델 → CLIP 계열) |
| 1분 안에 끝나나                | 같은 자리에서 잰다                                                                       | 90초를 넘으면 라운드를 줄인다                                                   |
| 첫 라운드 여섯이 충분히 다른가 | 1단계 대표를 나란히 본다                                                                 | 둘이 비슷해 보이면 군집을 다시 본다                                             |

종이 검증을 건너뛰고 화면부터 만들면, 화면이 다 된 뒤에 "결과가 이상하다" 를
벡터 탓인지 화면 탓인지 모르게 된다. 슬라이스 01 의 가짜 테스트와 같은 자리다 —
**구현 전에 가정이 참인지 본다.**

## 문구

`copy.ts` 에 넣는다. 기능 이름은 **이상형 찾기**. "연예인" 은 결과 화면에서만 쓴다

| 자리          | 뜻                                                    |
| ------------- | ----------------------------------------------------- |
| 첫 물음       | 어느 쪽 얼굴을 볼까요? — 여자 · 남자                  |
| 라운드 안내   | 이상형에 가까운 연예인을 1~3명을 골라주세요 · `1 / 3` |
| 다음 · 마지막 | 다음 · 결과 보기                                      |
| 결과 제목     | 내 이상형에 가장 가까운 얼굴                          |
| 자산 못 받음  | 얼굴을 못 불러왔어요. 잠시 뒤 다시 열어주세요         |

`열기` 를 쓰지 않는다 — 운세는 열면 나오지만 이것은 고르는 일이 남아 있다. 같은 말은 같은 무게여야 한다.
`예쁜`·`잘생긴` 을 쓰지 않는다. `끌리는` 이다 — 고르는 건 얼굴의 등급이 아니라 내 쪽의 마음이다.

## 정할 것 — 기획에서 열어둔 셋

1. **때.** 파티 시작 후 vs 등록부터. 앞당기면 오늘 탭 밖으로 나가야 한다
2. **접근.** 새로운 탭은 더 복잡하게 만든다. '오늘' 탭을 다른 이름으로 바꾸고, 그 탭에서 운세 기능과 이상형 찾기 기능 선택하고 접근할 수 있도록 해야한다.

## 고도화 방향

1. 사용자가 선택한 것과 결과에 대한 피드백 수집하여, 더 정확한 추천을 할 수 있도록 데이터로 사용한다. 부합하다는 반응과 부합하지 않다는 반응을 얻을 수도 있고, 아니면 사용자에게 결과 중에 진짜 이상형인 정답을 고르도록 할 수도 있다.
2. 이상형에 대해서 설명하는 글도 포함시킨다.

## 좀 더 고민해봐야할 것

1. 사람은 외적 이상형이 특정되어 있을 수도 있고, 특정되어 있지 않을 수도 있고, 없거나 여러 스타일을 좋아하는 경우도 있다.
2. 반대로 고르지 않은 연예인은 이상형과 멀다고 해석 가능할까?
3. 연예인 대부분은 외모가 뛰어난 편이다.
