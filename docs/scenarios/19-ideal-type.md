# 슬라이스 19 — 이상형 찾기

> **상태** — 구현됨 · 어디까지 나갔나는 `docs/PLAN.md` §6
> **이후 바뀐 것** — ADR-122 (재미 탭의 **두 번째** 카드 — 미션은 운세 카드 안이다 · 벡터는 인식 모델이 아니라 정해진 낱말로 고른 얼굴 속성 ·
> 종이 검증은 페르소나와 눈 가린 판정자로 네 번 돌렸고 운영자가 4차 자산으로 싣기로 정했다). 탭 이름은 `오늘` → `재미` (ADR-20 후기 2)
> · ADR-123 (v2 — 얼굴 **아홉** 중 **1~5** · 라운드마다 `다른 얼굴 보기` 한 번 · 고른 얼굴이 두 무리로 갈리면 두 무리를 각각 따라간다)
> · ADR-124 (재미 탭의 **첫** 카드 — 운세 위로 올렸다. 한 번 연 운세가 한 화면보다 길어 그 아래가 접혔다)
> · ADR-125 (재미는 **프로필 투표에 한 번에** 열린다 — 등록부터가 아니다 · 재미 탭에는 입구 카드만 선다 ·
> 결과 화면과 카드의 **`다시 찾기`** — 저장될 때만 바뀐다 · 정답은 결과마다 묻는다)
> · ADR-127 (v3 — 3라운드는 중심에 **가장 가까운 여섯을 결과 몫으로 남긴다** · 결과 위에 **끌린 얼굴의 특징** 한 장 ·
> 정답은 **여럿을 받는다**)
> · ADR-128 (끌린 얼굴 카드의 글 — 낱말 한 줄이 아니라 **그 얼굴에서 읽히는 사람** · 고른 얼굴의 특징과 거기서 받는 인상 · 연구 한 줄)
> · ADR-129 (리뷰 — 재미 탭에는 **소식 배너가 없다** · 정답 단추에 **얼굴** · 단계마다 **포커스**가 화면의 머리로 · 2 · 3라운드는 닮은 얼굴이라고 말한다)
> · ADR-132 (v4 — 벡터는 **얼굴 인식(SFace) + 얼굴 메시(MediaPipe)** 다. 참가자 평가가 `매우 부정확` 이었다 · 판에는 **배우 · 아이돌 · 가수 · 모델**만 싣는다 ·
> 두 갈래 문턱은 공간에 맞춰 −0.3 — v4 에서는 거의 평균 하나다)
> · ADR-135 (v5 — 운영자가 검수한 얼굴을 더해 **여 536 · 남 580** · 새 사람의 특징 낱말은 Claude 가 골랐다)
> · ADR-136 (v6 — 1라운드가 **모두에게 같지 않다.** 찾을 때마다 첫 화면 묶음 16벌 중 하나를 집어 무리의 다른 대표로 연다 ·
> 집은 번호는 결과와 함께 남는다)

파티에서 "이상형 연예인 누구예요?" 는 흔한 질문이고 대답하기 어려운 질문이다.
떠오르는 이름이 없어서가 아니라 **말하는 순간 그 이름이 나를 설명해 버려서**다.
그래서 앱이 대신 답을 찾아준다 — 끌리는 얼굴을 세 번 고르면 가장 가까운 연예인이 나온다.

**답을 찾는 건 앱이 하고, 말하는 건 본인이 한다.** 결과는 본인 화면에만 있다.
가림(슬라이스 16)과 같은 자세다 — 앱은 재료를 주고, 언제 누구에게 꺼낼지는 사람이 정한다.

`★` 는 반드시 테스트를 붙이는 것.

## 범위

**만든다**

|                                                            |                                                |
| ---------------------------------------------------------- | ---------------------------------------------- |
| 재미 탭 **첫 카드** (ADR-124)                              | 운세 카드 위. **프로필 투표부터** — 재미는 한 자리에, 한 번에 (ADR-125) |
| 여·남 중 고르기 → 얼굴 아홉 중 1~5 × 3라운드 → 연예인 셋   | 1분 안에 끝난다                                |
| 라운드마다 `다른 얼굴 보기` 한 번 — 아무것도 안 골랐을 때만 | 억지로 고른 얼굴이 평균을 흐리지 않게 (S-B7)   |
| 결과 위 **끌린 얼굴의 특징** 한 장 (ADR-127)               | 고른 얼굴로 센다 — 결과가 빗나가도 빗나가지 않는다 (S-C6) |
| 결과 아래 **정답 확인 한 번** — 여럿을 고를 수 있다 · 건너뛸 수 있다 | '결과가 취향에 맞나' 를 실전에서 재는 유일한 신호 (ADR-127) |
| 결과는 회차 DO 에 1인 1행. **저절로 바뀌지 않는다**        | 바꾸는 길은 `다시 찾기` 하나 — 저장될 때만 (ADR-125) |
| 계산은 **기기에서**. 서버는 결과만 받는다                  | DO 는 한 번 쓰고 끝. 파티 중 줄이 서지 않는다  |
| 얼굴 자료는 정적 자산. **열 때** 받는다                    | 안 여는 사람은 1바이트도 안 받는다             |

**안 만든다**

- **점수·퍼센트·유사도.** 순서만 있다. 운세에 점수가 없는 이유 그대로다 (ADR-20)
- **남에게 보이는 결과.** 명단·내 카드·프로필 시트 어디에도 없다. 보여주고 싶으면 폰을 보여준다.
  공개를 _본인이 고르게_ 하는 건 다음 슬라이스다 — 이번엔 없다
- **운영자 화면.** 운영에 필요 없는 건 운영자도 안 본다 (ADR-22 와 같은 결)
- ~~**다시 하기.** 라운드 안에서 뒤로 가는 건 된다. 결과를 본 뒤에는 끝이다 —
  '없었어요'(S-C4)도 다시 열지 않는다~~ — **들어왔다 (2026-09-28, ADR-125, 운영자).** 결과 화면과 재미 탭 카드의 `다시 찾기` (S-C3).
  '없음' 이 저절로 다시 찾기를 여는 일은 여전히 없다 — 단추는 답과 상관없이 결과 아래에 있다
- **사진 업로드 · 참가자 얼굴.** 닮은 순위가 생기는 순간 꼴찌가 생긴다 — 이 앱이 없애려던 경험이다
- **고른 얼굴을 취향 자료로 쓰는 것.** `picks` 는 저장하지만 (S-C2 가 다시 그릴 재료)
  쓰는 곳은 그 화면뿐이다 — 지표에도, 추천에도, 어디에도 안 흘린다.
  **예외 하나 — 설명글 (2026-10-06, ADR-134, QA 에서만)**: 글을 청할 때 2 · 3라운드의 연예인 사진과 골랐다는 표시가 LLM 으로 나간다. 참가자 정보는 없다
- **실시간 신호.** 내 결과는 나만 다시 읽으면 된다. `broadcast()` 를 건드리지 않는다
- ~~**LLM.** 벡터 내적뿐이다. 외부 서비스가 없으니 파티 당일에 죽을 것도 없다~~ — **설명글에 한해 들어왔다 (2026-10-06, ADR-134, 운영자 —
  QA 에서만).** 고르는 방식은 여전히 벡터 내적뿐이고, 글이 죽어도 화면은 고른 얼굴의 낱말로 쓴 글(ADR-128)로 선다

## 정했다 (2026-09-15)

기획에서 열어뒀던 것이 닫혔다. 판단 기준은 하나였다 — **파티 참가자의 경험이 먼저다.**

1. **때 — 등록부터** (S-A2). 등록~파티 사이가 이 앱에서 가장 빈 구간이다 (슬라이스 21 의 발견)
   — **프로필 투표부터로 옮겼다 (2026-09-28, ADR-125).** 운영자가 재미를 하나로 묶어 한 번에 열기로 했다
2. **접근 — 재미 탭 두 번째 카드** (S-A1). ADR-20 후기 2 가 탭 이름을 미리 넓혀 뒀다 — **첫 카드로 올렸다 (2026-09-28, ADR-124)**
3. **사진 — 실사. 고르는 것도 결과도** (S-C5). 공개 순간에 얼굴이 있는 쪽을 출처 확보 비용보다 앞에 뒀다
4. **정답 확인 — 이번 슬라이스** (S-C4). 고도화 방향 1 을 승격했다
5. **후보 다양성 — 라운드마다 좁힌다** (고르는 방식). 다양성은 '서로 다른 군집'이, 수렴은 '평균 근처'가 만든다

## 다시 정했다 (2026-09-28, v2 — ADR-123)

v1 을 싣기로 정한 날 운영자가 세 가지를 물었고, 셋 다 바꾸기로 했다. 결과를 정하는 것은 **고른 얼굴뿐**이다.

1. **얼굴 여섯은 적다 → 아홉(3×3), 1~5개** (S-B2). 보여주는 수가 늘면 고르는 질이 오른다
2. **끌리는 얼굴이 없으면 → 라운드마다 한 번 `다른 얼굴 보기`** (S-B7). 억지로 고른 '덜 싫은 얼굴' 이 평균을 흐리지 않게
3. **취향이 두 가지면 → 두 무리를 각각 따라간다** (고르는 방식 · S-C1). 평균 하나는 두 인상 사이로 떨어져 둘 다 아닌 얼굴을 가리켰다

## A. 자리와 때

### S-A1 ★ 재미 탭 첫 카드다

```
Then   재미 탭에 운세 카드 위 첫 카드로 있다 — 단계와 상관없이 늘 이 순서다
```

> 재미는 한 자리에. ADR-20 후기 2 의 다섯 문(본인만 · 한 번이면 그대로 · 점수 없음 ·
> 실패 무해 · 이야깃거리)을 다 지켜서 이 탭에 들어온다.
>
> **고쳤다 (2026-09-27)** — 처음에 `운세 · 미션 아래 세 번째 카드` 로 적었다. 미션은 카드가 아니라
> **운세 카드 안의 한 칸**이다 (UI.md — `카드는 하나다`). ADR-20 후기 2 가 적은 대로 두 번째다.
>
> **다시 고쳤다 (2026-09-28, ADR-124)** — 운세 **아래 두 번째**였다. 운세는 한 번 열면 한 화면보다 길어져서
> (360×640 에서 548~583px) 그 아래의 이 카드가 통째로 접힌 아래로 밀렸고, 한 번 연 운세는 그대로 남으니 내내 그랬다.
> 운영자가 새 기능을 위로 올렸다. 이 카드는 어느 때나 168px 이라 아래 운세의 머리를 가리지 않는다.

### S-A2 ★ 프로필 투표부터 열린다 — 재미는 한 번에

```
Given  등록을 마친 참가자
Then   프로필 투표부터 열린다 — 프로필 투표에도, 파티 중에도, 발표 뒤에도. 파티 운세 보기와 같은 문이다 (canOpenFun)
When   그 전이다 — 등록 중이거나, 운영자가 단계를 되돌렸다
Then   재미 탭은 켜져 있고 맨 위 한 줄이 언제 볼 수 있는지 말한다. 카드에는 무엇이 오는지만 있고 단추가 없다.
       서버도 새로 저장하지 않는다 (409). 이미 찾은 결과는 그대로 보이고 정답도 답할 수 있다
```

> 남의 데이터를 전혀 쓰지 않으니 명단(ADR-21)처럼 아껴 열 이유가 없다.
> 자산 다운로드도 파티 회선 밖으로 흩어진다.
> 탭의 문이 운세의 문(`canOpenFortune`)을 빌려 쓰던 것을 여기서 끝낸다 — 탭은 등록부터 켜져 있고,
> 운세·미션 카드는 각자의 문을 그대로 지킨다. ADR-20 후기 2 가 예비해 둔 자리다.
> 운세 카드는 그 문을 **자기 안에서** 말한다 — 매력 투표 전에는 생년월일 칸 없이 `FORTUNE.closed` 한 줄이다 (ADR-122).
>
> **고쳤다 (2026-09-27)** — `사전 투표에도, 파티 중에도, 발표 뒤에도` 만 적었다. 이 슬라이스의 과녁인
> **등록 중**이 빠졌고, 운영자가 단계를 되돌리면 등록한 사람이 `준비` 에 있을 수 있다. 문은 조건이 없다 — 서버는 단계를 보지 않는다.
>
> **다시 고쳤다 (2026-09-28, ADR-125)** — 등록부터였다. 운영자가 재미를 **하나로 묶어** 프로필 투표에 한 번에 열기로 했다 —
> 기다리라는 말이 하나로 줄고(`프로필 투표가 시작되면 모두 볼 수 있어요`), 열리는 순간도 소식 한 줄로 한 번 알린다.
> 위 문단의 `탭은 등록부터 켜져 있고` 는 그대로다 — 꺼진 탭은 되살리지 않았다. 운세 카드가 자기 안에서 말하던 닫힌 모양은
> 걷혔고, 두 카드가 같은 입구 틀로 선다. 등록 중에 할 재미가 없어지는 것이 대가다 (ADR-125 `대가`).

## B. 고르기

### S-B1 처음에 어느 쪽 얼굴을 볼지 고른다

```
Then   '여자' · '남자' 두 버튼이 같은 크기로 있고, 어느 쪽도 미리 눌려 있지 않다
```

> 누구에게 마음이 가는지는 앱이 정할 일이 아니다 (ADR-17). 내 성별의 반대를 미리 골라두지 않는다.

### S-B2 ★ 한 라운드에 얼굴 아홉, 1~5개 고른다. 세 라운드

```
Then   얼굴 9개가 3×3 으로 보이고, 1개 이상 골라야 '다음' 이 눌린다. 여섯 번째는 골라지지 않는다.
       마지막 라운드의 버튼은 '결과 보기' 다
```

> 아홉은 한 화면에 얼굴이 읽히는 크기로 들어가는 가장 큰 수다 — 360px 에서 한 칸 100px 이상은 3열이 한계라
> 여덟이 아니라 줄을 채운 아홉이다. 칸 폭은 여섯일 때와 같고 한 줄이 더 선다.
> 결과를 정하는 것은 고른 얼굴뿐이라 **보여주는 수가 늘면 고르는 질이 오른다** — 끌리는 얼굴을 만날 자리가 늘어난다.
> 취향은 하나로 특정돼 있을 수도, 여럿일 수도, 흐릿할 수도 있다 — 그래서 1~5개다. 상한이 있어야 **그중 가장**을 고른다 —
> 아홉 중 여덟을 고르면 평균이 흐려진다. 여섯 번째부터는 못 고른다.
> 세 라운드면 1분이다. 파티 테이블에서 폰을 보는 시간으로 그 이상은 길다.
> 세 라운드 만에 부합한 답을 내는 책임은 **고르는 방식**(아래)과 종이 검증이 진다 —
> 아홉이 서로 얼마나 다른가도 화면이 아니라 방식이 정한다. 라운드가 갈수록 좁아진다.
>
> **고쳤다 (2026-09-28, ADR-123)** — v1 은 **얼굴 여섯(3×2) 중 1~3개**였다. 운영자가 `여섯은 적다` 고 물었고,
> 아홉 · 1~5 로 늘렸다. 저장 모양(`picks` 셋 묶음)은 그대로라 v1 행(각 1~3개)도 그대로 읽힌다.

### S-B3 ★ 같은 얼굴이 두 번 나오지 않는다

```
Given  1라운드에 나온 얼굴 — `다른 얼굴 보기` 로 넘긴 아홉까지
Then   2·3라운드에 다시 나오지 않는다
```

> 다시 나오면 고장으로 읽힌다. 고르는 함수가 순수 함수라 이 규칙은 **테스트를 먼저 쓴다**
> (`buildSeating` 과 같은 예외).

### S-B4 뒤로 가면 이전 라운드다. 고른 건 남아 있다

> 라운드마다 push. 뒤로 가기 = 이전 라운드 (등록 스텝과 같다). 잘못 누른 건 여기서 고친다 —
> 그래서 결과 뒤에 '다시 하기' 가 없어도 된다.
> 카드를 닫고 나가면 고르던 건 버려진다. 1분짜리라 이어 하기를 만들지 않는다.
> 앞 라운드를 고쳐 고르면 그 뒤 라운드는 다시 계산한다 — 앞의 선택이 뒤의 후보를 정한다.
> 결과를 본 뒤의 뒤로 가기는 라운드를 되밟지 않고 재미 탭으로 간다 — 결과 보기가 라운드 세 칸을 되감는다 (ADR-122).

### S-B5 고르는 동안 이름이 없다

```
Then   라운드 화면 어디에도 이름이 없다. 사진 파일명도 불투명 id 다 (check:faces 가 잡는다)
```

> 이름을 알고 고르면 끌림이 아니라 팬심으로 고른다. 그리고 옆에서 화면을 본 사람에게
> 취향이 이름으로 읽힌다 — 이 기능이 없애려던 바로 그 노출이다.
> '연예인' 이라는 말도, 이름도 결과 화면에서만 쓴다.

### S-B6 골랐음은 색으로만 말하지 않는다

> 테두리와 함께 ✓ 표시.

### S-B7 ★ 끌리는 얼굴이 없으면 라운드마다 한 번 `다른 얼굴 보기`

```
Given  그 라운드에서 아무것도 고르지 않았고, 그 라운드에서 넘긴 적이 없다
Then   '다음' 아래에 '다른 얼굴 보기' 가 있다
When   누르면
Then   같은 라운드 규칙으로 다른 아홉이 선다. 버튼은 사라진다. 주소는 그대로다
       넘긴 아홉은 본 얼굴이다 — 그 라운드에도, 뒤 라운드에도, 결과에도 다시 나오지 않는다
Given  하나라도 골랐다 · 이미 넘겼다
Then   버튼이 없다
```

> 끌리는 얼굴이 없는데 하나를 골라야 하면 **덜 싫은 얼굴**을 고른다 — 끌림이 아니라 소거로 고른 얼굴이 평균을 흐린다.
> 하나라도 골랐으면 따라갈 것이 이미 있다. 넘김은 `끌리는 게 없다` 는 사람의 길이다 — 골랐던 것을 다 풀면 (아직 안 썼다면) 다시 보인다.
> **한 번뿐이다.** 끝없이 넘기면 1분이 아니고, 1라운드의 두 쪽(아홉 + 아홉)은 자산에 박혀 있다 — 첫 화면 묶음마다 두 쪽이다 (ADR-136).
>
> 넘긴 얼굴은 **저장하지 않고 평균에도 넣지 않는다.** `이 아홉에는 없었다` 이지 `이 얼굴들이 멀다` 가 아니다 —
> 안 고른 얼굴을 쓰지 않는 것(고르는 방식)과 같은 이유다.
>
> **push 하지 않는다.** 결과 보기의 되감기가 칸마다 적힌 라운드 수를 믿는다 (ADR-122 ④) — 칸을 하나 끼우면 그 수가 틀어진다.
> 대신 그 라운드가 어느 쪽을 보여줬는지 기억해서 **뒤로 갔다 오면 같은 얼굴이 선다.**
> 앞 라운드를 고쳐 고르면 그 뒤 라운드는 넘긴 쪽까지 다시 계산한다 (S-B4).

## C. 결과

### S-C1 ★ 연예인 셋. 첫 사람이 답이다

```
When   3라운드를 마치면
Then   가장 가까운 순서대로 사진과 이름 셋을 나열한다. 화면에 `%` 가 없다
```

> 첫 이름이 낯설 때 두 번째가 구해준다. **퍼센트는 없다** — 순서만 있다.
> 화면에 `%` 가 없는 것을 테스트로 고정한다 (운세와 같다).
>
> **두 갈래일 때도 첫 사람이 답이다 (2026-09-28, ADR-123).** 고른 얼굴이 두 무리로 갈리면 셋은
> `[큰 무리의 1위, 작은 무리의 1위, 큰 무리의 2위]` 순서다. 더 많이 고른 쪽이 그 사람의 더 큰 끌림이라
> **첫 사람은 큰 무리가 지킨다.** 둘째는 다른 인상의 답이다 — `두 번째가 구해준다` 가 여기서는 말 그대로가 된다.
> 셋째가 다시 큰 무리라 둘 대 하나가 고른 수와 같은 쪽으로 기운다.
> 두 무리라는 것은 화면에 말하지 않는다 — `취향이 두 가지예요` 는 앱이 매기는 판정이고, 순서만 있다는 약속과 어긋난다.
> 무리가 하나면 v1 과 같다 — 가까운 순서 셋.

### S-C2 ★ 본 얼굴은 결과에 나오지 않는다. 고른 얼굴은 밑에 따로 보인다

```
Then   결과 셋은 라운드 화면에 나왔던 얼굴이 아니다. 내가 고른 얼굴들은 결과 아래 따로 있다
```

> 방금 고른 얼굴을 그대로 돌려주는 건 답이 아니다 — 그건 본인이 이미 아는 것이다.
> 답은 **안 본 사람 중에서** 나와야 "찾아줬다" 가 된다.
> 골랐던 얼굴도 이상형에 가까운 얼굴들이다 — 버리지 않고 결과 아래에서 되돌아보게 한다.
>
> **`다른 얼굴 보기` 로 넘긴 아홉도 본 얼굴이다 (ADR-123).** 결과에 나오지 않는다 — 방금 넘긴 얼굴이 답으로 오면 고장으로 읽힌다.
> 두 갈래일 때도 셋 다 본 얼굴을 뺀 나머지에서 나오고, 서로 겹치지 않는다.
> `내가 고른 얼굴` 은 라운드마다 다섯까지라 열다섯까지다. 넘긴 얼굴은 거기 없다 — 저장하지 않는다.
>
> **그래서 3라운드는 답이 될 얼굴을 보여주지 않는다 (2026-10-02, ADR-127).** 3라운드가 중심에 가장 가까운 얼굴부터 보여주면
> 본 얼굴이 결과에서 빠지므로 답이 될 얼굴을 화면이 먼저 써버린다 — v2 는 결과 1위가 열 번째쯤으로 밀렸다.
> 중심마다 가장 가까운 여섯(`reserve`)은 건너뛰고 그다음부터 보여준다. 이 약속은 그대로다 — 답은 여전히 **안 본 사람**이다.

### S-C3 ★ 저절로 바뀌지 않는다 — 바꾸는 것은 다시 찾기뿐이다

```
Given  결과를 봤다
When   카드를 다시 연다 · 다시 읽는다 · 다른 기기에서 연다
Then   같은 결과다
When   `다시 찾기` 로 세 라운드를 다시 고르고 마지막 `결과 보기` 를 누른다
Then   새 결과가 지난 결과를 대신한다 — 둘을 나란히 두지 않는다. 다시 찾다가 나가면 지난 결과가 그대로다
```

> 처음 저장은 두 번 돼도 먼저 온 것이 남는다 (`ON CONFLICT DO NOTHING`, 운세와 같다).
> 열 때마다 달라지면 테이블에서 한 말이 거짓말이 된다 — 그래서 **저절로는** 바뀌지 않는다.
> **시작 화면에서 미리 말한다** — 처음이면 `언제든 다시 찾을 수 있어요`, 다시 찾을 때는 `새로 찾으면 지금 결과 대신 새 결과가 남아요`
> (마지막 `결과 보기` 위에서 한 번 더). 확인창은 따로 띄우지 않는다 — 되돌릴 수 없는 순간은 마지막 `결과 보기` 하나이고 거기서 미리 말했다.
> `다시 찾기` 는 결과 화면(정답 물음 바로 아래)과 재미 탭 카드(`결과 보기` 옆)에 있고, 문(S-A2)이 열려 있는 동안만 선다. 횟수는 세지 않는다 —
> 결과에는 난수가 없어서 같은 화면에서 같은 얼굴을 고르면 같은 결과다. **다시 뽑기가 아니라 다시 고르기다.**
> 찾을 때마다 새로 집는 것은 1라운드의 대표(첫 화면 묶음)뿐이고, 결과는 고른 얼굴이 정한다 (ADR-136).
>
> **고쳤다 (2026-09-27)** — `운세가 뒷면에서 말하는 것과 같다` 고 적었다. **그런 문장은 없다** — 운세 뒷면에는
> 생년월일 칸과 `운세를 읽는 데만 쓰고, 저장하지 않습니다.` 뿐이다. 한 번이면 그대로라고 **미리 말하는 줄은 이것이 처음**이다.
>
> **다시 고쳤다 (2026-09-28, ADR-125)** — `한 번 찾으면 그대로 남는다 · 다시 고르는 길이 없다` 였다. 운영자가 다시하기를 원했다.
> 운세는 부를 때마다 글을 새로 지어 다시하기가 곧 다시 뽑기라 두지 않았고, 이상형 찾기에만 뒀다. 시작 화면의 `한 번 찾으면 그대로 남아요` 는 지웠다.

### S-C4 ★ 정답을 한 번 묻는다 — 건너뛸 수 있다

```
Given  결과 셋
Then   그 아래에 "셋 중에 진짜 이상형이 있었나요?" — 셋 중 **한 명 이상**을 골라 보내거나 '없음'
When   이름을 누르면
Then   켜지기만 한다. 다시 누르면 꺼진다 — 보내기 전에는 아무것도 가지 않는다
       이름마다 그 사람의 얼굴이 함께 선다 — 이름만 보고 떠올려 답하지 않는다 (ADR-129)
When   답하면
Then   물음이 답으로 바뀌고 그 결과에는 다시 묻지 않는다. 결과는 그대로다 — '없음' 도 다시 찾기를 저절로 열지 않는다
When   다시 찾아 새 결과가 섰다 (S-C3)
Then   새 결과에는 다시 묻는다 — 정답은 결과마다 한 번이다
```

> '결과가 취향에 맞는가' 를 실전에서 재는 유일한 신호다. 종이 검증은 다섯 명이지만 실전은 마흔 명이다.
> 답하지 않아도 아무 일 없다 — 재촉하지 않고, 다음에 결과를 열면 물음이 그대로 있다.
> 남는 곳은 본인 화면과 지표의 **개수**뿐이다 (`v` 별 chosen/none) — 어느 연예인인지는 지표에 없다 (S-D4).
> '없음' 은 실패 신고가 아니라 다음 판(`v`+1)의 벡터·규칙을 고치는 재료다.
>
> **여럿을 받는다 (2026-10-02, ADR-127, 운영자).** 평가 자료로 쓰려면 셋이 저마다 맞았는지가 필요하다 — 한 명만 받으면 둘째 · 셋째의
> 적중이 1위에 묻힌다. 저장은 결과 순서대로다. 지표는 그대로 `chosen` · `none` 의 개수뿐이다.
> 그래서 결과를 바꾸지 않는다 — 바꾸면 S-C3 이 무너진다.
> 새 결과에 다시 묻는 것은 그 답이 **그 결과**에 대한 것이라서다 (ADR-125). 지표의 비는 사람마다가 아니라 결과 한 벌마다가 된다.

### S-C6 ★ 결과 위에 끌린 얼굴의 특징이 선다 (ADR-127)

```
Given  지금 판(특징 부호가 있는 판)으로 찾은 결과
Then   결과 얼굴 위에 `내가 고른 얼굴` 들에서 두드러진 인상이 한 장으로 선다 — 점수 · % · 순위가 없다
       제목 아래에 그 얼굴에서 읽히는 사람, 고른 얼굴에 많던 특징과 거기서 받는 인상, 연구 한 줄이 선다 (ADR-128)
When   두드러진 것이 없다
Then   그렇다고 말한다 — 카드를 감추지 않는다
Given  특징이 없는 옛 판(v1 · v2)의 결과
Then   카드가 없다
```

> **결과 연예인이 아니라 고른 얼굴을 센다** — 결과가 빗나가도 이 문장은 빗나가지 않는다. 남는 낱말은 고른 얼굴의 절반 이상(적어도 둘)이
> 가졌고 풀 전체보다 1.5배 이상 자주 나온 것이다 — 흔한 낱말은 누구의 취향도 말하지 않고, 마흔 명이 같은 문장을 받게 한다.
> 칸은 인상 다섯(동물상 · 분위기 · 눈매 · 턱선 · 이목구비)뿐이다. 몸의 한 부분을 집는 말은 나란히 보는 화면에서 평가로 읽힌다.
> 결과 화면에만 있다 — 재미 탭 입구 카드에는 싣지 않는다 (ADR-125 의 어깨너머).

### S-C5 사진은 실사다 — 고르는 것도 결과도

> 공개 순간에 얼굴이 있어야 "찾아줬다" 가 된다. 합성 얼굴안(법적 노출 0)과 견줘
> 참가자 경험을 앞에 뒀다 (정했다 3). **화면에 내보내는 연예인 사진이 이 기능의 법적 노출이다** —
> 사진 출처 확보가 자산 작업의 첫 일이고, 그 전에는 **화면을 열지 않는다** — 문은 빌드가 연다:
> 지금 판의 풀 JSON 이 빌드에 없으면 카드도 주소도 없다 (`lib/faces.ts`, `19-surface.md` 「자산」).
> **남는 노출은 어깨너머다.** 옆에서 화면을 보면 취향이 얼굴로 읽힌다 — 가림(슬라이스 16)이
> 콕에서 막은 그 통로다. 고르는 화면에 이름이 없는 것(S-B5)이 폭을 줄이고,
> 나머지는 알고 고른 대가로 남긴다 (ADR-32 의 '링크를 본 사람' 과 같은 자리였다 — 그 결정은 ADR-75 로 폐기됐고,
> 알고 고른 대가를 적는 자리는 ADR-118 의 `대가` 가 이어 쓴다).

## D. 저장과 공개 범위

### S-D1 ★ 내 결과는 내 응답에만 있다

```
Then   roster 의 PublicPlayer 에 없다 · 프로필 시트에 없다 · HostState 에 없다
```

> `toPublic()` 을 건드리지 않는다. `ParticipantState.ideal` 한 칸이 전부다 — verdict 도 그 안이다.

### S-D2 ★ 참가자를 지우면 결과도 사라진다

> 운세와 같다. 그 사람의 것은 그 사람과 함께 간다. 보낸 콕만 남는다 (ADR-29).
> 회차는 운영자가 지울 때까지 남고(ADR-36), 지우면 DO 하나로 다 사라지는 것은 그대로다.

### S-D3 서버는 id 만 받는다. 계산하지 않는다

> 기기가 고른 결과를 보내고 DO 는 저장만 한다.
> 개발자 도구로 결과를 지어내 보내는 참가자가 있을 수 있다 — **그래서 뭐.** 본인만 보는 본인 결과다.
> 서버가 벡터를 들고 다시 계산하면 워커 번들이 수백 KB 무거워지고,
> 얻는 건 "본인이 본인을 못 속인다" 뿐이다. 이름은 기기가 자산에서 찾는다 — DO 에는 이름이 없다.

### S-D4 회차 DO 밖으로 나가지 않는다

> 지표에 **결과를 넣지 않는다.** "이 파티 이상형 1위" 는 결과 통계다 — 운영 카운터가 아니다.
> 넣는 건 첫 저장·첫 확정의 개수와 `v` 뿐이다. 누가 누구를 골랐는지는 안 된다.
> 자리는 회차를 가리지 않는 집계 `pulse()` 다 (ADR-56) — `{ kind: "ideal"; key: "save" | "chosen" | "none"; v }`,
> 회차 id 도 연예인 id 도 없다. 회차별 카운터(`count()`)는 회차 id 를 인덱스로 달아서 쓰지 않는다 (ADR-122 ③).

## E. 같은 사람, 두 기기

### S-E1 고르던 중간은 이어지지 않는다

> 고르던 값은 그 기기 메모리에만 있다 (S-B4). 서버는 고르는 중간을 모른다 —
> 두 기기에서 같이 열면 각자 고른다.

### S-E2 ★ 먼저 끝낸 쪽이 남는다

```
Given  두 기기가 각자 고르고 있다
When   둘 다 결과를 보낸다
Then   먼저 닿은 것이 남는다. 늦게 보낸 기기에도 저장된 그 행이 그려진다 — 방금 고른 셋이 아닐 수 있다
```

> 서버는 이미 있으면 있던 것을 돌려준다 — 409 로 혼내지 않는다. 늦은 쪽이 잘못한 게 아니다.
> 화면은 응답을 그대로 그린다. 방금 받은 답을 버리고 다시 읽지 않는다 (14 의 `/vote` 와 같은 이유).
>
> **다시 찾을 때도 같다 (ADR-125).** 기기는 다시 찾기를 시작한 결과의 `at` 을 `replaces` 로 실어 보내고, 서버는 그 값이 지금 결과와
> 같을 때만 바꾼다. 두 기기가 같은 결과에서 다시 찾으면 먼저 닿은 쪽이 바꾸고, 늦은 쪽은 이미 바뀐 결과를 받아 그린다.
> 새 결과의 `at` 은 지난 값보다 크다 — 화면이 새 결과가 섰는지를 그 값으로 가린다.

## 숫자

|                    | 값                      | 왜                                                    |
| ------------------ | ----------------------- | ----------------------------------------------------- |
| 라운드 M           | 3                       | 1분. 군집 단계와 같다 — 거칠게 → 가늘게 → 낱낱이      |
| 한 라운드의 얼굴 N | **9**                   | 한 화면, 읽히는 크기 — 3열이 한계라 3×3 (S-B2)        |
| 고르는 수          | **1~5**                 | S-B2. 특정된 취향은 하나로 좁고, 갈리는 취향은 다섯까지. 상한이 `그중 가장` 을 만든다 |
| 다른 얼굴 보기     | 라운드마다 **1**        | S-B7. 아무것도 안 골랐을 때만                         |
| 1단계 대표         | **18**                  | 아홉 × 두 쪽 — 1라운드의 두 쪽이다                    |
| 2단계 대표         | 36                      | 아홉 × 두 쪽(18)을 넉넉히 덮는다                      |
| 첫 화면 묶음       | **16**                  | 1 · 2단계를 같은 무리의 다른 얼굴로 든 벌 — 찾을 때마다 하나를 집는다 (ADR-136) |
| 결과 J             | 3                       | 답 하나 + 구해주는 둘. 두 갈래면 큰 무리 둘 + 작은 무리 하나 |
| 풀                 | 성별마다 **200명 이상** | 본 얼굴(넘김까지 최대 54)을 빼고도 평균 근처가 낱낱이 되는 크기. `check:faces` 의 하한은 57. v4 는 여 194 · 남 182 — 연예인만 남기고 사람을 못 더했다 (ADR-132). **v5 는 여 536 · 남 580** — 운영자가 검수한 얼굴을 더했다 (ADR-135) |

> **고쳤다 (2026-09-28, ADR-123)** — v1 은 N 6 · 고르는 수 1~3 · 1단계 6 · 넘김 없음이었다.
> **또 고쳤다 (2026-10-10, ADR-136)** — v5 까지는 첫 화면 묶음이 없었다 — 1 · 2단계가 하나라 1라운드가 모두에게 같았다.

**라운드 수는 고정이다.** 풀이 작으면 라운드를 줄이는 게 아니라 자산을 채워서 온다 —
저장 모양(`picks` 3묶음)과 화면이 라운드 수를 들고 있어서, 이걸 변수로 만들면 전부가 변수가 된다.

**고르는 방식 — 고른 얼굴의 중심을 따라가되, 라운드마다 좁힌다. 두 무리로 갈리면 둘 다 따라간다**

```
중심     지금까지 고른 얼굴 벡터 전체로 낸다 (tasteCenters). 라운드 가중치 없음
         넷 미만이면 평균 하나(정규화). 넷 이상이면 둘로 갈라 보고 —
         두 평균이 반대쪽을 향하고(코사인 < 0) 작은 무리가 둘 이상이면 중심 둘(큰 무리가 먼저),
         아니면 전체 평균 하나
1라운드  1단계 대표 아홉 — 무리마다 하나. 어느 대표인지는 찾을 때마다 집는 첫 화면 묶음이 정한다 (ADR-136)
         넘기면 1단계의 둘째 쪽 아홉 — 같은 묶음의 둘째 쪽
         (v5 까지는 묶음이 하나라 모두에게 같았다 — 모두가 같은 얼굴로 모였다, ADR-133)
2라운드  중심에 가까운 순서로 2단계 대표 아홉 (본 얼굴 제외) — 대표라서 아홉이 서로 다른 군집이다
3라운드  중심마다 가장 가까운 여섯은 결과 몫으로 건너뛰고(ADR-127), 그다음부터
         중심에 가까운 순서로 풀 전체에서 아홉 (본 얼굴 제외) — 다만 이미 담은 것과
         너무 닮은 후보는 다음 것으로 민다. 닮은꼴 아홉이면 고를 이유가 안 읽힌다
         (2·3라운드에서 넘기면 같은 규칙으로 그다음 아홉)
중심 둘  아홉 자리를 고른 수로 나눈다 — 작은 무리는 한 자리 이상, 절반 이하.
         두 목록을 같은 규칙으로 겹치지 않게 채워 번갈아 놓는다. 한쪽이 모자라면 다른 쪽이 채운다
결과     중심이 하나면 가장 가까운 연예인 3 (본 얼굴 제외)
         둘이면 [큰 무리의 1위, 작은 무리의 1위, 큰 무리의 2위] (S-C1)
```

다양성은 '서로 다른 군집' 이 만들고, 수렴은 '중심 근처' 가 만든다 — 거칠게 → 가늘게 → 낱낱이.
라운드 가중치를 두지 않는 건 정할 값을 하나라도 줄이려는 것이다 — 이 가정 전체를 종이 검증이 재판한다.
**안 고른 얼굴은 쓰지 않는다.** 아홉 중 다섯까지만 고를 수 있어 안 고른 것에는 이유가 여럿이다 —
'멀다' 는 보장이 없는 신호를 평균에 넣지 않는다. **넘긴 아홉도 쓰지 않는다** (S-B7).

**두 무리로 가르는 문턱은 높게 잡았다.** 한 무리를 억지로 쪼개면 한 취향이 반으로 줄어든 채 엉뚱한 쪽을 끌어온다 —
틀리게 가르는 쪽이 못 가르는 쪽보다 나쁘다. v1 의 페르소나 세션으로 재 보니 이 문턱은 한 인상이 뚜렷한 세션을 2% 만,
두 인상에 끌리는 세션을 33% 갈랐다 (ADR-123). 같은 입력이면 같은 중심이다 — 시작점은 서로 가장 덜 닮은 두 얼굴이고 난수가 없다.

가지를 타고 내려가는 방식(고른 군집의 자식만 보여주기)도 검토했다. 둘을 골라 가지가 둘이 되면
어느 쪽 자식을 몇 개 보여줄지가 규칙이 되고, 그 규칙이 결과를 흔든다. 평균을 따라가면 규칙이 하나다 —
**가까운 것부터.** 취향이 둘로 갈리는 사람은 3라운드의 선택이 평균을 한쪽으로 끌고 간다.
계층 군집은 그대로 쓴다 — 단계마다 "얼마나 거친 후보 집합에서 고르나" 를 정하는 게 그 일이다.

> **고쳤다 (2026-09-28, ADR-123)** — 바로 위 문단의 기대 — `3라운드의 선택이 평균을 한쪽으로 끌고 간다` — 는 일어나지 않았다.
> 종이 검증에서 두 인상에 끌리는 페르소나는 1차 2:4, 4차 2:3 으로 무작위에 졌다 (ADR-122). 평균이 두 인상 **사이**로 떨어졌고,
> 2·3라운드도 그 가운데 얼굴을 보여줘서 둘째 인상을 더 고를 자리가 없었다 — 두 인상인데 안 갈린 세션은 대개 둘째 인상이 한 장뿐이었다.
> 그래서 v2 는 **라운드 후보부터** 두 중심을 나눠 따른다. 가지 방식의 걱정(몇 개씩 보여줄지가 결과를 흔든다)은
> 규칙 하나로 닫았다 — **고른 수의 비율대로.** 중심이 하나면 모든 것이 v1 과 똑같다.

## 먼저 확인할 것 — 화면을 만들기 전에

이 기능은 **"고른 얼굴 벡터의 평균에 가까운 연예인 = 내 이상형"** 이라는 가정 위에 서 있다.
얼굴 인식 모델의 벡터는 *누구인가*를 맞추도록 배운 것이지 *끌리는가*를 배운 게 아니다.
같은 사람의 사진은 모이고 다른 사람은 멀어지지만, **"내 취향" 이 그 공간의 한 점인지는 아무도 보장하지 않는다.**

그래서 화면 전에 종이로 잰다.

| 잰다                           | 방법                                                                                     | 판단                                                                            |
| ------------------------------ | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 결과가 그럴듯한가              | 성별당 60명짜리 작은 풀로 파이프라인을 돌리고, 다섯 명에게 노트북으로 세 라운드를 시킨다 | **다섯 중 넷**이 "내 취향 맞다" 가 아니면 벡터를 바꾼다 (인식 모델 → CLIP 계열) |
| 1분 안에 끝나나                | 같은 자리에서 잰다                                                                       | 90초를 넘으면 얼굴 크기·흐름을 다시 본다 — 라운드는 줄이지 않는다 (`숫자`)      |
| 첫 라운드 여섯이 충분히 다른가 | 1단계 대표를 나란히 본다                                                                 | 둘이 비슷해 보이면 군집을 다시 본다                                             |

> **후기 (2026-09-27, ADR-122)** — 벡터는 **인식 모델도 CLIP 계열도 아니다.** `gpt-6-luna` 가 사진마다
> 정해진 낱말 목록에서 열다섯 가지 속성(동물상 · 분위기 · 얼굴형 · 눈 … 나이 느낌)을 고르고(다섯 번, 다수결),
> 값마다 `text-embedding-3-large` 로 재어 속성마다 중심을 뺀 68차원으로 옮긴다. 위의 걱정 — *누구인가* 를 배운 공간 —
> 을 비켜 간 것이지 풀어낸 것은 아니다: 여전히 "내 취향이 그 공간의 한 점인가" 는 종이 검증이 본다.
> 종이 검증은 사람 다섯 대신 `gpt-6-luna` 페르소나가 고르고, 눈을 가린 판정자가 무작위 대조군과 견준다.
> 검증 결과는 자산과 함께 적는다 (ADR-122). **통과 기준은 아직 정하지 않았다** — `다섯 중 넷` 은 사람 다섯의 기준이라
> 판정자와 대조군에 그대로 옮겨지지 않는다. 돌리기 전에 ADR-122 `종이 검증` 에 적는다.
>
> **후기 (2026-10-03, ADR-132)** — 벡터가 **얼굴 인식(SFace) + 얼굴 메시**로 바뀌었다. 참가자 평가가 `매우 부정확` 이었고, 운영자가 전에 얼굴 모델의
> 특징을 평균 낸 쪽의 만족도가 더 좋았다고 했다. 위 표의 `인식 모델 → CLIP` 전제가 다시 산 셈이다 — ADR-122 의 1차가 인식 모델을 무작위보다 못하다고 본
> 것은 LLM 판정자의 눈이었다. 같은 고른 얼굴로 견주면 그 판정자는 낱말 벡터와 인식 모델을 57:55 로 가르지 못한다. **사람의 답이 재판한다** — S-C4 의 `v` 별 정답 비.

종이 검증을 건너뛰고 화면부터 만들면, 화면이 다 된 뒤에 "결과가 이상하다" 를
벡터 탓인지 화면 탓인지 모르게 된다. 슬라이스 01 의 가짜 테스트와 같은 자리다 —
**구현 전에 가정이 참인지 본다.**

> **고쳤다 (2026-09-27)** — 순서가 바뀌었다. **화면은 픽스처 풀**(`test/fixtures/faces/`, 지어낸 벡터)로 먼저 만들었고,
> 종이 검증과 실제 자산은 구현이 아니라 **출시**를 막는다 (`19-surface.md` 「자산」). 위의 걱정 — 벡터 탓인지 화면 탓인지
> 모른다 — 은 픽스처가 반쯤 푼다: 화면 테스트가 지어낸 벡터 위에서 이미 맞으므로, 실제 자산에서 결과가 이상하면 벡터 쪽이다.
> 출시의 문은 코드가 아니라 `qa → main` 이다.

## 문구

`copy.ts` 에 넣는다. 기능 이름은 **이상형 찾기**. "연예인" 은 결과 화면에서만 쓴다.
표는 **뜻**이다 — 문장의 정본은 `copy.ts` 의 `IDEAL` 이다

| 자리          | 뜻                                             |
| ------------- | ---------------------------------------------- |
| 첫 물음       | 어느 쪽 얼굴을 볼까요? — 여자 · 남자           |
| 첫 물음 아래  | 처음: 언제든 다시 찾을 수 있어요 · 다시 찾을 때: 새로 찾으면 지금 결과 대신 새 결과가 남아요 (ADR-125) |
| 라운드 안내   | 끌리는 얼굴을 1~5개 골라주세요 · `1 / 3`       |
| 다음 · 마지막 | 다음 · 결과 보기                               |
| 넘기기        | 다른 얼굴 보기 — 아무것도 안 골랐을 때만 (S-B7) |
| 결과 제목     | 내 이상형에 가까운 얼굴 — 최상급은 덜어낸다    |
| 끌린 얼굴     | 고른 얼굴에서 두드러진 인상 낱말 — 제목 한 줄과 그 아래 한 줄. 없으면 그렇다고 (ADR-127) |
| 정답 물음     | 셋 중에 진짜 이상형이 있었나요? 여럿을 골라 보낸다 · 없음 (ADR-127 · 130) |
| 다시 찾기     | 다시 찾기 — 결과 화면(정답 물음 아래)과 재미 탭 카드 (ADR-125) |
| 재미 탭 카드  | 시작 · 결과 보기 — 두 카드가 같은 말이다 (`FUN`) |
| 자산 못 받음  | 얼굴을 불러오지 못했어요 · 그 자리의 `다시 불러오기` |

`열기` 를 쓰지 않는다 — 운세는 열면 나오지만 이것은 고르는 일이 남아 있다. 같은 말은 같은 무게여야 한다.
`예쁜`·`잘생긴` 을 쓰지 않는다. `끌리는` 이다 — 고르는 건 얼굴의 등급이 아니라 내 쪽의 마음이다.
라운드 안내에 `연예인` 을 쓰지 않는다 — 이름 없이 고르는 화면(S-B5)에서 그 말은 결과의 것이다.

## 남는 물음

1. 외적 이상형이 특정된 사람도, 흐릿한 사람도, 여럿인 사람도 있다 — 1~5개(S-B2)가 받치고,
   갈리는 취향은 두 중심이 따라간다 (고르는 방식). 정말 그런지는 종이 검증과 S-C4 의 답이 말해준다
   — v1 은 `3라운드의 선택이 평균을 한쪽으로 끈다` 고 적었고, 일어나지 않았다 (ADR-122 · ADR-123)
2. 고르지 않은 연예인을 이상형과 멀다고 읽을 수 있을까 — **읽지 않기로 했다.**
   다섯까지만 고를 수 있어 안 고른 것에는 이유가 여럿이다 (고르는 방식). 넘긴 아홉도 같다 (S-B7)
3. 연예인은 대부분 외모가 뛰어난 편이라 풀이 벡터 공간의 한 구석에 몰려 있을 수 있다 —
   그 안에서도 갈리는지는 종이 검증의 "첫 쪽 아홉이 충분히 다른가" 가 본다
