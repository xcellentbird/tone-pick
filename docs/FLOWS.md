# 플로우와 상호 영향

한쪽에서 한 행동이 반대쪽 화면에 어떻게 나타나야 하는지. **여기 빠진 반응은 구현되지 않는다.**

참가자 화면은 실시간(WS)으로 "다시 읽어라" 신호만 받고 서버에서 한 벌을 다시 가져온다.
부분 갱신을 만들면 화면과 서버가 조용히 어긋난다.

---

## 운영자 액션 → 참가자 화면

| 운영자 액션 | 참가자 즉시 반응 |
|---|---|
| 사전 투표 시작 | 🗳️ 배너 + 홈의 소식, 콕 버튼 활성화, 남은 횟수 = `maxPre` |
| 매력 투표 마감 | ⏳ 홈의 소식 + 배너 (ADR-55), 콕 버튼 잠김, 남은 횟수 칸이 사라진다. **참가자 탭에서는 배너가 안 뜬다** — 그 화면이 이미 같은 문장을 말한다 |
| 사전 투표 마감 / 파티 진행 시작 | 🎉 배너 + 홈의 소식, **새 예산 `maxParty` 지급**, 이전 콕은 유지 |
| 자리 발송 | 자리 배너 + **전체 화면 이동 확인** + 참가자 탭에서 **같은 테이블 사람이 위로** 묶인다 (ADR-73). 발표 후에는 묶지 않는다 |
| 결과 발표 | 🎊 배너, 홈에 결과 요약(몇 명) · 내 정보에 상세, **콕 버튼 즉시 잠김**. **되돌릴 수 없다** (ADR-50) |
| 콕 횟수 설정 변경 | 남은 횟수가 그 자리에서 재계산 (이미 쓴 건 유지) |
| 콕 대상 설정 변경 | `모두에게` 로 바꾸면 동성에게도 찌를 수 있고, 목록이 전체로 열린다 |
| 참가자 삭제 | 그 참가자가 목록·자리·집계에서 사라진다 |

**마감만 운영자를 거치지 않을 수 있다.** `voteEndAt` 이 지나면 아무도 누르지 않아도 닫히는데,
그때는 **서버가 보낼 신호가 없다** — 그 순간 코드를 돌리는 사람이 없다.
그래서 마감이 가까우면 참가자 화면이 스스로 1초마다 다시 그린다 (ADR-55).
나머지 줄은 전부 `broadcast()` 가 밀어준다.

## 참가자 액션 → 운영자 화면

| 참가자 액션 | 운영자 반응 |
|---|---|
| 등록 완료 | 인원·성비 갱신, "아직 콕을 못 받은 사람"에 추가 |
| 콕 찌르기 | 콕 현황 갱신, 사전 투표 1위 갱신, 자리 배정 가중치에 반영 |
| 자리 이동 확인 | 확인율 상승 — 전원 확인 전에 다음 단계를 서두르지 않게 하는 신호 |
| 아무도 안 찌름 | "아직 콕을 못 받은 사람"에 남는다 — 운영자가 현장에서 개입할 신호 |
| 지각 등록 | 이미 발행된 자리에 없음 → 미배정 인원으로 표시 |

## 엣지 케이스

### 일정 · 단계

| 상황 | 처리 |
|---|---|
| 자리 발송 후 지각자 도착 | 배정은 닫히지 않는다 (ADR-28) — 앉히거나 다시 배정한다 |
| 매력 투표 시작이 이미 지난 시각 | 회차는 만들어진다 — 등록과 곧바로 이어 열린다 (ADR-38) |
| 발표 시각이 파티 일시보다 앞 | 회차를 만들 때 **거부** (ADR-43) — 파티가 시작되자마자 끝난다 |
| 발표 시각이 지났는데 파티를 안 시작함 | **아무 일도 없다** (ADR-43). 파티를 시작해야 울린다 — 그래야 빈 자리에서 발표가 안 뜬다 |
| 파티가 예정보다 길어짐 | 설정 탭에서 **발표 시각을 미룬다**. 파티 시작 뒤에도 열려 있는 유일한 일정이다 |
| 마감이 이미 지난 상태에서 사전 투표 시작 | 확인창에 ⚠️ "시작하자마자 마감됩니다" |
| 수동 진행이 예약보다 이르거나 늦음 | 확인창에 차이를 분 단위로 + "남은 예약은 해제돼요" |

### 콕 · 공개 범위

| 상황 | 처리 |
|---|---|
| 콕을 한 번도 못 받은 참가자가 결과 화면을 봄 | "0번" 표기를 쓰지 않고 별도 문구 |
| 발표 후 콕 버튼이 남아 있으면 결과 보고 뒤늦게 찌를 수 있음 | 발표 즉시 콕 잠금 |
| 발표 후에도 자리 이동 확인이 전체 화면을 덮음 | 발표됐으면 띄우지 않는다 |
| 잘못 찔렀을 때 | 되돌리기를 연 회차면 같은 사람을 다시 눌러 되돌린다. 닫은 회차면 **되돌릴 수 없다** — 확인창이 그렇게 말한다 |
| 다 쓴 뒤에 잘못 찌른 걸 알았을 때 | 찌른 적 있는 사람에게는 **창이 열린다** (ADR-34 후기) — 되돌리기 하나만 있고 `남은 콕 0회 → 1회` 다 |
| 동성에게 찌를 수 있게 열어둔 회차 | 자리 배정의 남녀 정원은 그대로. 콕은 가중치로만 들어간다 |
| 매력 투표 알림만 끈 회차 | 그 표는 `received.pre` 가 0으로 나간다 (ADR-43). **파티가 시작돼도 얹히지 않는다** |
| 알림을 끈 채로 발표까지 감 | 발표 뒤에는 전부 센다 — 그때는 매칭까지 열리므로 감출 것이 없다 |
| 파티 도중에 알림을 켜려 함 | **거부** (ADR-35). 쌓인 것이 한꺼번에 나타나 "한 번에 하나씩" 이 깨진다 |
| 서로 찔렀는데 상대 번호가 안 보임 | **정상이다** (ADR-42). 연락처는 매칭돼도 안 나간다 — 나가는 건 실명까지고, 그 아래 한 줄이 그렇게 말한다 |
| 매칭 상대에게 연락하고 싶음 | 앱은 여기까지다. **두 사람은 같은 방에 있다** — 이름과 얼굴을 알면 그 자리에서 직접 한다 |
| 인스타를 왜 받았냐고 물음 | **운영자 확인용**이다. 등록 화면 인스타 칸 아래에 그 한 줄이 있다 |
| 발표 전에 등록한 옛 회차 참가자 | 좁아지는 변경이라 그대로 안전하다 — 더 주겠다고 한 적은 있어도 덜 주는 것으로 약속을 어기지는 않는다 |

### 인증 · 회차

| 상황 | 처리 |
|---|---|
| 회차 PIN 과 공통 PIN 이 같으면 권한 상승 | 회차 PIN 자체를 없앴다 — 권한은 한 종류다 (ADR-12) |
| 참가 링크가 퍼지면 아무나 등록 | 링크는 회차마다 하나지만 **명단에 있는 번호**여야 문이 열린다 (ADR-75). 등록한 사람은 PIN 번호까지 맞아야 한다 |
| 남이 내 번호를 넣으면 | 등록 전이면 **먼저 정한 사람이 그 자리를 가진다** (첫 입장의 선점 — ADR-75, 알고 고른 대가). 등록 후면 PIN 번호가 막고, 5번 틀리면 그 번호가 잠긴다 |
| PIN 번호를 잊었거나 잠겼을 때 | 운영자에게 말한다 → 운영자가 **초기화** (PIN 번호와 실패 횟수를 함께 지운다) → 다음 입장에서 새로 정한다. 참가자 스스로 푸는 길은 없다 |
| 남이 내 번호로 5번 틀리면 | 내 번호가 잠긴다 — 잠금은 번호에 걸린다 (접속지에 걸면 망을 바꿔 빠져나간다). 운영자가 눈앞에 있어 받아들였다 |
| 입장 코드가 우연히 중복 생성 | 겹치지 않을 때까지 서버가 다시 뽑는다 |
| 다른 회차에 같은 닉네임 | 허용 — 유일성은 회차 내부에서만 |
| 링크를 다시 열었을 때 | **이 브라우저의 마지막 세션**으로 들어간다 (`/` 와 같다, ADR-75). 이 회차의 세션이 없으면 배너 → 번호 + PIN 번호 |
| 한 브라우저에서 링크 둘을 열었을 때 | 탭마다 세션이 갈린다 (ADR-44) — 두 번째 탭이 첫 번째를 덮지 않는다 |

### 자리

| 상황 | 처리 |
|---|---|
| 인원 대비 테이블이 너무 많음/적음 | 테이블당 2명 미만 · 8명 초과 시 경고 |
| 라운드마다 테이블 수가 다를 때 과거 라운드가 덮어써짐 | 배정 결과에 그때의 테이블 수를 함께 저장 |

| 초안이 참가자에게 새어 나감 | 초안은 렌더링 대상에서 제외 |

## 안 온 사람 · 늦게 온 사람 · 간 사람

**참석 상태는 없다** (ADR-45 가 ADR-33 을 되돌렸다). 문 앞에서 세는 건 사람이 한다.

여기 원래 적혀 있던 경고가 결국 맞았다 — *사람에게 붙는 플래그는 시간이 지나면 틀리고,
틀린 상태는 다음 라운드에서 사람을 조용히 빠뜨린다.* 자리에서 빼는 일은
**배정할 때 그 라운드에만** 고른다. 어디에도 저장되지 않으므로 낡을 수가 없다.

| | 하는 일 | 왜 |
|---|---|---|
| **늦게 왔다** | 아무것도 안 해도 **자리가 있다.** 배정 뒤에 등록했으면 `앉히기` | 안 빼면 앉는다 — 빈 자리는 보이지만 없는 자리는 안 보인다 |
| **안 왔다 (노쇼)** | 다음 배정에서 **뺄 사람**으로 고른다. 지금 라운드는 `자리 비우기` | **지우지 마라** — 매칭이 상대에게서 사라진다 |
| **중간에 갔다** | 같다 — 다음 배정에서 뺀다. 지금 라운드 자리는 `자리 비우기` | 그 라운드에만 빠진다. 콕·매칭은 그대로다 |
| **나갔다 돌아왔다** | 아무것도 안 해도 된다 | **되돌릴 상태가 없다** (ADR-45). 다음 배정에서 안 빼면 그대로 들어온다 |

`buildSeating` 은 **받은 명단을 전원 앉힌다** — 순수 함수는 그대로고, 거르는 일은
`makeSeating` 이 한다. 거르는 재료는 **그 배정 요청이 실어 온 `exclude` 목록**이고
어디에도 저장되지 않는다 (ADR-45) — 그래서 낡을 수가 없다.
그래서 **자리를 비운 것과 배정에서 뺀 것은 다른 일이다**: 앞엣것은 이미 짜인 라운드를 고치는 일이고,
뒤엣것은 다음 라운드를 짜는 일이다.

## 자리를 언제 보여주나

**발행해야 보인다** (ADR-39). `mySeat()` 은 단계를 보지 않고 마지막 **발행본**만 본다 —
파티가 시작되기 전에도 보낼 수 있어야 일찍 온 사람이 자기 테이블에 앉아 기다린다.

| | |
|---|---|
| 초안 (발행 전) | 참가자 응답에 `seat` 가 **없다.** 화면도, 개발자 도구도 |
| 파티 시작 | 그 순간 보이고 전체 화면 확인이 뜬다. **전환 방송이 곧 알림이다** |
| 발표 후 | 자리는 남고 확인창만 안 뜬다 — 매칭 화면이 `sameTable` 을 쓴다 |

예전에는 단계를 안 봐서, 미리 짜두면 그 순간 알림이 나갔다. 그래서 **파티가 시작된 뒤에
급히 배정**하게 됐다 — 피하려던 바로 그 상황이다.

**확인 화면은 다시 열 수 있다.** 늦게 도착해 앱을 처음 켠 사람에게 전체 화면이 덮치면
반사적으로 누르기 쉽고, 그러면 테이블 번호를 못 읽는다. 홈의 자리 카드를 누르면 다시 뜬다
(`/e/:code/seat`). **다시 연 화면에서는 확인을 받지 않는다** — 이미 센 사람을 또 세면
`acks` 가 "이 자리를 안다" 라는 뜻을 잃는다.

## 라운드 중에 사람이 빠질 때

두 가지 길이 있고, **하는 일이 다르다.**

| | 하는 일 | 남는 것 |
|---|---|---|
| **명단에서 빼기** | 앞으로 못 들어오게 한다 | 이미 등록한 사람은 **그대로 파티에 있다** (ADR-15) |
| **참가자 삭제** | 지금 있는 사람을 내보낸다 | 명단에는 남아서 **같은 번호로 다시 들어올 수 있다** (ADR-75). PIN 번호는 참가자 행과 함께 지워져 다시 정한다 |

완전히 내보내려면 **둘 다** 해야 한다. 삭제 확인창이 그 사실을 말한다.
한쪽만 하는 것도 쓸모가 있어서 묶지 않았다 —
명단만 빼는 건 "다음에는 부르지 않는다", 삭제만 하는 건 "실수로 등록했으니 다시 하세요" 다.

### 삭제하면 무엇이 따라 움직이나

- **받은 콕은 그대로다.** 지운 사람이 보낸 콕은 남긴다 (ADR-29) —
  숫자가 줄면 명단에서 사라진 사람과 맞춰 **누가 나를 찔렀는지 드러난다**
- **그 사람에게 쓴 콕은 예산이 돌아온다.** 없는 사람에게 쓴 횟수를 물릴 이유가 없다
- **발행한 자리에서도 빠진다.** 그 테이블 인원이 하나 줄고, 같은 테이블 사람들의
  `같은 테이블 N명 · 남 x / 여 y` 가 그 자리에서 바뀐다. 좌석 번호는 그대로다
- **서로 찌른 상대에게서 그 매칭이 사라진다.** 발표 화면이 그 사람을 찾지 못해 조용히 건너뛴다.
  받은 콕 숫자는 그대로라(ADR-29) 남은 쪽은 `받은 콕 3회 · 서로 찌른 상대 0명` 을 보게 된다 —
  **이게 삭제의 가장 비싼 값이다.** 안 온 사람·간 사람은 지우지 말고 `자리 비우기` 를 쓴다
- **짝이 있었다면** 상대의 💘·💔 표시가 사라지고 성적표의 총 쌍 수가 준다
- **운세도 지운다.** 그 문장에는 닉네임이 들어 있다 — 사람을 지웠는데 문장이 남으면 지운 게 아니다
- 자리 이동 확인 진행률(`N/총원`)의 분모가 준다

### 지워진 사람의 화면

`/api/me` 가 **404 + "참가가 취소되었어요"** 를 준다.
"그런 회차가 없어요" 로 뭉뚱그리지 않는다 — 회차는 멀쩡하고 **내가** 빠진 것이고,
그렇게 말하면 참가자는 링크를 의심하며 운영자에게 엉뚱한 걸 묻는다.

버튼은 `다시 입장하기` 다. 명단에 그 줄이 남아 있으면 **같은 번호로** 다시 들어와 등록할 수 있다 —
운영자가 실수로 지웠을 때 참가자가 스스로 복구한다.

소켓은 살아 있어서 삭제 즉시 `roster` 방송이 가고, 그 화면이 바로 뜬다.
